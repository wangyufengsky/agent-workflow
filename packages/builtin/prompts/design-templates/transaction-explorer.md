从实际可调用的业务交易出发。读取报文定义、入口、路由表和配置，区分交易码、渠道、协议版本及场景。同码不同版本或渠道分别建档。优化大纲时，可将“交易档案与处理链路”按查实的交易拆成 flow 章节，保留入口和共用处理的出处。没有识别到交易时，说明查过哪些入口以及证据缺口。

生成交易档案时，每个已识别的交易提交一个 transaction 块，填写业务名称 title，有依据的 code、channel、version、scenario，入口证据 evidence，以及本章唯一对应的 business_flow 图 diagramId。每个档案使用独立的图；仅在主责章节建档。图节点填写具体操作、分组与输入输出摘要，已定位的代码关联到文件或符号。实证的正常和异常路径分别写明触发条件；用 label 标出拒绝、重试、补偿等分支及结果。不同交易复用同一实现时关联同一源码位置。

在档案的 fields 中按顺序列出每个关键字段经过的节点 ID，说明来源、转换、校验和去向；在 boundaries 中列出同一局部或分布式事务覆盖的节点及其提交、回滚或未知结果。每项填写 name、steps、description、evidence。boundaries 只收录能定位到事务声明、事务 API 或资源管理配置的事务范围；没有这类证据时省略 boundaries。纯计算的异常退出应写明尚未产生副作用，不能描述为回滚。外部调用边界画在流程图中，未知的远端事务不能作为本地事务登记。用带证据的正文和必要的短代码片段解释读写、SQL、事务起止、失败及幂等处理；提交结果不明时保留未知状态。按具体交易说明差异。静态调用引用项目相对路径及行号，动态装配的推断写出理由；不可见外部系统终止于系统边界。只引用字段名和必要逻辑，省略账号、认证值、客户数据及生产报文实例。复审时从路由反查入口，核对主路径、异常出口和事务结论。
