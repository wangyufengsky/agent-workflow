# AP-04 会话生命周期验证 · 2026-10-24

## 行为与评审结论

新助手原生会话以规范化真实路径 `assistant/files/<conversationId>/` 为目录；创建、发送、停止、权限回复和生成附件路径保持一致。删除时锁住发送入口与系统回传，先清理原生会话，再清理本地记录与文件；外部清理失败保留聊天。原生已经删除而本地未记录的崩溃窗口，以 SDK 精确的 404 + NotFoundError 作为幂等成功，不吞网络故障或其他错误。

真实 opencode 1.19 验证表明已有会话目录不可通过 prompt 参数或 fork 改变，因此旧会话按 0020 迁移标记，在继续对话前保存退休 id、清理旧原生会话，再建立独立会话。界面 JSONL 保留，最近 200 条中的可见文字（至多 12,000 字符）通过持久 outbox 恢复；工具、内部推理与权限不回放。失败与跨重启恢复已覆盖。历史截取从流片段中间开始时，保留原偏移合并修订，防止旧文字混回新文字。

独立评审发现原生 shell 的 `head` / `rg` 等命令不会完整检查 external_directory，而原生 task 子代理也不会完整继承助手权限。真实脚本模型 + opencode 复现跨会话 head 读取成功后，助手 shell 改为全部 ask，原生 task 入口禁用；应用 tasks_create 保留。这是工具权限与工作目录隔离，不声称操作系统沙箱；用户批准 shell 或配置外部 MCP 后可获得更广访问。
