# 32 · 角色助手与桌宠：分阶段开发设计

> 2026-10-23；开发分支 `codex/whale-assistant`，基线 `main@d3335a6`。用户已授权先写设计、再逐阶段开发。本文的阶段状态区分设计、实现与实测，不预填验收结果。

## 1. 产品目标与素材路线

同一个应用助手以两种形态出现：应用内可选择光球或鲸鱼；桌面上以透明小窗陪伴用户。保留动作与碎碎念，点击可与现有助手对话，任务准备好、完成或失败时主动通知，并能打开结果。

**用户确认的素材路线（2026-10-23）：先使用 dsh-pet 的鲸鱼素材开发与验证全部功能；功能完善后，再设计自己的小人和动画，替换正式角色素材。** 原创角色制作是后续独立阶段，不以现在重新作画阻塞功能开发，也不把鲸鱼作为最终品牌资产。

临时素材来源：[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，固定版本 `48007b64ac0bebb2e97ac88344aed62de8399dd4`。其 README 许可区声明：代码 MIT，动画／提示词／源视频允许开源使用、禁止商用；衍生作品介绍、展示、分发处附原仓库地址。开发素材随包保留来源与许可说明；商业发行前替换原创素材或取得另行授权。字体与表情包不随本次移植引入。

角色清单集中定义动作文件与语义，不在业务代码散落鲸鱼文件名。以后替换角色主要修改素材和清单，沿用对话、任务状态与桌面交互。当前支持极光光球（默认）与临时鲸鱼两个形象，不建设角色商店、任意远程素材或通用插件系统。

## 2. 现有基础与改动边界

- 助手：复用 `assistant_conversations`、消息流、确认／权限卡、`assistant.send` 与 SSE；不维护另一份闲聊历史。
- 动作：使用原透明 WebM 素材，移植需要的播放与互动行为；不安装 DSH 宿主或额外 Electron，也不复制它的模型凭据系统。
- 桌面：复用现有 Electron main、preload、后端与 React；保持 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。
- 任务通知：来源为任务／待处理状态，不能把模型一轮回复结束视作整个任务完成。现有 SSE 重连可能重放，通知必须去重。
- 本分支从 main 开发。交付前已同步主线合入的浏览器 B1，保留网站设置与桌宠设置；附件与需求清单等尚未合入主线的工作不带入本次交付。

## 3. 界面与交互

### 3.1 应用内角色

设置页提供「AI 助手形象」切换，默认选择光球；切换即时同步到应用内与桌宠，不重置会话。欢迎区使用完整角色；助手面板、主页会话标题、等待回复位置使用紧凑角色。原有新建／切换对话、停止、确认、文件和导航卡片行为不变。聊天标题处不漫游，不能遮挡正文或操作。

光球按用户的试用反馈重新设计为青蓝紫极光光带：先生成透明素材，再以 WebGL 纹理变形、不同半径的扭动和色相漂移表现流动。状态变化平滑调整速度与颜色，工作时持续环绕，完成时跳跃与光晕扩散。大形象最多 30fps，离屏／后台停止绘制；小图标使用同一素材和轻量 CSS 呼吸。关闭动画、系统减少动态效果或 GPU 不可用时保留静态素材。设置页可逐项预览。鲸鱼用素材映射同一套语义。

动作语义为 `idle / thinking / working / waiting / success / error / speaking / interaction / dragging`。动作状态由实际助手或任务状态派生，角色播放状态不反写业务状态。用户点播可播放原动作库，结束后回到当前工作状态。关闭动画或系统减少动态效果时显示静止画面；素材加载失败有可见提示。

### 3.2 桌宠

设置页「角色助手与桌宠」中开启桌宠；默认关闭，用户开启后记住设置。桌宠透明置顶，支持拖动、点击互动、右键动作菜单、缩放、显示聊天与打开主窗口。透明空白区域允许点击下面的应用；聊天框和菜单获得正常键盘焦点。普通提醒不抢焦点。

开启桌宠不隐藏主窗口或 Dock 图标；关闭主窗口才隐藏主界面并保留后台工作。Dock 激活事件可恢复主窗，菜单栏／托盘能重新打开、隐藏桌宠和明确退出。关闭桌宠后回到原有退出习惯；明确退出时，关闭所有窗口并等待后端停止 opencode。重启恢复角色大小与屏幕位置；以角色本身作为拖动锚点，允许部分越出屏幕，但至少保留 64px 的可拖回区域。聊天、菜单、碎碎念与通知不占用收起时的透明窗口空间；展开时按可用空间依次选择上／下／右／左，保持角色位置与大小不变。面板完整留在工作区；极小屏幕无法并排容纳时允许面板与角色重叠，面板内容可滚动。显示器移除后将角色夹回至少部分可见的位置。

### 3.3 对话接力

桌宠聊天复用 `MessageList` 和现有发送／停止／确认接口。主窗口与桌宠可同时看同一会话，通过后端 SSE 同步消息；跨窗口共享当前会话选择。会话忙时遵守现有 `ASSISTANT_BUSY`，不偷偷开新会话或重复发送。删除当前会话后双方清除选择。

从桌宠发出的消息带明确的桌面来源上下文，不伪称用户正在浏览某个任务页面。模型或用户请求打开任务／表单／文件时，唤起主窗口完成；桌宠自身不导航成完整应用。导航请求只由一个窗口处理，避免双开文件与重复跳转。

### 3.4 碎碎念

保留自动与手动触发，使用现有模型配置和 opencode 适配层。使用独立、无工具的短生成上下文，不污染工作会话，不把碎碎念当作任务指令。默认自动关闭；开启后按可配置间隔生成，用户正在输入／助手忙／通知待显示时不打断。单次最多 120 字符、60 秒，只允许一次在途生成；气泡 12 秒后收起。关闭或退出取消计时及正在进行的生成。

人设采用我们自己的简短描述，功能回答仍须完整准确，不把碎碎念的短句限制应用到任务对话。失败明确显示生成失败，不伪造一条成功回复。碎碎念只产生气泡和说话动作，不弹系统通知。

### 3.5 任务通知

| 真实业务状态 | 提醒语义 | 动作与入口 |
| --- | --- | --- |
| `review` | 已准备好，等你检查／交付 | 庆祝，打开任务结果 |
| `completed` | 任务已完成 | 庆祝，打开任务 |
| `failed` | 任务遇到问题 | 出错，打开失败详情 |
| 新的阻塞问题／权限请求 | 需要你处理 | 等待，打开对应任务或待处理页 |

以任务／状态转换身份去重；同状态的进度更新不再次提醒，重新执行后再次到达同一状态属于新事件。多个任务通知排队，带任务编号／标题，不以单槽覆盖丢失。连接初始状态作为基线，历史完成任务不全量重放。通知由常驻端统一产生，主窗口与桌宠不会各发一次系统通知。断线恢复需对齐状态；退出应用期间不承诺通知或继续执行。

同一条提醒出现在主窗口左下角的气泡、桌宠气泡和系统通知三处，它们是一件事（2026-10-27 用户反馈）：在任何一处点「知道了」「详情」或点系统通知，三处一起收起（主进程按提醒 id 撤下系统通知，并通知两个窗口）；提醒说的事不再成立时也一起撤回——待处理项在任何地方被处理（如在「需要你处理」里允许或作答）、任务进入下一个状态（待检查的任务被合并后只留「任务完成」）。断线重连按快照对齐，期间已处理的项同样撤回。两个窗口各自接收服务器事件、先后不定，所以每个窗口记住已处理的提醒 id，晚到的事件或重连快照不会把它再显示出来或再发系统通知。

## 4. 实现分层

| 位置 | 职责 |
| --- | --- |
| `web/features/companion` | 素材清单、播放器、动作菜单、桌宠界面与共享对话适配 |
| `web/copy/companion.ts` | 全部用户文案与来源说明 |
| `desktop/main/companion*` | 透明窗口、拖动／位置、托盘、唤起主窗口、跨窗口 UI 消息 |
| `shared/contracts` 与 `constants` | 类型化 preload 协议、设置 schema、默认值与限制 |
| `server/modules/assistant` | 碎碎念的无工具生成；继续复用助手模型访问与错误处理 |
| 通知协调模块 | 从真实业务事件生成通知、排序和去重，独立于模型措辞 |

新增设置走既有 `settings` 存储；仅在确有跨重启数据需求时新增持久记录。新增操作进入操作清单；桌面系统能力走经过校验的 preload IPC。凭据不进入角色配置，renderer 不接触任意文件或任意 IPC 通道。

### 4.1 桌面窗口协议与位置迁移

`configure({ enabled, size })` 同步显示与 120–300 的角色尺寸。角色窗口经 `setPanel(none | chat | bubble)` 告知布局需求；主进程验证发送者后计算窗口矩形，并以 `onLayout` 返回相对于原生窗口的角色／面板矩形与方向。渲染端不自行移动系统窗口。收起只保留角色的可见部分与少量光晕／跳跃绘制余量，展开采用角色和面板的包围矩形与工作区交集。

`companion-position.json` 的 v2 格式为 `{ version: 2, x, y }`，记录角色锚点；旧 `{ x, y }` 按旧 460×680 窗口右下角色位置迁移。macOS 的跨桌面显示指定 `skipTransformProcessType: true`，避免创建桌宠时切换整个应用的进程类型。

鼠标穿透（D192）：macOS 与 Windows 上窗口平时 `setIgnoreMouseEvents(true, { forward: true })`，指针移到 `[data-interactive]` 上时渲染端 `setInteractive(true)`。Electron 的 `forward` 只支持 macOS 与 Windows，Linux 上窗口一旦穿透就收不到指针移动，再也变不回可点击，所以 Linux 上桌宠窗口始终接收鼠标、不穿透：收起时窗口只是角色加四分之一边长的余量，展开时是角色与面板的包围矩形，这些透明部分挡住其下的点击。

## 6. 验证计划

- 单元：动作选择与优先级、通知去重／重新执行／队列、窗口位置夹取；只测外部行为，不镜像实现。
- 集成：真实 SQLite 与事件链验证设置、碎碎念无工具会话和失败清理；FakeOpencode 仅证明契约。
- 浏览器：现有助手流程不回归；角色可见、动作加载失败、设置、减少动态效果；至少亮／暗主题截图。
- Electron：透明窗口、鼠标穿透、输入焦点、拖动／多屏、主窗隐藏与恢复、关闭桌宠、明确退出、同一会话与导航。
- live：碎碎念生成和桌宠发起助手任务分别记录真实模型证据；没有跑过的项明确标待验证。
- 交付前按 `06`／`07` 执行适用的类型、lint、依赖边界、测试与构建；不把静态检查或 FakeOpencode 当作完整桌宠验收。

### 7.1 当前明确边界

- 主进程只负责系统通知；各窗口按服务器事件维护自己的提醒队列，关闭某个窗口的提醒不等于另一窗口已读。
- SSE 缓冲可重放时按连续事件处理；缓冲失效时对齐最新快照，不重建断线期间全部中间转换。应用退出期间不驻留，不承诺继续任务或通知。
- 已在本机 macOS 自动验证窗口、拖动、会话／形象同步、主窗隐藏与恢复、关闭桌宠和退出；真实鼠标穿透、显示器拔插、系统通知授权和 Windows/Linux 桌面行为仍需人工／对应平台验收。
- 原创小人和原创动画保持 W6 后续阶段；现在默认光球，鲸鱼可选，所有行为共用同一助手与任务状态。
