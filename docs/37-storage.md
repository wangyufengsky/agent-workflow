# 37 · 存储空间与磁盘清理

> 状态：**已实现，待用户检查**（2026-10-25，用户要求，D157）。任务见 05 的 ST 系列。

## 1. 目标

用户长期使用后，数据目录（03 §7）里的会话记录、截图和日志会一直累积，任务工作区也可能占很多空间，但应用里看不到占用、也没有清理的地方。本功能只在专业模式「运行环境」页加一个「存储空间」面板：看各类占用，清理两类可以安全删除的数据。

不做：自动清理、定时清理、可配置的保留天数、数据库 VACUUM、删除任务或项目（项目删除已会删除其任务的记录，10 §5）。

## 2. 统计

`GET /system/storage`（11 §2）按 `StorageKind`（08）给出每类的字节数与合计，按需统计（打开面板与「重新统计」时），不随事件刷新：

| 类别 | 内容 |
| --- | --- |
| 数据库 | `app.db` 与 WAL 的 `-wal` / `-shm` |
| 日志 | `logs/` |
| 会话记录与截图 | `runs/`（任务、知识问答、PPT、Git 工作台、团队的会话流，截图、预览日志） |
| 任务工作区 | 工作区根目录（设置 `worktree.rootDir`，默认 `<数据目录>/worktrees`）；根目录在数据目录外时另外统计 |
| 助手文件与对话 | `assistant/` |
| 附件 | `attachments/` |
| 其他 | 数据目录里其余的文件 |

统计不跟随符号链接；统计中途被删除的文件（工作区正在清理）按 0 计。工作区的 `node_modules` 很大时统计需要几秒，面板先显示「正在统计…」。

## 3. 清理

`POST /system/storage/clean { target }`（`critical`，每次都要确认，助手也一样）只删除下面两类，返回释放的字节数与清理后的统计：

| 目标 | 删除 | 保留 |
| --- | --- | --- |
| `logs` | `logs/` 中最后修改早于 `STORAGE_KEEP_DAYS`（7）天的文件 | 每类日志（`app-`、`opencode-`）最新的一个，即正在写的那个，无论多旧 |
| `transcripts` | 结束（已完成 / 已取消）超过 7 天的任务的 `runs/<taskId>/`：会话流、截图、预览日志 | 任务行、结果卡、时间线、改动、分支；知识问答、PPT、Git 工作台、团队的记录（它们的对话仍在界面上） |

会话流读取时文件不存在即为空（`attempts.transcript.ts`），所以清理后这些任务的步骤会话回放显示为空，确认框写明这一点。失败、等待处理的任务不在清理范围内（可以重试）。

任务工作区不在这里清理：任务合并或放弃后工作区自动删除，残留的在 Git 工作台的工作区总览里处理（27），面板给出提示。

## 4. 界面

运行环境页（14 §1）在日志面板之后加「存储空间」面板：标题旁显示合计与「重新统计」；逐行列出各类与大小；数据目录与工作区目录的路径；「清理」小节列出两个目标、可清理的数量与大小，数量为 0 时按钮不可用；点击后弹出确认框，确认后提示「已释放 …」。
