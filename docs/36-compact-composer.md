# 36 · 精简助手输入区

> 状态：**设计稿，待用户确认**（2026-10-24）。决策 D143–D145 为推荐方案、待用户检查；需要拍板的取舍见 §8。确认前不改代码；确认后按 §9 实施（05 的 Y 系列），并把结论同步进 15 §6 / §6.2、28 §2、30 §2、14 §3.2 / §8。

## 1. 要解决的问题

用户在 1.0.0 安装版里试用主页对话后截图反馈：助手的回答只占窗口上半部分，下面的输入区太高，「严重压缩了对话界面」。三点具体意见：

1. 输入框顶部常驻的用量统计（三行）要取消，可以改成需要时才看的入口，或完全移除。
2. 「添加资料」「项目文件」「附上选中文字」各占位置（「附上选中文字」还单独占一行），加上「问助手 · 选一个流程可直接开始任务」与「⌘↵ 发送」，整体太高。
3. 「直接开始」的流程按钮已有 11 个、还会更多，两三行按钮占了很大空间，希望默认收起，点击后用动画展开。

这块输入区由三处共用：主页（`home-composer.tsx`，D111）、⌘J 面板与桌宠（`assistant/composer.tsx`）。本文的改动对三处同时生效（「直接开始」只有主页有）。

### 1.1 现在有多高

按截图量（窗口约 1000 × 625，下同为 CSS 像素），主页「对话中」的输入区自上而下：

| 行 | 内容 | 约高 |
| --- | --- | --- |
| 1–3 | 用量：「最近一轮 · 已完成 · 输入 … · 输出 … tokens · 耗时（含等待）…」「会话累计已报告 … tokens · 自 … 起；此前未知」「时限 60 分钟（不含权限等待）」 | 54 |
| 4 | 输入框（一行占位文字） | 24 |
| 5 | 「添加资料」「项目文件」（`AttachmentBar` 的按钮行） | 28 |
| 6 | 「附上选中文字」（`ContextAttachments`，单独一个 `div`，所以另起一行） | 28 |
| 7 | 「问助手 · 选一个流程可直接开始任务」…「⌘↵ 发送」(↑) | 32 |
| — | 框的内边距与行间距 | ≈ 24 |
| 8–9 | 框外：「直接开始」两行流程胶囊（11 个） | ≈ 64 |

合计约 **240px**，占主区域（顶栏以下约 557px）的 **43%**；消息流只剩约 245px。⌘J 面板宽 480px，没有流程胶囊，但用量与两行附件按钮同样在，框约 170px。

## 3. 用量改为按需查看（D143）

**推荐**：常驻的三行去掉，换成底栏右侧一个 16px 图标按钮 `(◔)`（`aria-label`「助手用量」，提示文字为最近一轮的一句摘要，例如「最近一轮 · 已完成 · 输入 89,421 · 输出 609 tokens」），点击或回车打开一个锚定在按钮上方的小浮层，内容就是现在的三行，原样保留。

- **内容与口径不变**：15 §6.2 的全部规则（只显示模型实际报告的用量、未报告与真实 0 分开、统计起点、会话累计与未报告轮次、含等待的耗时、时限）都不动，`UsageLine` 的文字不变，只是从「常驻」改为「点开才看」。后端、`assistant_turns`、SSE 都不改。
- **何时出现**：与现在常驻行的条件相同（对话存在且已有用量记录）。进行中时浮层里的耗时照常走秒。
- **不丢信息**：本轮的结束原因不只在用量行里——超时、停止、运行时消失都会在消息流里写一行系统消息（`TranscriptSystemEvent.TimedOut` / `Aborted` / `RuntimeLost`），失败有错误卡片，忙碌有「正在思考」与停止键。所以收起用量不会让用户错过「这轮出了什么事」。
- **浮层**：平台 `popover`（轻点外部或 `Esc` 关闭，焦点回到按钮）+ CSS 锚点定位，同对话列表（15 §6.1）；`role="dialog"`、`aria-label`「助手用量」，内部仍是现在的 `section`。

与已有决策的关系：15 §6.2 是用量功能的设计本身，**没有对应的 D 编号**（02 中没有登记它的显示位置）；本文只改它的显示位置，并在 15 §6.2 第一段写明「在输入区底栏的用量按钮里查看」。19 §2「不在本看板统计内」一段说助手用量在对话输入区查看，仍然成立（文字改为「在对话输入区的用量按钮里查看」）。

考虑过的其他方案：

| 方案 | 不选的原因 |
| --- | --- |
| A（推荐）底栏图标 + 点开的浮层 | — |
| B 完全移除 | 助手用量就在界面上哪里都看不到了：质量与用量看板明确不统计助手（19 §2），用户也就没法知道一次问答花了多少 tokens；15 §6.2 刚实现的口径白做 |
| C 每条回复下一行弱化小字（「89k / 609 tokens · 10.4 秒」） | 每轮都多一行，长对话里是噪声；会话累计与时限仍没有地方放 |
| D 放到对话标题旁 | 主页、面板、桌宠三处的头部各不相同，要写三遍；用量是「这一轮」的事，挨着发送键更好找 |

## 4. 附件与上下文收进「+」菜单（D144）

`(+)` 按钮（`aria-label`「添加资料与上下文」，`aria-haspopup="menu"`）打开一个向上弹出的菜单：

| 菜单项 | 现在的按钮 | 出现条件 |
| --- | --- | --- |
| 📎 上传文件… | 「添加资料」 | 总是 |
| 📁 项目文件… | 「项目文件」 | 主页（问助手与开始任务两种模式）；有项目时（30 §2.1，面板不属于某个项目，没有这项） |
| ❝ 附上选中文字… | 「附上选中文字」 | 问助手模式（主页、面板、桌宠） |
| 📋 附上任务详情 / 附上步骤详情 | 同名按钮 | 面板与桌宠，当前在任务 / 步骤页时（15 §6） |

- **行为不变**：每一项点下去做的事与现在的按钮完全相同（文件选择框、项目文件对话框、选中文字的编辑弹窗、任务快照）。拖放与粘贴文件照旧（30 §2），所以最常用的「拖进来」不需要打开菜单。
- **已附加的资料**：附件卡片列表仍在输入与底栏之间，只在有附件时出现；「暂不支持图片，请用文字描述」这类提示（`draft.notice`）放在卡片列表的位置（没有卡片时单独一行，`role="status"`），出现时才占高度。
- **「附上选中文字」要保住选区**：现在的按钮在 `mousedown` 上 `preventDefault`，点击时还能读到页面选区。改为在按下 `(+)` 时（`pointerdown`，键盘为 `Enter` / `Space` 打开时）先记下 `window.getSelection()` 的文字，点菜单项时用记下的那份；仍然只在用户操作时读取，不读剪贴板、表单或整页（15 §6）。
- **无障碍**：菜单 `role="menu"`，项为 `menuitem`；打开时焦点到第一项，`↑` / `↓` 移动、`Home` / `End` 到首尾、`Enter` / `Space` 选择、`Esc` 关闭并把焦点还给 `(+)`；平台 `popover` 负责轻点外部关闭。
- **问助手提示行**：底栏原来的「问助手 · 选一个流程可直接开始任务」去掉。模式仍写在框里：问助手模式由占位文字（空闲「今天想让 AI 做什么？」，对话中「接着说，或选一个流程直接开始任务…」）与底栏的「直接开始」按钮表达，开始任务模式由顶部标签表达（D111 不变）。底栏去掉提示后只有图标，宽度够放在一行，不再换行。

考虑过的其他方案：

| 方案 | 不选的原因 |
| --- | --- |
| A（推荐）一个「+」菜单 | — |
| B 三个图标按钮排在底栏（📎 📁 ❝），不要菜单 | 少点一次，但纯图标的「项目文件」「附上选中文字」很难认；面板在任务页时还要第四个；底栏变挤 |
| C 只留「上传文件」图标，其余放进输入框的 `/` 命令 | 发现性差，简单模式用户不会知道；要新做命令解析 |

## 5. 「直接开始」默认收起（D145）

### 5.1 收起与展开

- **收起**（默认）：底栏一个小胶囊 `[⚡ 直接开始 ▾]`（28px 高，与现在对话中的胶囊同一种样式）。主页空闲与对话中都默认收起；不记住上次是否展开（每次进入主页、点「新对话」都是收起）。
- **展开**：点胶囊后，**框内**、底栏上方出现流程面板，上方一条 `--hairline` 分隔线；面板里是全部流程胶囊（内置流程在前，专业模式的自定义流程在后，中间用一个小标题「自定义」隔开），自动换行。胶囊仍显示图标与名称，`title` 为流程说明（同现在）。框随之变高：对话中框停靠在底部，所以向上长、消息流相应变矮（消息流贴底跟随，最新一条仍可见）；空闲时向下长，把「试试问」推下去。
- **选中一个流程**：面板收起，框切到「开始任务 · 流程名」（与现在点胶囊相同），焦点回到输入框。
- **收起的方式**：再点一次胶囊、`Esc`（焦点在面板里时）、选中流程。点框外不收起（面板在框内，不是浮层；误点外面不应把用户正在看的东西收走）。
- 侧栏「开始任务」、`⌘N`、地址里的 `workflow`（`open_form`、「据此修复」）照旧直接进入开始任务模式，不经过面板。

为什么放在框内而不是框外或浮层：框内展开时两种状态的方向都自然（停靠在底部的框向上长、居中的框向下长），选中后框原地变成「开始任务」，视线不用移动；浮层会盖住最后几行回答，用户常常是读完回答才决定用哪个流程。

### 5.2 动画

只用 CSS（D84 ③ 的原则，不引入动画库）：

| 动效 | 规格 | `prefers-reduced-motion: reduce` |
| --- | --- | --- |
| 面板展开 | 高度 0 → 自动，`interpolate-size: allow-keywords` + `transition: height`，0.28s `--ease-spring`；`@starting-style` 配合 `transition-behavior: allow-discrete` 处理从 `hidden` 到显示 | 不做高度动画，直接出现 |
| 胶囊出现 | 每个胶囊淡入并上移 4px，0.2s，按序号错开 15ms（`--i` 自定义属性，11 个约 0.15s 内全部出现） | 无 |
| 面板收起 | 高度与透明度反向，0.16s，结束后 `hidden` | 直接消失 |
| 「▾」 | 展开时旋转 180°，`--t-fast` | 不旋转（仍以 `aria-expanded` 表达） |

Electron 44（Chromium 140 以上）与 Playwright 的 Chromium 都支持 `interpolate-size` 与 `@starting-style`。

### 5.3 键盘与读屏

- 胶囊是 `button`，`aria-expanded`、`aria-controls` 指向面板；面板 `role="group"`、`aria-label`「选择流程开始任务」，收起时 `hidden`（不在无障碍树里、不可聚焦）。
- 展开时焦点移到面板里的第一个胶囊（开始任务模式下从标签打开时，移到当前流程）；面板在 DOM 里位于底栏之前，所以不移焦点的话 `Tab` 会越过它。面板内用 `Tab` / `Shift+Tab` 在胶囊间移动，`Esc` 收起并把焦点还给「直接开始」。
- 选中的流程仍用 `aria-pressed` 表达（开始任务模式下打开面板时可见）。
- 展开 / 收起不额外播报：`aria-expanded` 的变化读屏会读出。

### 5.4 考虑过的其他方案

| 方案 | 不选的原因 |
| --- | --- |
| A（推荐）底栏「直接开始 ▾」，框内展开全部 | — |
| B 只露最常用的 4–5 个 + 「更多」 | 「最常用」要么按使用次数排（新查询、顺序会变、肌肉记忆失效），要么写死（新流程永远在「更多」里）；仍占一行 |
| C 框外保留一行「直接开始 ▾」 | 收起时仍多一行约 36px，只解决了一半 |
| D 浮层（popover）展开 | 盖住最后几行回答；与「+」菜单长得一样，用户分不清哪个是附件哪个是流程 |
| E 空主页展开、对话中收起 | 空主页确实有空间，但同一个控件两种默认状态，用户在两处看到的不一样；用户的提议是默认收起。作为备选列在 §8 |
