# 14 · 界面规格

设计稿 `opencode-workflow-design-showcase/` 是视觉与交互参考。本文定义 v1.0 实际要做的页面、简单/专业两层界面、主题配置与对设计稿的改进。设计稿中没有的简单模式页面，按本文描述实现，沿用设计稿的视觉语言（令牌、间距、组件形态）。

## 1. 路由与页面

**简单模式的硬约束（38 C6，D158）**：侧栏导航不超过 5 项（主页、任务、项目、知识问答、设置；PPT、质量与用量、团队只在专业模式的导航里，路由两种模式都能打开）、主页「直接开始」的流程按钮不超过 5 个（其余在「更多流程」里）、主页工作概览最多三段（需要你处理、进行中、待合并）。新功能默认只进专业模式；要进简单模式的导航、主页或设置，在设计文档里写明理由并单独确认。走查（J9）截图时核对。

路由常量在 `web/src/app/routes.ts`（侧栏内页面挂在无路径布局路由 `_shell` 下，`getRouteApi` 用 `ROUTE_IDS`）；导航配置在 `web/src/app/navigation.ts`。没有任何项目时，侧栏内的页面都重定向到 `/onboarding`。开发构建另有 `/dev/components` 组件走查页（E2E 在全部主题下截图，生产构建不含）。

专业模式页面在简单模式下直接访问时显示「此页面属于专业模式」及开启按钮，不报错不重定向（`ProOnly`）。

专业页面（M5）：

- 流程 `/workflows`：卡片列出流程（内置 / 自定义、规划方式、产出、版本）。内置流程「查看」（只读）与「复制」；自定义流程「编辑」与「删除」（确认对话框）。「新建流程」选择固定步骤或 AI 规划，从现有角色生成空白定义（固定流程含一个步骤）。复制与新建都只问 key 与名称，然后进入编排器。
- 编排器 `/workflows/:key`：基本信息、允许的角色（勾选）、默认检查点、步骤的默认检查；固定流程用计划画布编辑模板（§5，规则为流程的允许角色），工具条的「插入流程的步骤」打开对话框，列出别的固定流程（选中后说明处显示它的步骤链），「插入」把它的步骤复制到所有末步之后，重名的标识加后缀（`fix_2`），被复制步骤的角色并入允许角色，可撤销（34 §15.7，D150）；AI 规划流程编辑规划者角色、规划指引（Markdown）与必经步骤（key、标题、角色、位置最先 / 最后 / 不限、指令、检查）。步骤的检查（这里与计划画布共用一个编辑器）依次为运行命令、「页面体检」（勾选后可填空格分隔的页面路径，留空用项目的关键页面，v1.3，29 §7.1）、AI 评审与人工验收；改其中一项不影响其余各项。右侧实时显示 `validateWorkflowDefinition` 的问题（08 §5.4）与版本历史，「保存为新版本」后编辑器从新版本重新开始。
- 角色 `/roles`：卡片（名称、说明、key、基础类型、模型）；内置角色只能复制，自定义角色可编辑（名称、说明、提示词、模型）与删除。模型下拉来自 opencode 的 provider 列表（`/system/environment` 的 `models`），另有「使用默认模型」。
- 数据库 `/databases`：连接卡片（类型、用户@主机:端口/库、TLS：加密时显示「TLS」，不校验证书时显示「TLS · 不校验证书」）；添加 / 修改对话框（第一项是类型：MySQL、PostgreSQL、openGauss / GaussDB、SQL Server、GoldenDB，下方一句该类型的说明；端口按类型预填，未改过的端口随类型切换，24 §2；密码只写，修改时留空表示不改；最后一项「TLS 加密」下拉：不加密 / 加密并校验证书 / 加密但不校验证书，下方一句该档的说明，「加密但不校验证书」写明可能被冒充，D166）、测试连接（显示服务器版本或驱动错误）、浏览表结构（抽屉：表、注释、行数估计、列）、删除（确认）。项目详情页在专业模式下有「关联数据库」勾选列表。
- MCP 工具 `/tools`：每个执行 MCP 工具的名称（及 opencode 中的全名）、说明、可用于哪些尝试类型、输入 JSON Schema（折叠）。
- 运行环境 `/runtime`：另有 opencode 日志面板（最新一天的日志末尾 200 / 500 / 2000 行，手动刷新）与「存储空间」面板（各类占用、清理旧日志与旧会话记录，37 §4）。
- 设置：专业模式另有「专业设置」面板，覆盖 08 §4.3 中模式为专业的每一项（默认模型、bash 策略、每任务并发步骤、最多尝试、尝试时限、AI 草拟提交信息的时限、合并方式、合并后删除分支、worktree 目录、opencode 路径）。

运行环境页（M2-09）：opencode 状态徽标、版本、要求版本、可执行文件、`ready` 时的服务地址与启动时间；「重启 / 启动 opencode」按钮（`stopped` / `crashed` / `ready` 时可用，提示会中断进行中的会话）；不可托管时链接到环境检测页 `/environment`；可用模型数与默认模型。开发构建（`import.meta.env.DEV`）另有调试入口：填 Git 目录、要求、可选模型，发起一次执行尝试，`?attempt=<id>` 显示该尝试的状态、当前进展、用量与实时会话流（用户消息、思考默认折叠；工具调用与结果折叠显示输入 / 输出；系统事件与错误按文案显示）。侧栏运行指示点读取 `GET /system/runtime`，随 `runtime.updated` 实时变化。

## 2. 全局框架

- 左侧栏：品牌、「开始任务」主按钮（跳主页，输入框切到「开始任务 · 新功能开发」并聚焦）、导航、底部运行环境指示点（ready 绿 / 其他黄红，点击简单模式进环境检测页 `/environment`，专业模式进运行环境页）。
- 顶栏：面包屑、「需要你处理」徽标按钮（数量 > 0 时高亮，点击从右侧弹出条目列表，就地处理，底部「查看全部」进入 `/inbox`）。顶栏不放主题切换（38 C4）：换主题在设置页与 ⌘K 的「切换主题」。侧栏「任务」旁显示同一个数量。数量只数卡住任务、等用户行动的打开条目（`BLOCKING_INBOX_KINDS`：除「待合并」外的所有种类，D119）；弹出列表先列这些，再在「等你合并」标题下列待合并条目，只有待合并时上方一句「没有等你回答或决定的事情。」。
- 主密码锁定提示条（D178）：设置了主密码、本次启动还没解锁时（`EnvironmentDTO.credentials.masterPassword = locked`），顶栏下方、页面之上一条警告提示条（锁图标），说明令牌与数据库密码还锁着、建 PR、推送、取回审查意见、查询数据库（包括 AI 用到数据库的步骤）都要先解锁，内有主密码输入框与「解锁」（§3.1 的同一个解锁框）；不能关闭，解锁后消失。
- 设计稿的演示条（顶部 ←/→、展示模式、原型目录）与底部原型控制条**不进入产品**。
- 最小窗口 1024×700；以 1280 宽为主设计宽度。对话框最高为窗口高度减 32px，内容更高时（如带错误与解锁框的数据库连接表单）在窗口内滚动。布局问题（一栏被挤到没有宽度、按钮挤出卡片）不一定造成页面溢出，所以容易出问题的页面在 e2e 里于最小窗口下量控件实际宽度与边界（`e2e/helpers.ts` 的 `box`、`MIN_WINDOW`）：PPT 大纲的标题与要点、PPT 预览、流程卡片的操作、Git 的提交详情与 diff。
- 快捷键：`⌘K` 命令面板（§2.1）、`⌘J` 应用助手面板（v1.1，见 [15 §6](15-assistant.md#6-界面)；主页上聚焦主页输入框，D112）、`⌘N` 开始任务、`⌘,` 设置。
- 打开动画（D113，28 §5）：应用启动时窗口先显示约 1.2s 的「Everything is a *Workflow.*」动画，与后端启动并行，点击或按键跳过；reduced-motion 或设置「外观 → 打开动画」关闭时静态显示一帧直到后端就绪。
- 顶栏另有助手按钮（开合面板）；面板浮在主内容之上（顶栏下方、右侧，磨砂玻璃，不遮罩），页面宽度不变，未被覆盖的部分照常可用，被覆盖的部分收起面板即可操作（D84，规格见 [15 §6.1](15-assistant.md#61-视觉规范d84)）。

### 2.1 命令面板 ⌘K

- 数据来源：静态导航项（按模式过滤）+ 最近任务（最近更新的 50 个，可按编号、标题、项目、流程搜索）/ 项目搜索 + 操作清单 `GET /operations?expose=palette`（按当前模式过滤操作的 `mode`）。
- 无参数操作（切主题、切模式、重新检测环境、重启 opencode）直接执行；有参数操作（开始任务 → 主页表单、添加项目 → 添加对话框）打开对应页面或表单，不在面板里做复杂表单。前端为每个面板操作登记执行方式（`use-palette-items.ts`），没登记的操作不显示。
- `critical` 级操作不进入命令面板。
- 面板组件与 v1.1 助手的确认卡片共用操作标题与参数摘要的渲染逻辑。

### 2.2 AI 写的文字（Markdown）

AI 写的文字一律经 `components/markdown.tsx` 按 Markdown 显示，不直接当纯文本输出（D114）：

- 范围按「模型经 MCP 工具提交的字段」（`shared/contracts/mcp/`）逐个对照，而不是按页面：`submit_result`、`submit_plan`、`submit_review`、`ask_user`、`report_progress`、`submit_answer`、Git 审查的发现；PPT 的大纲与幻灯片内容由幻灯片自己的渲染处理（23 §5）。
- **段落**：步骤摘要（任务页侧栏「步骤」、节点抽屉「产出」、结果卡各步骤摘要与审查报告）、注意事项、计划说明、AI 评审的说明、重试时带给 AI 的检查意见、失败详情中的最后一次检查意见、需要你处理中的提问、PR 审查意见的发言、Git 审查的发现与建议、知识问答与助手的回答、会话流的正文。
- **行内**（`inline`，只保留粗体、斜体、删除线、行内代码与链接，标题、列表等退化为文字）：假设（结果卡、计划确认、节点产出、PPT 的理解）、改动文件的说明、AI 评审问题的描述、提问的默认假设与选项按钮、计划确认中步骤的指令（两行预览）、AI 汇报的当前进展（任务页「正在：」、任务卡片、批量任务表、会话流与规划进度、PPT 生成条）、Git 审查发现的标题。
- 安全边界：不渲染原始 HTML（`<script>`、`<img onerror>` 等按文字显示）；链接经 `ExternalLink` 用系统浏览器打开，应用窗口不跳走（助手回答里的应用内路径仍在应用内打开）。
- 代码块用主题令牌（`bg-sunken`、`line`），长行在块内横向滚动，不撑宽所在的面板；表格同样在自身内横向滚动。
- 专业视图的节点页「指令」与会话流中发给 AI 的提示词一样按原文显示（看的是发给模型的原文）。
- 不是 AI 写的文字仍是纯文本：命令输出与工具原始输入输出（`pre`）、提交信息正文、批量与定时任务的说明（来自 `copy/`）、PPT 的讲稿与页面内容（编辑框与幻灯片有自己的渲染）。

### 2.3 diff 浏览器与大视图

- 组件 `components/diff/`：文件树（状态、+/− 行数）+ 单个文件的 diff（行号、增删底色、shiki 高亮、长行自动换行；Git 工作台的审查标记与定位到行）。结果卡、节点「改动」、Git 工作台共用。
- **随可用宽度排版**（容器查询，不看窗口宽度）：宽度不足 640px（如 520px 的节点抽屉、Git 工作台的提交详情栏）时文件树叠在 diff 上方（最高 160px，内部滚动），diff 占满整行；并排视图在这个宽度下每边只剩一条缝，切换按钮隐藏，只用合并视图。
- **大视图**（D114，`DiffDialog`）：节点「改动」页签右上角「放大查看」、结果卡「查看改动」与改动文件名打开几乎占满窗口的对话框（四周各留 24px）：左侧文件树带 +/− 行数，右侧该文件的完整 diff，两侧各自滚动；`↑` `↓` 或 `j` `k` 在文件间切换（顺序同文件树，列表自动滚到选中项），`Esc` 或右上角关闭；从结果卡的文件名打开时先显示那个文件，再次打开从头开始。
- **合并视图为默认，并排视图可切换**：AI 的改动多为新增与小范围修改，合并视图一行一列最省宽度、在任何宽度都能读；并排视图对比改写的段落更直观，但需要约 1000px 以上才不换行，所以只在宽处（大视图、Git 工作台、专业节点页）提供，组件已有、开关成本为零。

| 失败 | 失败说明（哪一步、原因的用户文案、可展开技术详情）+「重试」；页头「取消任务」。失败只在这里说明一次，侧栏不再重复它的「需要你处理」条目。**步骤失败的原因与出口**（D118）：首句用完次数且最后没通过的是命令检查时为「步骤「X」多次尝试后，检查 `pnpm test` 仍没有通过。」，否则「执行步骤「X」时多次尝试仍没有完成。」（需要你处理的条目同一句）；其下从这一步读出最后一次为什么没完成：最后一次执行尝试提交了结果时为第一条没通过、也没跳过的检查——命令检查「最后一次运行 `pnpm test` 退出码为 1（或：超时了），输出的最后几行：」加输出末尾 15 行（多于 15 行时「展开全部输出 / 只看最后几行」），AI 评审「最后一次 AI 评审没有通过：」加评审说明与问题清单；没有提交结果时为一句「AI 最后一次没有提交结果就停下了 / 超时了 / 的会话出错了 / 的尝试被中止了 / 没有完成这一步」；有已完成步骤时一句「已完成的 n 个步骤会保留，重试从这一步继续。」。按钮：「重试」、「带上说明重试…」（执行阶段的失败，检查命令无法运行时除外；对话框说明「这句说明会随这一步的下一次尝试一起交给 AI，例如「测试前要先启动本地数据库」。」、输入框「给 AI 的说明」、「重试」，即 `retry` 的 `feedback`）、检查命令的出口（下文）、「查看这一步的过程」（打开步骤抽屉的「过程」页签，`?node=<id>&open=true&tab=process`）；技术详情只有错误码与英文消息。**检查命令的出口**（D116，简单与专业模式相同）：检查命令在应用环境里无法运行时，说明为「步骤「X」的检查命令 `mvn -q test` 在应用环境里找不到程序 `mvn`。这不是 AI 的问题：代码没有被判为不通过，AI 也没有重做。」（126 为「……里的程序 `./gradlew` 没有执行权限」），主按钮为「重新检查」，另有「修改检查命令…」「跳过这项检查…」；因命令检查用完次数时，「重试」旁有「修改检查命令…」。「修改检查命令」对话框：说明「这个任务里还没完成的步骤都改用新命令，然后用 AI 已经交的结果重新检查。」、命令输入框（预填项目当前的检查命令，与失败的命令相同或项目没有时预填失败的命令）、勾选「同时设为项目的检查命令」（失败的命令就是项目的检查命令时默认勾选）、「保存并重新检查」。「跳过这项检查」确认对话框：「跳过后，这个任务之后的步骤都不再运行 `mvn -q test`，结果标为「未验证」。合并前请自己确认代码能通过检查。」与「跳过并继续」 |
| 已完成 / 已取消 | 结果卡只读（显示合并提交或 PR 链接） |

### 3.4 节点详情（简单视图）

右侧抽屉（宽 520px，不遮罩画布：抽屉打开时仍可看到并点击画布，单击另一个步骤即切换抽屉内容；地址 `?node=<id>&open=true`（`&tab=output|changes|process` 打开指定页签，D118），单击画布节点只选中、在侧栏显示摘要，双击或「查看详情」打开抽屉），三个页签；还没有产出的步骤（如运行中）默认打开「过程」：

2. **改动**：本节点结果中列出的改动文件与说明（行内 Markdown；每条路径一行、说明在其下，长路径可在任意处折行，否则抽屉宽度下说明会被挤成一字一行）、提交 sha 与「放大查看」，以及本节点提交的逐行 diff（§2.3：抽屉内文件树叠在 diff 上方、只用合并视图；「放大查看」打开大视图）。
3. **过程**：这一步最近一次执行及其后 AI 评审尝试的会话流（[25](25-conversation-stream.md)，D102–D104）：固定高度的盒子，内部滚动、贴底跟随，上翻后显示「回到最新」；正文、思考（默认收起，正在思考时露出最后几行）、工具调用一行一个动作「编辑 src/a.ts +12 −3」「运行 pnpm test ✓」（本应用的 MCP 工具也写成人话如「提交结果」），结束后连续的动作折叠成组；运行中标题行显示当前进展（`report_progress`）；步骤结束后默认收起为一行摘要。发给 AI 的提示词、模型与提醒次数等只在专业视图显示。

简单模式下直接打开 `/tasks/:taskId/nodes/:nodeId` 时，页面显示与抽屉相同的三个页签，不显示尝试列表、步骤标识与指令。

专业视图跳到 `/tasks/:taskId/nodes/:nodeId` 全页，额外显示：每次尝试（执行与评审）各一个会话流盒子纵向排列（已结束的收起，`?attempt=` 展开并滚到那一次）、完整工具输入输出、发给 AI 的消息、模型 / tokens / 提醒次数（盒子标题行）、指令（长指令换行，默认 9 行），以及重跑（失败的步骤）/ 跳过（未开始或失败的步骤）/ 中止（运行中的会话）按钮；同样的步骤按钮也出现在任务页侧栏的步骤摘要中。

### 3.5 结果卡

```
✅ 已完成 5 个步骤 · 改动 8 个文件 +312 −41 · 检查全部通过
摘要：（各节点摘要合成，AI 写的一段话）
假设：（任务中做出的假设，提醒用户确认）
改动文件：列表 → 点击看 diff
[合并到 main]  [创建 PR]  [让 AI 再改改…]  [放弃]
```

- 首行的检查统计：有未通过的为「n 项检查未通过」；否则有用户跳过的检查为「有 n 项检查没有运行：`mvn -q test`（已跳过）」（D116）；否则「检查全部通过」。有跳过的检查时，「创建 PR」的说明末尾预填「未验证：应用环境无法运行检查 `mvn -q test`，已跳过。」（平台上的审查者看不到结果卡）。
- 「合并到 main」使用设置 `delivery.defaultStrategy`；专业模式另有「合并选项…」对话框选择策略与目标分支。
- 「创建 PR」项目未绑定远端（或没有令牌）时置灰，悬停说明；按钮行下方一句说明「绑定远端仓库并保存令牌后可以创建 PR」加「去项目设置绑定」链接；点击打开对话框，标题与说明预填任务标题与结果摘要。
- 「让 AI 再改改…」打开对话框填写意见（`request-changes`，`reason: user`）；这个任务的预览标签页开着时（桌面版，29 §8.1）另有勾选「附上当前页面」（默认勾选，`page: { tabId }`）。「放弃」= 取消任务（确认对话框）。
- 项目配置了页面预览时，检查统计行之后有「页面」一区（v1.3，29 §8.4）：最近一次页面体检的桌面截图（最多 4 张，缩略图点开看大图，更多时折叠为「其余 n 页」），以及「打开预览」（切到预览页签；任务完成或取消后不显示）。
- 页面体检在节点详情「产出」里每页每视口一行，「过程」里改变页面的浏览器动作可展开看画面；页面体检无法运行时失败面板的出口见 29 §8.3。
- 「查看改动」与改动文件名打开 diff 大视图（§2.3，D114：文件树、unified / 并排视图切换、shiki 高亮、键盘切换文件；点文件名先显示那个文件），worktree 删除后（已完成 / 已取消）只显示列表。
- 冲突时卡片顶部显示冲突文件，主按钮变为「交给 AI 解决冲突」，次按钮「我自己处理」（对话框说明在任务工作区中 `git merge` 并提交的命令；专业模式另有 Git 工作台链接）。
- 上次合并失败（git 失败、平台报错、应用中断）时显示失败说明，按钮照常可再试；合并前检查不通过（如主工作区在目标分支且有未提交改动）以错误提示显示在按钮下方。
- 合并中显示进度；已完成显示「已合并到 main · 提交 <sha>」或 PR 链接（应用内用系统浏览器打开）。
- `report` 类流程：显示审查报告，按钮「完成」（`report_only`）「据此修复」（回到主页，预选修 Bug 流程并以报告预填需求）；方案设计的报告是「据此开发」（预选新功能开发，13 §3.9）。
- **PR 审查意见**（v1.2，21 §9）：已完成且以 PR 交付的任务，结果卡在 PR 链接下方有「审查意见」区。「取回审查意见」实时向平台请求（之后为「重新取回」）；每条意见一行：勾选框（文件与行，或「对话中的评论」）、「在平台查看」链接，下方是各条发言（作者与正文，Markdown）。默认勾选按 D87；下方「补充说明（可选）」与「让 AI 按意见再改改」（至少勾选一条，旁边显示「已选 n 条」）。PR 已合并或关闭、分支两边分叉等错误以错误提示显示在区内。
- 以 PR 交付过的任务回到待合并时，主按钮为「推送到 PR」（`pull_request`，推送到同一个 PR），不显示「合并到 main」与「创建 PR」；按钮下方一句「这个任务已经有 PR，看过改动后推送到同一个 PR。」加「打开 PR」链接。PR 交付完成后显示「已推送到 PR」与「打开 PR」。

分两组（D119）：「等你回答或决定」为卡住任务的条目，按任务分组；最后「等你合并」为待合并条目（每张卡片写明所属任务）。只有待合并时上面一组显示「没有等你回答或决定的事情。」。每种 kind 一个卡片组件，**就地处理**：

| kind | 卡片内容 | 操作 |

### 3.7 项目、任务列表、设置

- 添加项目（项目页的对话框与引导页的「添加第一个项目」共用一个表单）：填写或选择目录后「添加项目」。目录不在任何 Git 仓库里（`PROJECT_PATH_NO_GIT`）时，表单里的错误换成「这个目录还没有用 Git 管理」确认区（D153）：说明任务要在 Git 分支上进行，列出三件事——运行 `git init -b main`；写入 `.gitignore` 并列出将忽略的规则（已有时写「保持不变」）；把现有的 N 个文件（共多少）作为第一个提交（用户自己的 Git 身份，没有设置时用 agent-workflow）；统计中显示「正在统计要纳入的文件…」。总量达到 `GIT_INIT_LARGE_TOTAL_BYTES` 或有文件达到 `GIT_INIT_LARGE_FILE_BYTES` 时在其中加一条警告提示条，列出最大的几个文件并建议先补忽略规则。按钮「初始化 Git 并添加」与「取消」；改动目录或取消后回到原表单。仓库的子目录仍显示原错误、提示选择仓库根目录。
- 项目：卡片列表（名称、路径、默认分支、活动任务数；路径放不下时省略中间、保留末段目录，完整路径在悬停提示里，`components/path-text.tsx`，Git 工作台同）；详情页编辑名称、默认分支、检查命令、远端绑定（平台、自建 GitLab 地址、仓库、令牌；由 origin 预填，保存前验证令牌；已绑定时可更换令牌或解除绑定；未单独绑定而 origin 的平台有全局令牌时，提示正在用全局令牌，D155）；专业模式显示关联数据库，以及「总是允许的命令」：在「需要你处理」中选「总是允许」记下的 bash 模式（等宽字体，按记下的时间），每条可「撤销」，没有时显示「还没有总是允许的命令。」（D101）。
- Git 工作台（专业，v1.2 重做，27 §6，D110）：概览为项目卡片（当前分支、与远端、未提交改动、最近提交、最近一次审查、远端状态 chip（项目令牌：平台名；全局令牌：「GitHub · 全局令牌」；有 origin 没令牌：「GitHub 未绑定令牌」；没有可识别的平台：「没有 GitHub / GitLab 远端」，D155）；读不到仓库时说明并去项目页）；单个仓库为占满内容区的工作台：页头工具条（项目切换、分支 ▾ 切换 / 新建、领先落后、未提交改动、上次获取时间、获取、拉取、推送、合并…；主工作区有未完成的合并时提示）；左栏视图「改动 / 提交 / 分支 / 文件 / Worktree」、提交筛选（分支、作者、提交信息或 SHA）、本地与远端分支快捷列表、远端说明（同卡片的四种状态，另写明推送与 PR 用哪个令牌）；「提交」视图中栏为按日期分组的提交列表（简化图谱、HEAD 与分支标签、审查徽标，「加载更早的提交」），右栏为提交详情（正文、作者 / 提交者、SHA 复制、父提交（合并提交切换对比的父）、所在分支、改动统计；页签「改动文件」与「AI 审查」）；「改动」视图左栏为已暂存 / 未暂存文件（整文件暂存与取消），中间为 diff，右侧提交面板（标题、正文、「AI 草拟」、作者、提交 ▾ 提交并推送、「AI 审查改动」）；「分支」视图为分支表（切换、合并到当前分支、更多：推送 / 创建 PR / AI 审查 / 比较 / 新建 / 删除；任务分支只读并链接任务页）与任意两个版本的比较（起点也可以按日期选：「到」在那天 0 点之前的最后一个提交，diff 上方写明起点；可「审查这段差异」）；「文件」与「Worktree」同 M4-08。对话框：合并（合并提交 / 压缩为一个提交，冲突时列出文件并「交给 AI 解决」）、推送（列出将推送的提交、不强推）、新建分支、删除分支（未合并的再确认）、创建 PR。
- 项目详情的「AGENTS.md」（40 §7，两种模式都有，在「项目」面板之后）：一句「默认分支 main 上的版本」或「默认分支 main 上还没有 AGENTS.md。」与为什么要有它；有文件时 Markdown 渲染（最高 360px，内部滚动；过大或二进制时一句说明）；有未结束的整理任务时一行「正在整理：T-12 · 生成 AGENTS.md」+ 状态，链接到任务页，不显示表单；否则表单：「补充说明（可选）」、勾选「加入适合 Agent Workflow 的规则」（默认勾选）与「预览这一节」（展开渲染后的规则）、主按钮「让 AI 生成」/「让 AI 补充」，成功后进入任务页。整理任务更新时面板随 `task.updated` 重新读取。
- 项目详情的「页面预览」（v1.3，29 §8.5，两种模式都有）：启动命令、关键页面（每行一个），其余（安装命令、就绪路径、额外允许的地址）在「更多设置」里；「保存」与「试运行」（在主工作区启动一次，成功显示地址与日志末尾，失败显示错误与日志末尾；没有保存过设置时不可用）。启动命令留空保存即不使用页面预览。

## 4. 主题配置

### 4.1 结构

```
web/src/theme/
├─ tokens.ts             THEME_TOKEN_NAMES 与 ThemeTokens 类型（键与设计稿 skins.css 变量一一对应）
├─ theme-definition.ts   ThemeDefinition 类型
├─ themes/
│  ├─ default.ts       默认：深色（D152）
│  ├─ claude-code.ts   Claude Code：暖色
│  ├─ codex.ts         Codex：白
│  ├─ deepseek.ts      DeepSeek：蓝白
│  └─ dracula.ts       Dracula：深紫（D154）
├─ registry.ts           THEMES: Record<ThemeId, ThemeDefinition>
├─ apply-theme.ts        resolveTheme(preference, prefersDark)；applyTheme 把 tokens 写成 :root CSS 变量，设置 color-scheme 与 data-theme
└─ use-applied-theme.ts  按设置应用主题，system 时跟随 prefers-color-scheme
```

```ts
export type ThemeDefinition = {
  id: ThemeId;                   // 显示名在 copy 中按 ThemeId 查
  colorScheme: 'light' | 'dark';
  tokens: ThemeTokens;           // Record<ThemeTokenName, string>，键即 CSS 变量名（去掉 --）
  codeTheme: string;             // shiki 主题名
};
```

- `tokens.ts` 的键由设计稿 `originals/main/assets/skins.css` 迁移，CSS 变量名保持不变（`--bg`、`--ink`、`--run-fill`…；`unknown*` 随「回执未知」状态删除，D11；`shadow-card` 来自 ds.css），设计稿的 `ds.css` 迁入 `styles/base.css`（只保留与主题无关的令牌和通用类，原型切换器与 canvas.js 节点样式不迁移）后可直接使用。
- 组件样式（CSS Modules）只能使用 `var(--token)`，禁止写颜色字面量；`pnpm lint:css` 检查 `#hex`、`rgb(`、`hsl(` 出现在主题文件以外即报错。
- 切换：设置 `ui.theme` 变更 → `applyTheme()` 即时生效，无需刷新；`system` 时监听 `prefers-color-scheme`。
- React Flow 的连线、节点、小地图颜色，diff 增删色，代码高亮主题都从当前主题取值。
- 勾选框与单选框不用系统控件，由 `base.css` 按令牌绘制：未选时边框为 `--muted`（非文字对比度），选中后用主按钮的 `--primary-bg` / `--primary-ink`；勾选后的底色与各表面、勾与底色 ≥ 3:1 由主题对比度单测保证。
- 新增主题 = 新增一个 `themes/*.ts` + 在 `ThemeId` 枚举与 registry 中登记；类型系统保证令牌齐全。
- PPT 的页面有自己的主题（与应用主题无关）：每套主题另有一组不透明的幻灯片调色板 `slides: SlidePalette`（`bg` `surface` `ink` `sub` `accent` `fill` `onFill` `line` `codeBg` `codeInk`），渲染时写成页面容器上的 `--slide-*` 变量，PowerPoint 导出也读它；单测校验其对比度（23 §5.2）。
- 工作中的通用动效 `.shimmer`（文字流光，只改遮罩透明度）与 `.caret`（打字光标）在 `base.css`，助手面板与会话流共用（25 §4.6）。
- 界面通用动效都在 `base.css`，只用 CSS，减少动态效果时由全局规则压到瞬间完成：
  - 抽屉、对话框、命令面板与遮罩随 Radix 的 `data-state` 播放进出关键帧（抽屉滑入滑出、对话框与命令面板淡入并轻微上浮、遮罩淡入淡出）；Radix 只在打开时挂载它们，过渡无法播放，关闭时它等动画结束再卸载。
  - 切换页面时页面内容淡入（`.content > *` 挂载时播放）；只改透明度，不改位置，页面第一帧量到的几何就是最终的（光球是否在视口内、画布适配节点）。
  - 平台 `popover` 菜单默认只做透明度的淡入淡出（`:where([popover])`，不改位置，锚定的菜单第一帧就在原处；组件可用自己的类覆盖，如助手的向上弹出菜单）。
  - 页签下划线在选中项上展开、离开的一项收起；按钮与图标按钮按下时缩到 0.97。
- 助手面板的磨砂材质与助手标识也是主题令牌（`frost`、`frost-card`、`frost-edge`、`frost-filter`、`frost-shadow`、`frost-sheen`、`aura`，D84）；与主题无关的动效令牌 `--ease-spring`、`--t-drawer` 在 `base.css`。
- 每套主题在单测中校验：正文/次要文字在 `bg`/`panel`/`sidebar` 及其上叠加的悬停、选中底色（`fill-1`–`fill-3`、`accent-fill`）、外框装饰渐变最浓处，以及助手磨砂面板（`frost` 叠在 `bg`/`surface`/`raised` 上，及其上的 `frost-card` 与悬停底色）上对比度 ≥ 4.5:1，状态文字在其 fill（叠在 `bg` / `panel` 上）上 ≥ 4.5:1，侧栏数量徽标（`stall`）在侧栏及其悬停、选中底色上 ≥ 4.5:1，主按钮与品牌按钮（含悬停）文字 ≥ 4.5:1（沿用设计稿已校验的约束）。渲染后的页面另由 E2E 走查（J9）用 axe 的 `color-contrast` 规则在全部主题下逐页检查（M6-01）。
