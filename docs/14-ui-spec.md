# 14 · 界面规格

设计稿 `opencode-workflow-design-showcase/` 是视觉与交互参考。本文定义 v1.0 实际要做的页面、简单/专业两层界面、主题配置与对设计稿的改进。设计稿中没有的简单模式页面，按本文描述实现，沿用设计稿的视觉语言（令牌、间距、组件形态）。

## 1. 路由与页面

路由常量在 `web/src/app/routes.ts`（侧栏内页面挂在无路径布局路由 `_shell` 下，`getRouteApi` 用 `ROUTE_IDS`）；导航配置在 `web/src/app/navigation.ts`。没有任何项目时，侧栏内的页面都重定向到 `/onboarding`。开发构建另有 `/dev/components` 组件走查页（E2E 在四套主题下截图，生产构建不含）。

专业模式页面在简单模式下直接访问时显示「此页面属于专业模式」及开启按钮，不报错不重定向（`ProOnly`）。

专业页面（M5）：

- 流程 `/workflows`：卡片列出流程（内置 / 自定义、规划方式、产出、版本）。内置流程「查看」（只读）与「复制」；自定义流程「编辑」与「删除」（确认对话框）。「新建流程」选择固定步骤或 AI 规划，从现有角色生成空白定义（固定流程含一个步骤）。复制与新建都只问 key 与名称，然后进入编排器。
- 编排器 `/workflows/:key`：基本信息、允许的角色（勾选）、默认检查点、步骤的默认检查；固定流程用计划画布编辑模板（§5，规则为流程的允许角色）；AI 规划流程编辑规划者角色、规划指引（Markdown）与必经步骤（key、标题、角色、位置最先 / 最后 / 不限、指令、检查）。右侧实时显示 `validateWorkflowDefinition` 的问题（08 §5.4）与版本历史，「保存为新版本」后编辑器从新版本重新开始。
- 角色 `/roles`：卡片（名称、说明、key、基础类型、模型）；内置角色只能复制，自定义角色可编辑（名称、说明、提示词、模型）与删除。模型下拉来自 opencode 的 provider 列表（`/system/environment` 的 `models`），另有「使用默认模型」。
- 数据库 `/databases`：连接卡片（类型、用户@主机:端口/库、TLS）；添加 / 修改对话框（第一项是类型：MySQL、PostgreSQL、openGauss / GaussDB、SQL Server、GoldenDB，下方一句该类型的说明；端口按类型预填，未改过的端口随类型切换，24 §2；密码只写，修改时留空表示不改）、测试连接（显示服务器版本或驱动错误）、浏览表结构（抽屉：表、注释、行数估计、列）、删除（确认）。项目详情页在专业模式下有「关联数据库」勾选列表。
- MCP 工具 `/tools`：每个执行 MCP 工具的名称（及 opencode 中的全名）、说明、可用于哪些尝试类型、输入 JSON Schema（折叠）。
- 运行环境 `/runtime`：另有 opencode 日志面板（最新一天的日志末尾 200 / 500 / 2000 行，手动刷新）。
- 设置：专业模式另有「专业设置」面板，覆盖 08 §4.3 中模式为专业的每一项（默认模型、bash 策略、每任务并发步骤、最多尝试、尝试时限、合并方式、合并后删除分支、worktree 目录、opencode 路径）。

运行环境页（M2-09）：opencode 状态徽标、版本、要求版本、可执行文件、`ready` 时的服务地址与启动时间；「重启 / 启动 opencode」按钮（`stopped` / `crashed` / `ready` 时可用，提示会中断进行中的会话）；不可托管时链接到环境检测页 `/environment`；可用模型数与默认模型。开发构建（`import.meta.env.DEV`）另有调试入口：填 Git 目录、要求、可选模型，发起一次执行尝试，`?attempt=<id>` 显示该尝试的状态、当前进展、用量与实时会话流（用户消息、思考默认折叠；工具调用与结果折叠显示输入 / 输出；系统事件与错误按文案显示）。侧栏运行指示点读取 `GET /system/runtime`，随 `runtime.updated` 实时变化。

## 2. 全局框架

- 左侧栏：品牌、「开始任务」主按钮（跳主页输入框并聚焦）、导航、底部运行环境指示点（ready 绿 / 其他黄红，点击简单模式进环境检测页 `/environment`，专业模式进运行环境页）。
- 顶栏：面包屑、「需要你处理」徽标按钮（数量 > 0 时高亮，点击从右侧弹出条目列表，就地处理，底部「查看全部」进入 `/inbox`）、主题快速切换。侧栏「任务」旁显示打开条目的数量。
- 设计稿的演示条（顶部 ←/→、展示模式、原型目录）与底部原型控制条**不进入产品**。
- 最小窗口 1024×700；以 1280 宽为主设计宽度。
- 快捷键：`⌘K` 命令面板（§2.1）、`⌘J` 应用助手面板（v1.1，见 [15 §6](15-assistant.md#6-界面)）、`⌘N` 开始任务、`⌘,` 设置。
- 顶栏另有助手按钮（开合面板）；面板浮在主内容之上（顶栏下方、右侧，磨砂玻璃，不遮罩），页面宽度不变，未被覆盖的部分照常可用，被覆盖的部分收起面板即可操作（D84，规格见 [15 §6.1](15-assistant.md#61-视觉规范d84)）。

### 2.1 命令面板 ⌘K

- 数据来源：静态导航项（按模式过滤）+ 最近任务（最近更新的 50 个，可按编号、标题、项目、流程搜索）/ 项目搜索 + 操作清单 `GET /operations?expose=palette`（按当前模式过滤操作的 `mode`）。
- 无参数操作（切主题、切模式、重新检测环境、重启 opencode）直接执行；有参数操作（开始任务 → 主页表单、添加项目 → 添加对话框）打开对应页面或表单，不在面板里做复杂表单。前端为每个面板操作登记执行方式（`use-palette-items.ts`），没登记的操作不显示。
- `critical` 级操作不进入命令面板。
- 面板组件与 v1.1 助手的确认卡片共用操作标题与参数摘要的渲染逻辑。

## 3. 简单模式页面

### 3.1 首次启动引导 `/onboarding`

三项检测，每项一行：✅ 已就绪 / ❌ 未就绪 + 一句原因 + 修复指引（可复制的命令）+「重新检测」。

1. Git 已安装（显示版本）。
2. opencode 1.19.0 已安装（未安装：给出安装命令；版本不符：给出切换版本命令；可「手动选择 opencode 路径」）。
3. 至少一个可用模型（未登录：提示在终端运行 `opencode auth login`）。
4. 凭据存储（v1.1，D74）：可用时 ✅；不可用时为警告（不影响「全部通过」），说明暂时不能保存令牌与密码，Linux 上给出安装密钥服务的命令。

安装命令按 `EnvironmentDTO.platform` 显示（17 §3.7）；快捷键提示在 macOS 写 ⌘，其他平台写 Ctrl。

全部通过后「添加第一个项目」→ 选择文件夹 → 进主页。引导完成后不再自动出现（环境异常时主页顶部提示条引导回来）。

### 3.1a 环境检测 `/environment`

有项目之后，同样的四项检测与「重新检测」在侧栏内的这一页（标题「开发环境」），不含「添加第一个项目」：侧栏运行指示点（简单模式）与运行环境页的「查看环境检测」都到这里。引导页在外壳之外、唯一的出口是添加项目，有项目时再进入它会是死路，因此有项目后访问 `/onboarding` 转到本页。

- 流程卡片：图标 + 名称 + 一句话说明；固定流程的卡片右上角有「批量」，进入新建批量任务页（20 §2），右下角有「定时」，进入新建定时任务页（22 §7）；专业模式下额外列出自定义流程，并显示「更多选项」（标题、基于分支、每个步骤由我验收、不确定时停下来问我）与「保存草稿」（`start: false`；任务页的草稿显示「开始」按钮）。

- 点开始 → 立即跳到任务页（任务处于「准备中」）。「开始」不可用时旁边说明原因（如「先描述需求」）。
- 任务按显示状态分组：「进行中」= 准备中 / 执行中 / 已暂停 / 合并中，「待合并」= 待合并，「最近完成」= 已完成。等用户处理的任务（待确认计划、需要你处理、失败）不再列在任务分组里，由上方「需要你处理」的条目给出操作。

- 表单下方是**助手条**（D84）：说明「零散的事，交给应用助手」、三条建议（点即在新对话中提问并打开面板）、「问助手 ⌘J」；主页上唯一的输入框是「开始任务」的需求框，开发任务走表单，零散的事交给助手。

按状态替换主区域：

| 显示状态 | 主区域 |
| --- | --- |
| 准备中 / 规划中 | 画布位置显示进度说明（建立工作区 → AI 正在阅读代码并规划）+ 规划会话的实时进展（`report_progress` 与最近的工具调用一行） |
| 待确认计划 | 只读计划画布 + 规划说明 + 步骤清单（标题、角色、指令摘要，按依赖先后）+ 假设列表；按钮「确认并开始」「按意见重新规划」（输入框）；专业视图另有「编辑计划」（计划画布 §5，保存为新的草稿版本后回到确认） |
| 执行中 / 需要你处理 | 进度画布（上图）；专业视图顶部有「暂停」 |
| 已暂停 | 暂停说明条 + 进度画布；顶部「继续执行」。专业视图的说明条有「调整计划」（计划画布，已开始的步骤加锁），保存后显示「有未确认的调整（第 N 版）」与「确认调整」（任务保持暂停）；继续执行会放弃未确认的调整 |
| 待合并 | **结果卡**（§3.5）替换画布，画布可折叠查看 |
| 失败 | 失败说明（哪一步、原因的用户文案、可展开技术详情）+「重试」；页头「取消任务」。失败只在这里说明一次，侧栏不再重复它的「需要你处理」条目 |
| 已完成 / 已取消 | 结果卡只读（显示合并提交或 PR 链接） |

### 3.4 节点详情（简单视图）

右侧抽屉（宽 520px，不遮罩画布：抽屉打开时仍可看到并点击画布，单击另一个步骤即切换抽屉内容；地址 `?node=<id>&open=true`，单击画布节点只选中、在侧栏显示摘要，双击或「查看详情」打开抽屉），三个页签；还没有产出的步骤（如运行中）默认打开「过程」：

1. **产出**：结果摘要（Markdown）、假设、注意事项、检查结果（命令输出可展开、AI 评审问题清单）。
2. **改动**：本节点结果中列出的改动文件与说明、提交 sha，以及本节点提交的逐行 diff（文件树 + unified / 并排视图，同结果卡）。
3. **过程**：会话回放（正文、工具调用折叠为一行「编辑 src/a.ts +12 −3」「运行 pnpm test ✓」，本应用的 MCP 工具也写成人话如「提交结果」），运行中顶部显示当前进展（`report_progress`）并实时追加，「跟随最新」开关。发给 AI 的提示词、思考过程、模型与提醒次数等只在专业视图显示。

简单模式下直接打开 `/tasks/:taskId/nodes/:nodeId` 时，页面显示与抽屉相同的三个页签，不显示尝试列表、步骤标识与指令。

专业视图跳到 `/tasks/:taskId/nodes/:nodeId` 全页，额外显示：尝试列表与切换（执行与评审尝试）、完整工具输入输出、思考过程、tokens/成本/时间、指令，以及重跑（失败的步骤）/ 跳过（未开始或失败的步骤）/ 中止（运行中的会话）按钮；同样的步骤按钮也出现在任务页侧栏的步骤摘要中。

### 3.5 结果卡

```
✅ 已完成 5 个步骤 · 改动 8 个文件 +312 −41 · 检查全部通过
摘要：（各节点摘要合成，AI 写的一段话）
假设：（任务中做出的假设，提醒用户确认）
改动文件：列表 → 点击看 diff
[合并到 main]  [创建 PR]  [让 AI 再改改…]  [放弃]
```

- 「合并到 main」使用设置 `delivery.defaultStrategy`；专业模式另有「合并选项…」对话框选择策略与目标分支。
- 「创建 PR」项目未绑定远端（或没有令牌）时置灰，悬停说明；按钮行下方一句说明「绑定远端仓库并保存令牌后可以创建 PR」加「去项目设置绑定」链接；点击打开对话框，标题与说明预填任务标题与结果摘要。
- 「让 AI 再改改…」打开对话框填写意见（`request-changes`，`reason: user`）；「放弃」= 取消任务（确认对话框）。
- 「改动文件」可点击：右侧抽屉打开 diff 浏览器（文件树、unified / 并排视图切换、shiki 高亮），worktree 删除后（已完成 / 已取消）只显示列表。
- 冲突时卡片顶部显示冲突文件，主按钮变为「交给 AI 解决冲突」，次按钮「我自己处理」（对话框说明在任务工作区中 `git merge` 并提交的命令；专业模式另有 Git 管理台链接）。
- 上次合并失败（git 失败、平台报错、应用中断）时显示失败说明，按钮照常可再试；合并前检查不通过（如主工作区在目标分支且有未提交改动）以错误提示显示在按钮下方。
- 合并中显示进度；已完成显示「已合并到 main · 提交 <sha>」或 PR 链接（应用内用系统浏览器打开）。
- `report` 类流程：显示审查报告，按钮「完成」（`report_only`）「据此修复」（回到主页，预选修 Bug 流程并以报告预填需求）。
- **PR 审查意见**（v1.2，21 §9）：已完成且以 PR 交付的任务，结果卡在 PR 链接下方有「审查意见」区。「取回审查意见」实时向平台请求（之后为「重新取回」）；每条意见一行：勾选框（文件与行，或「对话中的评论」）、「在平台查看」链接，下方是各条发言（作者与正文，Markdown）。默认勾选按 D87；下方「补充说明（可选）」与「让 AI 按意见再改改」（至少勾选一条，旁边显示「已选 n 条」）。PR 已合并或关闭、分支两边分叉等错误以错误提示显示在区内。
- 以 PR 交付过的任务回到待合并时，主按钮为「推送到 PR」（`pull_request`，推送到同一个 PR），不显示「合并到 main」与「创建 PR」；按钮下方一句「这个任务已经有 PR，看过改动后推送到同一个 PR。」加「打开 PR」链接。PR 交付完成后显示「已推送到 PR」与「打开 PR」。

## 4. 主题配置

### 4.1 结构

```
web/src/theme/
├─ tokens.ts             THEME_TOKEN_NAMES 与 ThemeTokens 类型（键与设计稿 skins.css 变量一一对应）
├─ theme-definition.ts   ThemeDefinition 类型
├─ themes/
│  ├─ deepseek.ts
│  ├─ warm.ts
│  ├─ spdb.ts
│  └─ github-white.ts
├─ registry.ts           THEMES: Record<ThemeId, ThemeDefinition>
├─ apply-theme.ts        resolveTheme(preference, prefersDark)；applyTheme 把 tokens 写成 :root CSS 变量，设置 color-scheme 与 data-theme
└─ use-applied-theme.ts  按设置应用主题，system 时跟随 prefers-color-scheme
```

```ts
export type ThemeDefinition = {
  id: ThemeId;                   // 显示名在 copy 中按 ThemeId 查
  colorScheme: 'light' | 'dark';
  tokens: ThemeTokens;           // Record<ThemeTokenName, string>，键即 CSS 变量名（去掉 --）
  codeTheme: string;             // shiki 主题名
};
```

- `tokens.ts` 的键由设计稿 `originals/main/assets/skins.css` 迁移，CSS 变量名保持不变（`--bg`、`--ink`、`--run-fill`…；`unknown*` 随「回执未知」状态删除，D11；`shadow-card` 来自 ds.css），设计稿的 `ds.css` 迁入 `styles/base.css`（只保留与主题无关的令牌和通用类，原型切换器与 canvas.js 节点样式不迁移）后可直接使用。
- 组件样式（CSS Modules）只能使用 `var(--token)`，禁止写颜色字面量；`pnpm lint:css` 检查 `#hex`、`rgb(`、`hsl(` 出现在主题文件以外即报错。
- 切换：设置 `ui.theme` 变更 → `applyTheme()` 即时生效，无需刷新；`system` 时监听 `prefers-color-scheme`。
- React Flow 的连线、节点、小地图颜色，diff 增删色，代码高亮主题都从当前主题取值。
- 新增主题 = 新增一个 `themes/*.ts` + 在 `ThemeId` 枚举与 registry 中登记；类型系统保证令牌齐全。
- PPT 的页面有自己的主题（与应用主题无关）：每套主题另有一组不透明的幻灯片调色板 `slides: SlidePalette`（`bg` `surface` `ink` `sub` `accent` `fill` `onFill` `line` `codeBg` `codeInk`），渲染时写成页面容器上的 `--slide-*` 变量，PowerPoint 导出也读它；单测校验其对比度（23 §5.2）。
- 助手面板的磨砂材质与助手标识也是主题令牌（`frost`、`frost-card`、`frost-edge`、`frost-filter`、`frost-shadow`、`frost-sheen`、`aura`，D84）；与主题无关的动效令牌 `--ease-spring`、`--t-drawer` 在 `base.css`。
- 每套主题在单测中校验：正文/次要文字在 `bg`/`panel`/`sidebar` 及其上叠加的悬停、选中底色（`fill-1`–`fill-3`、`accent-fill`）、外框装饰渐变最浓处，以及助手磨砂面板（`frost` 叠在 `bg`/`surface`/`raised` 上，及其上的 `frost-card` 与悬停底色）上对比度 ≥ 4.5:1，状态文字在其 fill（叠在 `bg` / `panel` 上）上 ≥ 4.5:1，侧栏数量徽标（`stall`）在侧栏及其悬停、选中底色上 ≥ 4.5:1，主按钮与品牌按钮（含悬停）文字 ≥ 4.5:1（沿用设计稿已校验的约束）。渲染后的页面另由 E2E 走查（J9）用 axe 的 `color-contrast` 规则在四套主题下逐页检查（M6-01）。

## 6. 文案原则

- 用用户的话，不用实现术语。对照表（`copy/glossary.ts` 注释维护）：

| 内部概念 | 界面用语 |
| --- | --- |
| node | 步骤 |
| attempt | 第 N 次尝试（仅专业视图） |
| worktree | 独立工作区（仅专业视图） |
| plan version | 计划（专业视图显示「第 N 版」） |
| acceptance / checks | 检查 |
| inbox | 需要你处理 |
| deliver | 合并 / 创建 PR |
| request changes | 让 AI 再改改 |
| interrupted | 已中断（将自动重试） |

- 不出现：回执、未知、待核对、修订号、投影、领取、围栏等。
- 错误文案：一句话说明发生了什么 + 用户能做什么；技术细节折叠。
