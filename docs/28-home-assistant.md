## 2. 主页布局（D111）

### 2.1 两种状态

主页有两种状态，由地址决定：`/` 为**空闲**，`/?conversation=<id>` 为**对话中**。空闲时助手居中、工作概览在下方；在主页发出第一条消息后进入对话中，消息流占据主区域，工作概览收到右侧。

**空闲**（应用启动后、点「新对话」后）：

```
┌ 侧栏 ┬──────────────────────────────────────────────────────────┐
│      │                ● ─ ● ─ ●                                 │
│      │          Everything is a Workflow.                       │
│      │           万事皆流程，执行由你掌控。                         │
│      │   ┌──────────────────────────────────────────────────┐   │
│      │   │ 今天想让 AI 做什么？                                 │   │
│      │   │                                                  │   │
│      │   │ 问助手 · 选一个流程可直接开始任务            ⌘↵  (↑)  │   │
│      │   └──────────────────────────────────────────────────┘   │
│      │   直接开始：[新功能] [修 Bug] [补单测] [代码审查] [重构]        │
│      │   试试问：列出我的项目 · 哪些事需要我处理 · 每周一 9 点补单测…   │
│      │   最近对话：整理本周失败的任务 · 2 小时前   …       全部对话 → │
│      ├──────────────────────────────────────────────────────────┤
│      │   需要你处理（2）                               查看全部 →  │

└──────┴──────────────────────────────────────────────────────────┘
```

- 顶部是用户喜欢的设计稿标语（`home.html` 的 hero）：三个相连的节点、「Everything is a *Workflow.*」（Workflow. 为 accent 色衬线斜体）、副标「万事皆流程，执行由你掌控。」。它与打开动画（§5）的最后一帧是同一个图形，动画结束进入应用时视觉上是连续的。原 `HOME_COPY.title`「今天想让 AI 做什么？」改为输入框的占位文字。
- **输入框**：与面板同一个输入组件，主页上更大（最少 3 行、最宽 760px）。
- **直接开始**：内置流程（专业模式另加自定义流程，排在其后）以一行流程胶囊列出，点一个即把输入框切到「开始任务」（§2.2）。
- **试试问**：四条建议，点即在新对话中发送；它们特意覆盖不同模块（项目、需要你处理、定时任务、PPT），让人知道助手能做什么（§4）。
- **最近对话**：最近 3 个对话（标题 · 相对时间），点击进入「对话中」；「全部对话」打开对话列表。
- 下方工作概览与现在的主页相同（需要你处理最多 3 条、批量任务、进行中、待合并、最近完成），只是不再有大的流程卡片。

**对话中**：

│      │ ● 整理本周失败的任务 ▾           ＋ 新对话  │ 需要你处理 2     │
│      │                                         │  T-12 有个问题   │
│      │           （消息流，与面板同一组件，         │  T-9 待合并      │

│      │   你：帮我修一下登录页记不住密码的问题       │  T-14 执行中     │

│      │   ┌ 需要你确认 · 开始任务 ──────────┐      │ 批量 1           │
│      │   │ 项目 订单服务 · 流程 修 Bug … │      │  补单测 3/5      │

- 消息流就是面板里的那一个组件（文档 25 负责其样式），主页只决定它的位置和宽度。确认卡片、导航卡片、权限卡片在主页上同样可用。
- 右侧**工作概览栏**（宽 280px）：需要你处理、进行中、待合并、未结束的批量任务，各为一行可点的条目；助手开出的任务会马上出现在这里，与消息流里的导航卡片同步更新。窗口宽度小于 1180px 时默认收起（顶栏「需要你处理」徽标与侧栏计数照常），可手动展开或收起，开合只记在界面状态里。
- 头部：对话标题（点开对话列表，同面板）与「新对话」（回到空闲状态 `/`）。

### 2.2 一个输入框，两个去处

输入框有两种模式，模式总是写在输入框里，不靠猜：

| 模式 | 进入方式 | 输入框里显示 | 发送后 |
| --- | --- | --- | --- |
| **问助手**（默认） | 打开主页；在「开始任务」模式下点标签上的 ✕ | 底部提示「问助手 · 选一个流程可直接开始任务」 | 发给助手：对话中为当前对话，空闲时新建对话并进入「对话中」 |
| **开始任务** | 点「直接开始」中的流程；侧栏「开始任务」与 `⌘N`（选中内置流程「新功能开发」）；地址带 `workflow` / `requirement`（助手的 `open_form`、审查报告的「据此修复」） | 顶部一个标签「开始任务 · 修 Bug ✕」、紧挨着的项目选择（总是显示）及一句流程说明；底部：「运行前让我确认计划」；固定流程另有「批量…」「定时…」两个链接（进入新建批量 / 定时任务页，预选项目与流程，同现在卡片角上的入口）；专业模式另有「更多选项」（标题、基于分支、每步由我验收、不确定时停下来问我）与「保存草稿」 | 直接调用 `tasks.create`（与现在的表单同一个操作、同样的校验与「开始不可用时说明原因」），跳到任务页。**不经过模型、没有确认卡片**：用户自己点「开始」就是确认 |

这样简单模式的用户开始任务仍是一步：点流程 → 写需求 → `⌘↵`。也可以直接跟助手说「帮我修一下……」，助手调用 `tasks_create`，对话中出现确认卡片与导航卡片（J11、J25）。两条路调用同一个操作，结果相同；前者快且确定，后者适合说不清用哪个流程、或顺带要做别的事的时候。

### 2.3 考虑过的其他方案

| 方案 | 不选的原因 |
| --- | --- |
| A（推荐）一个输入框两种模式（上文） | — |
| B 回到 D84 之前：助手输入框在上、开始任务表单在下 | D84 走查发现用户分不清两个输入框该用哪个 |
| C 只有助手：开始任务一律由助手代办（`open_form` 预填表单或 `tasks_create` + 确认卡片） | 最常用的操作要等模型几秒、花 tokens、结果不确定，还多一次确认；违背「一步开始」 |
| D 助手为主，「开始任务」表单折叠在一个按钮后 | 开始任务变成两步；表单仍是第二个输入框 |

代价（A）：主页重写；大的流程卡片（图标 + 名称 + 一句说明）变为一行胶囊，说明移到选中后的标签下；J1、J17、J19 的入口定位要改（流程卡片角上的「批量」「定时」移到「开始任务」模式的底部）。

## 3. 主页对话与 ⌘J 面板（D112）

**同一组对话，两种视图。** 对话只有一套（`assistant_conversations`，15 §2），主页是全页视图，面板是浮层视图，同一时刻只显示一个：

- 主页「对话中」时不显示面板；在主页按 `⌘J` 或顶栏助手按钮，焦点进入主页输入框（空闲时同样）。
- 主页发出的消息带页面 `home`；离开主页后在面板里接着说，带的是当时所在的页面（15 §2，`useAssistantPage` 不变）。

**离开主页时的接力**（主页处于「对话中」，对话为 X）：

| 怎么离开的 | 面板 |
| --- | --- |
| 助手带过去的：`open_page`、`open_form`、导航卡片的「打开」、知识问答引用的原文 | 打开，显示对话 X：用户正在对话中，是助手把他带到了别处 |
| 用户自己点走的：侧栏、工作概览栏、页面里的链接 | 只有 X 正在回复或有等待确认的卡片时才打开；否则不打开，顶栏助手按钮随时打开同一个对话 |

接力用浏览器自带的同文档视图过渡（`document.startViewTransition`，Chromium 内置，不是动画库）：消息流从页面中央移到右侧面板的位置，0.36s；`prefers-reduced-motion` 下直接切换。

**回到主页**：面板开着时回到主页（侧栏「主页」）→ 面板收起，对话移到主页（`/?conversation=<面板当前的对话>`，反向接力）；面板关着时主页为空闲。应用每次启动主页都是空闲状态，上次的对话在「最近对话」里。

代价：多一条「何时自动打开面板」的规则（集中在一个纯函数里并单测，§8）；`⌘J` 在主页与其他页面的行为不同（主页聚焦输入框，其他页面开合面板）。

## 5. 打开动画（D113）

### 5.1 画面与时间线（1.2s）

画面居中：三个节点（圆点）由两段连线串起，下方标语「Everything is a *Workflow.*」与副标「万事皆流程，执行由你掌控。」。底色、文字与 accent 取用户的主题（§5.3）。

| 时间 | 发生的事 |
| --- | --- |
| 0 | 窗口出现即为主题底色（`BrowserWindow.backgroundColor`，没有白屏） |
| 0–0.45s | 三个节点依次弹出（缩放 0.6 → 1 并淡入，错开 0.09s），连线随之描出（SVG `stroke-dashoffset`） |
| 0.30–0.80s | 「Everything is a」淡入并上移 8px，「Workflow.」晚 0.08s 跟上 |
| 0.60–0.95s | 副标淡入 |
| 0.95–1.20s | 停留 |
| 1.20s 起 | 后端已就绪：整体淡出 0.2s 进入应用。未就绪：停在最后一帧，一颗光点沿连线循环流动表示「正在启动」，就绪后淡出 |

只用 CSS 关键帧与内联 SVG，不引入动画库。点击或按任意键立即跳过（后端未就绪时跳到最后一帧等它）。

### 5.2 不拖慢启动：先开窗口，与后端并行

现在的顺序是「等后端就绪 → 才创建窗口」，启动期间用户什么都看不到。改为：

1. `app.whenReady` 后**立即**创建窗口（主题底色），以 `data:` URL 显示打开动画页（`splashHtml`，§7）。
2. 同时启动后端（令牌改由 main 生成，窗口与后端共用）。
3. 两件事都完成后在同一窗口 `loadURL(应用地址)`：后端就绪，**且**动画播完或被跳过（main 经 `executeJavaScript` 等动画页的 `window.splash.done`，再等 0.2s 的淡出 `leave()`）。

因此动画与后端启动重叠：后端启动比 1.2s 慢时，动画不增加时间（把原来的空白等待变成了画面）；比 1.2s 快时，进入应用晚一些，一点即过。

实测（本机 macOS arm64，`pnpm build` 后的应用，全新用户数据目录，各 2 次）：窗口在启动后 0.5–0.9s 出现（原先要等后端就绪，约 1.1–1.3s）；关掉动画时应用在窗口出现后约 0.55s 载入，即后端在窗口出现后约半秒就绪；开着动画时应用在窗口出现后约 1.7s 载入。也就是说这台机器上后端比动画快，动画让进入应用晚约 1.1s（含淡出），点击或按键可立即跳过。

后端在就绪前退出（现在是没有窗口、无声失败）：动画页显示「后台服务没能启动」与「退出」按钮，原因写入日志。

### 5.3 主题与设置从哪里来

动画页出现时后端还没启动，读不到设置（设置在后端的 SQLite 里）。所以前端在设置加载与变化时，经 preload 把「下次启动用的外观」交给 main：`aw.setLaunchPreferences({ theme: <实际应用的 ThemeId>, intro: <是否播放> })`，main 写入 `<userData>/launch.json`；下次启动时 main 读它，决定窗口底色、动画页的主题与是否播放。设置仍只有一处定义（后端设置），`launch.json` 只是给下次启动的副本。

- 首次启动（还没有 `launch.json`）：按系统外观选主题（`nativeTheme.shouldUseDarkColors` → `SYSTEM_THEME_MAP`，与「跟随系统」相同），播放动画。
- `launch.json` 读不出或格式不对：按首次启动处理（这是给定义好的恢复路径，有单测；它只影响一帧的颜色，不值得让应用启动失败）。

### 5.4 什么时候播放

- **只在应用启动时**（冷启动）播放。窗口内刷新、开发模式的热更新、浏览器开发模式与浏览器 E2E 都没有 Electron 的动画页，不会出现（J25 不受影响）。
- `prefers-reduced-motion: reduce`：不播放动画，静态显示最后一帧直到后端就绪，没有最短时间。
- 设置「外观 → 打开动画」（`ui.introAnimation`，布尔，默认开，简单模式）：关掉后与 reduced-motion 相同（静态一帧直到就绪），下次启动生效。
- Electron E2E（J10、J15）照常等待应用页面出现；J15 另断言先出现动画页、随后出现引导页。

代价：main 的启动顺序改动（先开窗口、后端并行）、新增动画页入口与它的 preload、`launch.json` 与一个 preload 方法、一个设置项；Electron E2E 的启动等待随之调整。

## 7. 实现结构

| 位置 | 内容 |
| --- | --- |
| `web/src/features/home/` | `home.page.tsx`（空闲 / 对话中、建议、最近对话）、`home-composer.tsx`（两种模式的输入框与「直接开始」）、`use-start-task.ts`（原表单的 `tasks.create`）、`more-options.tsx`（专业模式的更多选项）、`work-overview.tsx`（空闲时下方的工作概览与 `useWork`）、`work-rail.tsx`（对话中的工作概览栏）；原 `start-task-form.tsx` 与助手条 `home-assistant-entry.tsx` 删除 |
| `web/src/components/workflow-mark.tsx`、`web/src/brand/mark.ts` | 标语与三个节点，主页与动画页共用的几何 |
| `web/src/features/assistant/` | `handoff.ts`：规则 `panelFollowsUser`、外壳里的 `useAssistantHandoff`（离开 / 回到主页）、`followAssistant`（助手带用户离开：打开面板，从主页离开时经视图过渡）；`use-ask.ts` 在主页上把对话放进地址而不是打开面板；面板在主页上不显示 |
| `web/src/splash/splash-page.ts`（`@aw/web/splash`） | 动画页：纯函数 `splashHtml({ theme, intro })` 生成自包含的 HTML（主题令牌、标语、关键帧、跳过与 `window.splash`），`splashBackground` 给窗口底色 |
| `desktop/src/main/` | `index.ts` 先开窗口（令牌由 main 生成）、以 `data:` URL 显示动画页、并行启动后端，经 `executeJavaScript` 等 `window.splash.done`、`leave()`，失败时 `fail()`；`launch.ts` 读写 `launch.json`；preload `setLaunchPreferences` |
| `shared` | `AssistantPage` 加 `batches`、`batch`、`schedules`、`schedule`、`environment`（参数 `batchId`、`scheduleId`）；设置 `ui.introAnimation`；`launchPreferencesSchema`、`AwBridge.setLaunchPreferences` |

与设计稿的出入：动画页不是 web 的第二个 Vite 入口，而是 main 加载的 `data:` 页面。渲染进程的资源路径是绝对的（`base: '/'`，23 §6.1），以文件加载的页面找不到它们；`data:` 页面自包含，main 用 `executeJavaScript` 等待它的 Promise，也就不需要专门的 preload。专业模式的自定义流程直接排在内置流程之后，没有「更多」下拉。
