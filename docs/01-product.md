# 01 · 产品定义与 v1.0 交付范围

## 1. 一句话

**选项目 → 选流程 → 写需求 → AI 在独立分支里做完 → 你看结果、点合并。**

用户不需要理解规划、工作区、节点、尝试这些内部概念；想深入的专业用户可以打开专业模式，自己编排流程、编辑计划、设置验收与角色。

## 2. 设计原则

1. **默认简单，专业可选**。同一套引擎，两层界面。简单模式 = 所有检查点取默认值、界面只呈现结果与必要打扰。
2. **界面复杂度与自动化程度分开控制**：
   - **专业模式开关**（全局，默认关）只决定界面显示多少；
   - **检查点**（流程配置 + 任务启动时可覆盖）决定流程在哪里停下等人。
3. **只在必须时打扰**：AI 的阻塞性提问、opencode 权限请求、失败、等待合并。全部汇总到「需要你处理」。
4. **合并永远由人点**。这是全自动执行的唯一安全底线，不提供自动合并。
5. **AI 遇到不确定时默认做合理假设并在结果中写明**；用户可在设置或启动任务时改为「停下来问我」。
6. **每个任务独立分支 + 独立 worktree**，多个任务可并发，互不干扰，不碰用户主工作区。
7. **状态少而明确**：用户只看到「排队 / 规划中 / 执行中 / 需要你处理 / 待合并 / 已完成 / 失败 / 已取消」这一级别的状态，没有「回执未知 / 待核对 / 修订号」。

## 3. 两种模式

### 3.1 简单模式（默认）

| 环节 | 用户看到的 | 后台发生的 |
| --- | --- | --- |
| 开始 | 主页：选项目、选流程卡片、输入需求、一个可选勾选「运行前让我确认计划」、点开始 | 创建任务 → 建分支与 worktree → AI 规划（或套用固定流程）→ 自动确认 |
| 执行 | 任务页：只读进度画布，节点依次亮起；顶部一行当前进展 | 调度器按依赖派发节点，每个节点一次 opencode 会话；自动验收（测试命令 / AI 评审） |
| 打扰 | 「需要你处理」：AI 提问（选项 + 自由回答）、权限请求（允许一次 / 总是允许 / 拒绝）、失败（重试 / 放弃） | 节点停在等待状态，回答后继续同一会话 |
| 查看 | 点任一节点：产出摘要、改了哪些文件、diff、会话回放 | — |
| 结束 | 结果卡：改动摘要、测试结果、diff；按钮「合并到 main」「创建 PR」「让 AI 再改改」「放弃」 | 合并 / 推送 + 建 PR/MR / 追加修改节点 / 清理 |

菜单：主页、任务、项目、设置；「需要你处理」以徽标形式出现在顶栏和主页。

### 3.2 专业模式（设置中开启）

在简单模式之上额外开放：

- 计划画布编辑：增删节点、改依赖、改角色与指令、改验收方式；确认后才执行。
- 执行中暂停 → 调整待执行节点 → 继续；单节点重跑、跳过、人工验收。
- 流程编排器：自定义流程（固定 DAG 或 AI 规划 + 约束）、检查点默认值、验收方式。
- 角色管理：提示词、模型、权限基线。
- Git 工作台：仓库浏览、分支、提交与 diff、worktree 总览、合并策略（merge / squash / rebase）、冲突处理。
- 系统页：运行环境（opencode 托管状态、日志、重启）、MCP 工具清单、数据库连接。
- 任务页「显示详细信息」：临时以专业视图查看单个任务（简单模式下也可用，不改变全局设置）。

### 3.3 命令面板（v1.0）与应用助手（v1.1）

- **命令面板 ⌘K（v1.0）**：搜索并直接执行应用操作（跳转页面、打开任务、开始任务、切主题、切模式等），来自操作清单。
- **应用助手（v1.1）**：全局侧边面板（⌘J）+ 主页顶部输入框。用自然语言让助手调用应用各项功能（项目、任务、流程、数据库、Git，以后的知识库与 PPT），或完成简单工作（查日期、生成文档）。写操作在对话中弹出确认卡片，可对单个操作设为「总是允许」；合并、取消、删除每次都要确认；密码与令牌只在表单中输入，不经过对话。详见 [15-assistant.md](15-assistant.md)。

## 4. v1.0 交付范围

### 4.1 包含

| 功能域 | 简单模式 | 专业模式 |
| --- | --- | --- |
| 首次启动引导 | 检测 Git、opencode 1.19.0、opencode 模型登录状态，给出修复指引 | 同左 |
| 项目 | 添加本地 Git 仓库、绑定 GitHub/GitLab 远端与令牌 | 关联数据库连接 |
| 流程 | 5 个内置流程（新功能 / 修 Bug / 补单测 / 代码审查 / 重构） | 自定义流程、编辑检查点与验收 |
| 任务 | 创建、进度画布、节点详情（精简）、结果卡、让 AI 再改改、取消、重试 | 计划编辑、暂停调整、节点重跑/跳过/人工验收、完整节点详情 |
| 需要你处理 | 提问、权限请求、失败、待合并 | 同左 + 待人工验收 |
| 交付 | 合并到目标分支（默认 squash）、创建 PR/MR、冲突交给 AI 解决 | 选择合并策略、手动处理冲突后继续 |
| Git 工作台 | — | 仓库/分支/提交/diff、worktree 总览与清理 |
| 角色 | 4 个内置角色 | 自定义角色 |
| 数据库 | — | MySQL、PostgreSQL、openGauss / GaussDB、SQL Server、GoldenDB 连接管理（v1.2 起五种），AI 只读查询工具 |
| 系统 | 设置：主题、专业模式、AI 不确定时的行为、并发数 | 运行环境、MCP 工具清单 |
| 主题 | 四套主题一键切换 + 跟随系统 | 同左 |
| 命令面板 | ⌘K 搜索页面、任务与常用操作 | 同左 |
| 平台 | macOS（arm64），.dmg 安装包 | 同左 |

### 4.2 不包含（v1.1 及以后）

后续版本的范围见 [04-project-plan.md §5](04-project-plan.md#5-后续版本路线图d77)：v1.1 为应用助手、知识问答、Windows / Linux、质量与用量、固定模板批量任务；v1.2 为 PR 审查意见回流、定时任务、PPT 制作、更多数据库。不做：对外 MCP、独立恢复工作台、快照评审、历史模板与角色配置归档、大需求分组逐步细化、自动合并。

## 5. v1.0 验收标准

1. 在一台只装了 Git 与 opencode 1.19.0（已登录模型）的 Mac 上，安装 .dmg 后首次启动引导全部通过。
2. 简单模式下，用「新功能开发」流程对一个示例 TS 项目提需求，无需任何中途操作即可到达结果卡；点「合并到 main」后主分支出现一个 squash 提交，worktree 被清理。
3. 同一项目同时运行 3 个任务，各自分支与 worktree 独立，互不阻塞；三个都能分别合并，第二个起若有冲突能交给 AI 解决后再合并。
4. AI 提问、权限请求能在「需要你处理」中回答，回答后任务在原会话继续。
5. 关闭应用时有任务在执行，重新打开后任务继续执行（中断的尝试自动重试一次）。
6. 专业模式下能编辑计划后再执行、暂停后调整待执行节点、自定义一个流程并用它跑通一个任务。
7. MCP 工具返回错误码时，opencode 中的模型能据此修正并再次调用成功（以提交计划的校验错误为例）。
8. 四套主题下全部页面无对比度问题、无横向溢出（1280 宽）。
9. 测试规范要求的单元 / 集成 / E2E 测试全部通过。
