# 26 · 流程画布与流程页重设计

用户手动测试安装包后的反馈（2026-10-22）：

1. 画布不小心滑到别处就彻底回不去了，需要「回到画布中央」与放大、缩小按钮。
2. 节点的文字会超出框。
3. 整体流程界面与画布界面按设计稿重做：通过连线上的 +、− 增删与连接步骤，自动连接、自动排列。

本文是这次重设计的规格，覆盖所有画布（任务进度、计划确认、计划编辑、流程模板）与流程编辑页。决策：D105（画布视图、控件与自动布局）、D106（编辑交互）、D107（流程编辑页以画布为主），用户 2026-10-22 确认按推荐方案实现。

计划与流程的数据模型不变：步骤只有 `dependsOn`，没有坐标；不改 09 的状态机、10 的表结构与 11 的接口（§8）。

## 2. 视图与控件（D105）

### 2.1 控件条

画布左下角一个浮动胶囊（`--float` 底、`--line-2` 边框），所有画布都有：

| 控件 | 行为 |
| --- | --- |
| − | 缩小一级（÷1.2），以画布中心为基准 |
| 百分比 | 当前缩放（如 `83%`）；点击回到 100%，以画布中心为基准 |
| + | 放大一级（×1.2） |
| ⊙ 适应画布 | 回到全图（§2.2），动画 300 ms |
| 小地图 | 开关小地图（右下角，可拖动、点击跳转）；步骤多于 12 个时默认打开（沿用 14 §5） |

缩放范围 0.3–1.5（不变）。按钮为图标按钮，有 `aria-label`（「缩小」「放大」「适应画布」「显示小地图」），到达缩放上下限时对应按钮禁用。

### 2.2 回到全图

「适应画布」把全部步骤与首尾端点放进视野：

- 缩放取「放得下」的值，限制在 0.5–1 之间（原 0.8–1）。1280 宽的窗口去掉侧边导航与右侧面板，画布只有 600–700 px 宽：五个串行步骤约 1500 px，0.8 时只放得下三列，这正是现在第三步被截掉的原因。缩放低于 0.75 时卡片自动换成概览样式（§4.5），0.5 时标题仍约 11 px。
- 0.5 仍放不下时：竖向居中，横向左对齐，让「开始」可见，其余向右平移查看（同设计稿）。
- 首次显示画布时自动适应一次。之后数据变化（状态更新、新增步骤）保持用户的视角；编辑时新增的步骤若在视野外，平移到可见（缩放不变）。
- 画布尺寸变化（窗口缩放、侧栏开合）：用户还没有手动移动过视角时重新适应，否则保持。

### 2.3 平移边界（反馈 1 的根因）

现状平移没有边界，触控板一滑图就离开视野，且没有任何控件能回来。除了「适应画布」按钮，平移本身也限定范围：React Flow 的 `translateExtent` 设为图的外框各向外扩展半个画布（按当前缩放换算），视野最多移到图的边缘，任何时候至少有一部分步骤留在画布上。缩放变化时重新计算范围。

### 2.4 指针与触控板

| 输入 | 行为 |
| --- | --- |
| 拖动空白处 | 平移 |
| 滚轮、触控板双指滑动 | 平移（`panOnScroll`；现状为缩放，是「滑走」的直接原因） |
| ⌘ / Ctrl + 滚轮、触控板捏合 | 以指针为中心缩放 |
| 单击步骤 | 选中（只读画布：侧栏显示摘要；编辑画布：侧栏显示步骤表单） |
| 双击步骤 | 只读画布打开节点详情（14 §3.4）；不缩放 |
| 单击空白 | 取消选中 |

### 2.5 键盘

画布是一个可聚焦的 `section`（`aria-label` 如「计划画布」），步骤卡片是按钮：

| 键 | 焦点在 | 行为 |
| --- | --- | --- |
| Tab / Shift+Tab | 画布内 | 按布局顺序（列从左到右，列内从上到下）在步骤之间移动；聚焦的步骤在视野外时平移到可见 |
| Enter | 步骤 | 只读：打开节点详情；编辑：选中并把焦点移到侧栏标题输入框 |
| Space | 步骤 | 选中 |
| Esc | 画布内 | 取消选中 |
| `+` / `=`、`-`、`0` | 画布内（不在输入框） | 放大、缩小、适应画布 |
| 方向键 | 画布空白（区域本身） | 平移 80 px |
| Delete / Backspace | 编辑画布中的步骤 | 删除并重连（§5.2） |
| ⌘Z / ⇧⌘Z（Windows、Linux 为 Ctrl） | 编辑画布与侧栏（不在输入框） | 撤销 / 重做 |

连线上与步骤上的 + 是可聚焦的按钮（§5.1），焦点样式 `--accent` 2 px 外框。

## 3. 自动布局（D105）

### 3.1 规则

- 方向左→右；步骤不能拖动，位置完全由依赖决定，数据里没有坐标。
- 同一个图总是得到同一个布局（确定性）：结果只取决于步骤顺序与依赖。

### 3.2 算法（`canvas/layout.ts`，纯函数，同步；同一列内的重心排序在 `components/charts/layered-layout.ts`，与助手的流程图共用，35 §5.3）

1. **分列**：最长路径分层。没有依赖的步骤在第 1 列；其他步骤的列 = 依赖中最大的列 + 1。「开始」在第 0 列，「结束」在最后一列之后。
2. **列内排序**：先按计划中的顺序；再用重心法扫三遍：自左向右按上游的平均位置、自右向左按下游的平均位置、再自左向右按上游，相同时保持原顺序（稳定排序）。减少连线交叉。
3. **坐标**：列宽为卡片宽（208 px），列距 56 px，端点胶囊与相邻列的间距 52 px（放得下连线上的 +）；行距 24 px；每列在竖直方向以 0 为中心对齐；端点胶囊在所在列中居中。
4. **连线**：贝塞尔曲线从上游右边中点到下游左边中点。跨多列的依赖不加虚拟节点，可能从中间列步骤的后面穿过（连线在卡片之下）；计划最多 20 个步骤（`PLAN_MAX_NODES`），实际计划多为 2–8 步，可以接受。

布局约 80 行，单测覆盖：分列、列内顺序（交叉减少）、同输入同输出、端点位置。

### 3.3 不再使用 elkjs

| 方案 | 体积 | 许可 | 说明 |
| --- | --- | --- | --- |
| elkjs 0.12.0（现状，D03） | `elk.bundled.js` 1.6 MB，gzip 469 KB | EPL-2.0 或 GPL-3.0 | renderer 里最大的单个依赖；异步计算，结果晚于渲染，需要 `use-graph-layout` 丢弃过期结果，节点先在原点再跳到位置；GWT 编译产物，出问题无法调试 |
| @dagrejs/dagre 3.1.1 | `dagre.min.js` 49 KB，gzip 17 KB | MIT | 同步、成熟；仍需要为端点、列内对齐另写代码，能力远超 20 个步骤的需要 |
| 自写（推荐） | 约 80 行 | — | 同步、确定、可单测；与设计稿的分层一致，加重心排序 |

推荐自写，删除 elkjs 依赖（03 §3 依赖清单、D03 标注「布局部分已被 D105 取代」）。

## 4. 节点卡片

### 4.1 尺寸与结构

固定 208×88（布局需要固定尺寸，接近设计稿的 204×100，压低高度让串行计划更容易放下），圆角 14，内边距 10×12，三行，每行一行高：

```
┌──────────────────────────────────┐
│ 🔒 实现分页接口        [● 进行中] │  标题（13.5px / 500）+ 状态徽标
│ [开] 开发工程师  ×2               │  角色头像（首字，角色色）+ 角色名 + 尝试次数（专业视图，>1 时）
│ 正在补分页参数的单测…              │  说明（11.5px，--muted）
└──────────────────────────────────┘
```

- 说明行：有当前进展（`report_progress`）时显示进展；否则在计划与模板画布显示指令的第一行；否则空。
- 角色头像：角色名首字，颜色取 `--role-1`…`--role-6`（按角色 key 散列，同一角色在各画布同色），底色为该色 16% 混合。
- 加锁的步骤（已开始，不能修改）：标题前锁形图标（沿用）。

### 4.2 文字规则（反馈 2 的根因）

现状 `.meta` 中只有最后一个 `span` 设置了单行省略，角色名可以折行；卡片固定高度，折行的文字掉出卡片。规则：

- 三行都是 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`，行内可收缩的元素 `min-width: 0`；状态徽标、尝试次数、锁图标 `flex: none`。
- 不用 `overflow: hidden` 裁掉卡片本身（会裁掉焦点外框与 + 按钮）。
- 完整文字：卡片 `title` 属性为「标题 · 角色 · 说明」全文（系统提示，悬停约 0.5 秒出现）；可聚焦的节点的 `aria-label` 为「标题，状态」；选中后侧栏与节点详情显示全文。
- 宽度估算：标题行去掉徽标约可放 8 个汉字；计划中的标题多为 4–10 个字，超出的省略。

### 4.3 端点胶囊

「开始」与「结束」为 72×32 的胶囊（`--fill-3` 底），不可选中、不可删除。任务已到待合并或已完成时，「结束」胶囊为完成色。编辑画布中它们的连线也有 +：「开始 → 第一步」上插入新的第一步，「末步 → 结束」上在末尾追加（§5.1）。

### 4.4 状态样式

沿用 14 §5 与 `STATUS_TONE`：运行中边框与呼吸光晕，等待你处理为等待色边框，完成为完成色边框，失败为告警色边框；已跳过、已取消为虚线边框、整体 60% 不透明度。选中为 `--accent` 边框加 4 px `--accent-fill` 外圈。

### 4.5 概览样式（缩放低于 75%）

缩放低于 0.75 时，卡片只显示标题（22 px，最多两行，超出省略），角色、说明与状态徽标隐藏，状态改为右上角的色点（边框色不变）；端点胶囊与 +、− 按钮同比放大。这样「适应画布」看全图时仍能读出每一步是什么；放大到 75% 及以上恢复三行卡片。实现为画布根元素上的一个 class（读 React Flow 的缩放），节点组件不变。截图见 `docs/design/26-canvas/*-task.jpg`（概览）与 `*-task-zoom.jpg`（100%）。

## 5. 编辑交互（D106）

编辑操作都是图的纯函数（`canvas/plan-graph-edit.ts`），结果总是无环，不需要再查环。

### 5.1 增加

| 入口 | 操作 | 结果 |
| --- | --- | --- |
| 连线中间的 +（悬停画布时半透明出现，悬停或聚焦时实心） | 插入 `insertBetween(a, b)` | 新步骤 N 依赖 a（a 为「开始」时 N 没有依赖）；b 的依赖中 a 换成 N（b 为「结束」时 N 是新的末步） |
| 步骤右侧的 +（悬停、选中或聚焦步骤时出现）→ 菜单「添加下一步」 | `addAfter(a)` | N 依赖 a；a 原来的下游改为依赖 N（N 插在 a 与它所有下游之间） |
| 同一菜单「添加并行步骤」 | `addParallel(a)` | N 的依赖与 a 相同；a 的下游同时依赖 N（N 与 a 并列、同时开始） |
| 工具条「添加步骤」 | 选中步骤时同「添加下一步」；不可以或没有选中时 `addAtEnd`；两者都会破坏规则（§5.4）时按钮不可用 | N 依赖当前所有末步，成为新的唯一末步 |

新步骤：标题「新步骤」，角色为参照步骤的角色（插入时取 a，a 为「开始」时取 b；流程不允许时取第一个允许的角色），指令为空（校验提示「标题、指令不能为空」）。新步骤自动选中，侧栏标题输入框获得焦点并全选。新步骤在视野外时平移到可见。

### 5.2 删除（−）

入口：选中步骤后按 Delete / Backspace；悬停或选中步骤时右上角的 − 按钮；侧栏「删除步骤」。

`removeAndReconnect(k)`：删除 k；对 k 的每个上游 u 与每个下游 d，若 d 还不（传递地）依赖 u，则让 d 依赖 u。即前后自动相连，且不添加多余的连线。u 先于 k 先于 d，新的依赖不会成环。

删除不弹确认：底部提示「已删除『X』」带「撤销」，⌘Z 同样撤销。

### 5.3 连接与断开

- 不再从圆点拖线（去掉连接把手）：拖线要求精确拖到另一步骤的左侧，触控板上很难操作，且容易拖出环（现状靠拒绝来防）。
- 新增与删除时自动连好（§5.1、§5.2）。其他依赖在侧栏「依赖的步骤」勾选：只列出不会成环的候选（沿用 shared `dependencyCandidates`）。
- 断开：侧栏取消勾选。

### 5.4 加锁的步骤与必经步骤

只显示结果合法的操作，不显示会被拒绝的按钮：

- 暂停调整计划时，已开始的步骤加锁（沿用 `lockedChanges`）。一个 + 或 − 只在它的结果不改动任何加锁步骤时显示。例如：连线 a → b 的 + 要求 b 未加锁；「添加下一步」要求 a 的下游都未加锁；加锁的步骤没有 −。
- AI 规划流程的必经步骤（`requiredSteps` 的 `position`）：结果会新增 `REQUIRED_STEP_ORDER` 问题的操作不显示。例如「整体验证」（last）后面没有 +、「添加下一步」与「添加并行步骤」。
- 判断方式：对每个候选操作算出结果图，跑一遍 `lockedChanges` 与 `validatePlanGraph`，与当前问题比较（`editGuard`）。20 个步骤以内，每次渲染几十次纯函数调用。

### 5.5 撤销与重做

编辑器保存本次编辑的历史，最多 50 步：画布、侧栏表单的每次修改都是一步，连续输入同一个字段算一步。工具条有「撤销」「重做」按钮，快捷键 ⌘Z / ⇧⌘Z（焦点在输入框中时为输入框自己的撤销）。保存或离开编辑后清空。历史是编辑器的界面状态（`canvas/use-history.ts`），由使用编辑器的页面持有：计划编辑为计划图，流程编辑页为整个流程定义（名称、说明、设置与步骤）。

### 5.6 编辑画布的工具条与侧栏

计划编辑（任务页）与流程模板（流程编辑页）用同一个编辑器：

- 画布上方工具条：撤销、重做、添加步骤，右侧为问题数（「没有问题」或「N 个问题」）。问题列表与调用方的按钮（保存 / 取消）在侧栏「校验结果」中，问题可点击定位步骤。流程编辑页的工具条见 §6.3。
- 右侧侧栏（360 px）：选中步骤的表单（沿用 `PlanNodeForm`：标识、标题、角色、指令、依赖、检查），底部「删除步骤」。未选中时显示一句说明：「点选一个步骤修改它；在连线中间点 + 插入步骤，在步骤右侧点 + 添加下一步。」
- 侧栏顶部的步骤下拉框去掉：步骤卡片已可用键盘聚焦与选中（§2.5）。

结构不变（14 §3.3：画布 + 右侧状态面板）。画布高度改为填满视口（扣除页头与底部留白，最小 420 px），不再固定 360 px 起。控件条、端点胶囊、新卡片如上。待确认计划时的只读画布同样有控件。

### 6.2 计划编辑（专业）

「编辑计划」与「调整计划」进入 §5.6 的编辑器，画布与侧栏填满页头以下的区域。已开始的步骤显示锁与状态。

### 6.3 流程编辑页（专业，D107）

以画布为主，替换现在的「表单 + 页底画布」：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ← 流程 / [我的修 Bug      ] 第 3 版   2 处未保存修改  ↶ ↷  [+ 添加步骤] [问题 1] [保存为新版本] │
├──────────────────────────────────────────────────────┬───────────────────┤
│                                                      │ [步骤] [流程设置]  │
│   (开始) ──+── [定位根因] ──+── [修复] ──+── (结束)    │ 选中步骤的表单      │
│                                                      │ …                 │
│ [− 83% + | ⊙ 适应画布 | ▦]                            │ [删除步骤]         │
└──────────────────────────────────────────────────────┴───────────────────┘
```

- 顶部工具条代替页头：返回、名称（直接编辑的输入框）、版本徽标（内置流程为「内置 · 只读」）、未保存修改数、撤销、重做、添加步骤、问题数、「保存为新版本」（没有修改或有问题时不可用）。内置流程不显示编辑按钮，只说明「内置流程只读。复制后可以修改。」（复制在流程列表中），侧栏只有只读的流程设置。
- 侧栏两个页签：
  - **步骤**：选中步骤的表单（同 §5.6）。
  - **流程设置**：说明、允许的角色、默认检查点、步骤的默认检查、规划方式与产出（只读说明）、版本列表；AI 规划的流程另有规划者角色与规划指引。
- **固定流程**：画布编辑模板（同计划编辑器）。
- **AI 规划的流程**：画布显示流程的「形状」：开始 → `first` 必经步骤 → 虚线占位卡「AI 规划的步骤」（说明「运行时由规划者按需求拆分」，不可选中）→ `last` 必经步骤 → 结束。没有位置要求的必经步骤与占位卡并列在同一列。必经步骤可点选，在「步骤」页签编辑（标识、位置（最先 / 最后 / 不限）、标题、角色、指令、检查）；最先与最后的必经步骤各至多一个（两个最先的步骤都要排在对方之前，没有计划能满足；`validateWorkflowDefinition` 报 `REQUIRED_STEP_ORDER`）：还没有最先的步骤时，「开始 → AI 规划的步骤」连线上的 + 新增它，还没有最后的步骤时，「AI 规划的步骤 → 结束」上的 + 新增它，已有时不显示这两个 +，位置下拉框中已被占用的选项不可选；工具条「添加步骤」新增不限位置的必经步骤，− 删除。数组按「最先、不限、最后」分组保存。数据仍是 `requiredSteps` 数组，结构不变（`features/workflows/required-steps.ts`）。

## 7. 动画

全部用 CSS（`transform`、`opacity`、`stroke`），不新增依赖；`prefers-reduced-motion: reduce` 时循环动画停止、过渡时长为 0。

| 场景 | 动画 |
| --- | --- |
| 步骤状态变化 | 边框色与光晕 400 ms 过渡（沿用）；状态徽标淡入 150 ms |
| 运行中 | 卡片呼吸光晕（沿用）；通往运行中步骤的连线为 `--run` 色流动虚线（`stroke-dashoffset` 循环 1.2 s） |
| 步骤完成 | 它的出线由虚线变为 `--ok` 实线，颜色 650 ms 过渡 |
| 步骤失败 | 通往它的连线为 `--danger` 色 |
| 新增步骤 | 新卡片从 92% 放大并淡入，180 ms；其他步骤平滑移到新位置（节点 `transform` 240 ms 过渡，`--ease`） |
| 删除步骤 | 其余步骤平滑移到新位置（同上） |
| 适应画布、平移到某步骤 | 视角 300 ms 过渡 |
| + / − 按钮 | 出现时从 80% 放大淡入，150 ms |

## 8. 数据模型与接口

- 计划图 `PlanGraph` 与流程定义 `WorkflowDefinition` 不变，没有坐标、没有端点节点；端点、占位卡只在画布上生成。
- 不改状态机（09）、表结构（10）、接口（11）。编辑操作只是前端对图的变换，保存走现有的「保存计划草稿 / 保存流程」，后端仍用 `validatePlanGraph` / `validateWorkflowDefinition` 校验。
- 新增的用户可见文案放在 `web/src/copy/plan-editor.ts` 与 `copy/workflows.ts`。
