# 04 · 项目计划

## 1. 目标

交付 [01-product.md §5](01-product.md#5-v10-验收标准) 定义的 v1.0：macOS 桌面应用，简单模式完整可用，专业模式核心能力可用。

## 2. 里程碑

工期按 1 名开发者 + AI 编码助手估算，单位为工作周。每个里程碑结束时有可运行、可演示的产物，并通过该里程碑的测试。

| 里程碑 | 内容 | 工期 | 累计 | 可演示产物 |
| --- | --- | --- | --- | --- |
| **M0 工程骨架与技术验证** | monorepo、构建、lint、测试框架、CI 脚本；7 项技术验证 S1–S7 | 1 | 1 | 空壳应用能启动；验证结论写入 02-decisions |
| **M1 基础层** | shared（枚举、错误码、状态机、契约、操作清单）；后端 core（db、迁移、事件、错误、HTTP、SSE、操作清单挂载）；Electron 壳 + utilityProcess；前端框架（路由、导航、主题、API 客户端）；设置；项目；首次启动引导 | 1.5 | 2.5 | 引导页检测环境、添加项目、切换四套主题与模式 |
| **M2 opencode 托管与 MCP** | opencode 运行时托管与崩溃恢复；配置注入；bridge 插件；MCP 服务与工具注册表；尝试生命周期；会话流 JSONL 与 SSE | 1.5 | 4 | 运行环境页显示 opencode 状态；调试入口发起一个尝试，能看到实时会话流并收到 `submit_result` |
| **M3 任务主链路（简单模式）** | 内置流程与角色；任务创建 → worktree → 规划 → 自动确认 → 调度 → 节点执行 → 验收（命令 / AI 评审）→ 结果卡；提问与权限审批；失败与重试；重启恢复；简单模式主页、任务页、节点抽屉、需要你处理 | 2 | 6 | 简单模式从输入需求到结果卡全程跑通；3 个任务并发 |
| **M4 交付与 Git** | diff 展示；本地合并（squash/merge/rebase）；冲突交给 AI 解决；GitHub/GitLab PR/MR；worktree 清理；Git 管理台（仓库浏览、分支、提交、diff、worktree 总览） | 1.5 | 7.5 | 合并到 main / 创建 PR；冲突由 AI 解决后再合并 |
| **M5 专业模式** | 计划编辑画布；检查点；暂停调整；节点重跑/跳过/人工验收；流程编排器；角色管理；完整节点详情；数据库连接 + DB MCP 工具；MCP 工具页；运行环境日志；⌘K 命令面板 | 2 | 9.5 | 自定义流程跑通；暂停调整后继续；AI 查询数据库 |
| **M6 打磨与发布** | 四主题走查；性能（20 节点计划、长会话流、10 个并发任务）；错误文案；打包 .dmg；E2E 全集；live 测试；文档收尾 | 1 | 10.5 | v1.0 安装包与验收报告 |

关键路径：M0 → M1 → M2 → M3 → M4 → M6。M5 依赖 M3，可与 M4 部分并行。

## 3. 每个里程碑的完成定义

1. 该里程碑在 [05-dev-plan.md](05-dev-plan.md) 中的任务全部完成并满足各自完成标准。
2. `pnpm check`（类型 + lint + 依赖边界）、`pnpm test`、`pnpm test:int` 全部通过；涉及界面的里程碑 `pnpm e2e` 通过。
3. 涉及的文档（枚举、状态机、API、MCP、数据模型）与代码一致。
4. 有一段可演示的操作路径（写在里程碑 PR 描述中）。

## 4. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| MCP 调用无法通过插件拿到 sessionID（S1） | 工具归属方案 | 改用 `attempt_token` 参数（已设计备选），M0 内定案 |
| Electron 44 内 `node:sqlite` 不可用或不稳定（S2） | 存储驱动 | 改用 better-sqlite3 + electron-builder 重编译 |
| opencode 1.19.0 接口与 SDK 类型有出入（S3–S5） | 适配层 | 以实测为准，在 `modules/opencode/client` 内封装，记录差异 |
| 模型不稳定调用 submit_* 工具 | 简单模式成功率 | 首条消息与 nudge 提示词迭代；live 测试统计成功率；必要时把关键约束写进 agent 基础提示词 |
| 内置流程质量不足 | 产品价值 | M3 起每周用 2 个真实仓库跑 5 个内置流程，问题回灌提示词 |
| 并发 Git 操作锁冲突（S6） | 并发任务 | 每仓库互斥锁串行化改 refs 的操作 |
| 用户自己的 opencode 全局配置与注入配置冲突 | 行为不可预期 | 注入配置覆盖同名键；环境页展示生效的 agent 与 MCP；问题时提供「纯净模式」（`--pure` 不加载外部插件，S3 验证） |

### 5.2 v1.2（原 v1.2 与 v1.3 合并）

只做以下四项：

1. **PR 审查意见回流**：PR/MR 上的审查意见可一键「让 AI 再改改」，修改推送回同一 PR。
2. **定时任务**：按计划自动运行流程（如每晚补单测、每周依赖检查），结果进入「需要你处理」等待确认；合并仍需用户点击（D16）。设计见 [22-scheduled-tasks.md](22-scheduled-tasks.md)（D90–D92）。
3. **PPT 制作**：设计稿 `ppt*.html` 为参考，开发前先写设计文档。
4. **更多数据库**：PostgreSQL、openGauss / GaussDB（复用 PostgreSQL 驱动）、SQL Server、GoldenDB（MySQL 协议，复用 mysql2，作为独立类型列出），均在 `DbDriver` 扩展点下实现，保持只读（D07）。

### 5.3 明确不做

- 对外 MCP（供 Claude Desktop / Cursor 等外部工具调用）：应用助手已通过助手 MCP 使用全部操作，无外部需求；操作清单保留扩展能力。
- 独立恢复工作台、快照评审、历史模板与角色配置归档。
- 多人协作、云端同步（与本地桌面应用定位冲突）。
- 自动合并（D16）。

v1.0 为助手预留的地基（操作清单、风险与凭据字段标注、`/mcp/exec` 路径、⌘J 保留）计入 M1 与 M5，工期不变。
