# 42 · 任务归档与删除

> 状态：**已实现，待用户检查**（2026-10-28，用户要求：「现在没有任务的归档和删除功能，我想在下个版本加上这个」）。决策 D218–D224 同日按推荐方案确认（02），任务拆分见 05 的 TA 系列。§3 的现状来自读代码（2026-10-28 的 main）。

## 1. 为什么要有

- 任务页（14 §3.7）只能按项目与显示状态筛选。用久了，已完成、已取消的任务远多于进行中的，列表越来越长。
- 想删掉一个任务（试用时建的、建错的、测试用的），现在只能连同整个项目一起删（10 §5）。
- 存储空间面板（37）只清理会话记录，任务本身一直留着。

## 2. 范围

做：

- 归档、取消归档单个任务；已归档的任务默认不在任务列表里。
- 「归档已结束的任务」：把当前筛选范围内所有已结束的任务一次归档。
- 删除单个已结束的任务，连同它在应用里的记录与文件。
- 助手可以归档、取消归档与删除（按 15 §4 的风险确认）。
- 简单模式与专业模式都有。

不做：

- 自动归档（例如完成 30 天后）、定时清理。
- 多选批量删除、回收站、撤销删除。
- 删除 Git 里的东西：任务分支、提交、远端 PR 一律不动。
- 归档或删除批量任务、需求计划、定时任务本身，只针对任务。

## 3. 现状

| 方面 | 现在 |
| --- | --- |
| 结束的任务 | 状态机里 `completed` 与 `cancelled` 是终态（`isTerminalState`；`completed` 可以经 PR 审查意见回流重新打开，仍算终态，21 §7）；`failed` 不是终态，可以重试或放弃 |
| 删除项目 | `tasks.actions.ts` 的 `deleteProject`：要求项目的任务都已结束（否则 `PROJECT_HAS_ACTIVE_TASKS`），释放任务的附件，删任务行（外键级联），再删 `runs/<taskId>/` |
| 引用任务的表 | 级联删除：`nodes`、`attempts`、`plans`、`requirements` 两张表、`deliveries`、`worktrees`、`inbox_items`、`task_events`（时间线）、`batch_items`、`assistant_task_followups`。置空：`schedule_runs.task_id`、`initiative_items.task_id` |
| 文件 | `runs/<taskId>/`（会话流、截图、预览日志）；附件 `attachments/`（任务输入与反馈）；工作区在任务合并或放弃后已删除，残留的（`error`）在 Git 工作台处理 |
| 任务编号 | `tasks.repo.ts` 的 `insert` 取 `max(seq) + 1`：删掉编号最大的任务后，新任务会**复用**这个编号，新分支 `aw/T-n-…` 可能与留下的旧分支、已合并 PR 里的名字撞上。删除项目今天就会触发 |
| 统计 | 质量与用量（19）按 `attempts` 统计；任务被删，`attempts` 跟着删，统计随之变少。团队页（33）按 Git 提交统计，不受影响 |
| 需求计划 | 工作包的 `task_id` 置空后，工作包回到「没有任务」，交付信息（`lastDelivery`）也没了 |

## 4. 决策

| 编号 | 问题 | 推荐 | 备选 |
| --- | --- | --- | --- |
| D218 | 归档怎么表示 | 任务加 `archived_at`（时间戳，未归档为 null），**不是状态**，不经状态机：归档与任务做到哪一步无关，取消归档要能回到原状态。只有已结束（终态：已完成、已取消）的任务能归档；取消归档随时可以。归档不改动其他任何东西（分支、PR、统计、时间线） | 加 `archived` 状态：要给每个终态加进出事件，取消归档还得记住原状态 |
| D219 | 已归档的任务在哪里出现 | 任务列表默认不含已归档的，筛选里加「已归档」只看它们；其他地方照常（任务页能打开，带「已归档」标记与「取消归档」；批量任务、需求计划、定时任务的记录里照常列出）；统计照常计入。已完成的任务从 PR 审查意见回流重新打开时（`reviseFromReview`）自动取消归档 | 归档后到处隐藏：批量与需求计划的进度会对不上 |
| D220 | 「归档已结束的任务」的范围 | 任务页按当前选中的项目（未选即全部项目）把已结束且未归档的任务全部归档，确认框写数量。不提供按天数筛选 | 加「结束超过 N 天」：多一个输入，简单模式下用处不大 |
| D221 | 哪些任务能删、删什么 | 已结束的任务都能删（不要求先归档），每次都确认（`critical`）。删除：任务行与级联的记录、`runs/<taskId>/`、任务的附件、残留的工作区目录（不删分支）。保留：分支、提交、PR。确认框写明「会话记录与用量统计里的这部分数据一起删除，分支和 PR 不受影响」 | 只能删已归档的（先归档再删，多一步但不易误删）；删除时保留 `attempts`（`task_id` 置空）让统计不变，代价是统计查询都要处理没有任务的尝试 |
| D222 | 属于批量任务或需求计划的任务 | **不能删**（`TASK_IN_USE`，`details` 给出批次或需求计划），只能归档：删了批次的条目跟着消失、进度数字变；需求计划的工作包会回到「没有任务」并丢掉交付信息。定时任务产生的任务可以删，运行记录显示「任务已删除」 | 允许删除，批次与需求计划显示「任务已删除」：两处都要改展示与进度计算 |
| D223 | 任务编号复用 | 编号永不复用：新表 `app_counters(name, value)`，`task_seq` 由迁移按现有 `max(seq)` 初始化，建任务时在同一事务里加一。删除项目的复用问题一并解决 | 维持 `max(seq) + 1`，删除时提示：撞名要靠运气避开 |
| D224 | 助手与命令面板 | 加 `tasks.archive`、`tasks.unarchive`、`tasks.archiveFinished`（`write`）与 `tasks.delete`（`critical`），都对助手开放，按 15 §4 出确认卡片；命令面板只开放归档与取消归档 | 删除不对助手开放：用户说「把那个任务删了」时助手只能打开任务页 |

## 5. 数据与接口

表（10）：

- `tasks.archived_at`：integer，可空；索引 `(archived_at)`。
- `app_counters`：`name` text 主键、`value` integer；迁移写入 `('task_seq', coalesce(max(tasks.seq), 0))`。

API（11）：

| 操作 | HTTP | 风险 | 说明 |
| --- | --- | --- | --- |
| `tasks.archive` | `POST /tasks/:id/archive` | write | 未结束时 `TASK_NOT_FINISHED`；已归档时原样返回 |
| `tasks.unarchive` | `POST /tasks/:id/unarchive` | write | 未归档时原样返回 |
| `tasks.archiveFinished` | `POST /tasks/archive-finished { projectId? }` | write | 返回归档的数量 |
| `tasks.delete` | `DELETE /tasks/:id` | critical | 未结束 `TASK_NOT_FINISHED`；在批次或需求计划里 `TASK_IN_USE` |
| `tasks.list` | 现有 | read | 查询加 `archived`（默认 false：只要未归档的；true：只要已归档的） |

`TaskDTO` 加 `archivedAt`。归档与取消归档发 `task.updated`；删除发新的 `task.deleted { taskId, projectId }`（11 §11），列表与打开着的任务页据此刷新或离开。

错误码（08）：`TASK_NOT_FINISHED`（409）、`TASK_IN_USE`（409，`details` 为 `{ batchId }` 或 `{ initiativeId }`）。

删除的顺序与 `deleteProject` 相同：先在一个事务里释放附件、删任务行（级联），提交后再删 `runs/<taskId>/` 与残留工作区目录；文件删除失败只记日志，不回滚（记录已经没了，残留文件归存储空间面板统计）。

## 6. 界面（14）

- **任务页（详情）**：页头的操作区加「归档」（已结束时）或「取消归档」，以及「删除任务」（已结束时）。**实现出入**：任务详情里没有所属批次或需求计划，按钮不预先禁用；删除时报 `TASK_IN_USE`，确认框里显示「只能归档，不能删除」。已归档的任务在页头显示「已归档 · 10 月 28 日」与「取消归档」。删除确认框写明会删什么、保留什么，确认后回到任务列表。
- **任务列表**：状态筛选的下拉里在各状态之后加「已归档」；选它时列表只列已归档的任务。页头右侧加「归档已结束的任务」（没有可归档的任务时不可用），确认框写「将归档 12 个已结束的任务（项目 todo-web），可随时取消归档」。
- **其他页面**：批量任务、需求计划、定时任务里列出的任务旁显示「已归档」小标记。
- **图标**：新增 `archive`（带盖的盒子）。
- 文案都在 `apps/web/src/copy/`。

## 7. 测试（07）

- 集成：未结束不能归档或删除；归档后列表默认不含、`archived=true` 只含它；取消归档；`archiveFinished` 只动当前项目已结束且未归档的；从 PR 审查意见回流重新打开时自动取消归档；删除后任务、节点、尝试、时间线、附件与 `runs/<taskId>/` 都没了，分支还在；批次与需求计划里的任务 `TASK_IN_USE`；删掉编号最大的任务后新任务不复用编号（删除项目亦然）。
- E2E：在任务页归档、在列表的「已归档」里找到并取消归档；删除一个已取消的任务后回到列表且看不到它。
