四套皮肤 · 颜色迁移图

deepseek 风是新的结构基准：组件、间距、圆角、交互全部来自 ds.css。其他三套皮肤只替换颜色与效果令牌（skins.css），不再各自维护一份页面样式。这张图说明每个令牌在四套皮肤里的取值、旧变量该换成哪个新令牌，以及每套皮肤迁移时改了什么、为什么改。
当前有效皮肤为 deepseek 风 / claude 风 / SPDB / GitHub 白四套。科技蓝已退役，选过科技蓝的用户回落到 deepseek 风。

同一组件，四套皮肤

下面每一列都是真实组件，只在容器上换了 data-skin。用来快速确认：层级关系、选中态、状态色、结果未明的虚线样式在四套皮肤里含义一致。

令牌对照表

按用途分组。半透明令牌铺在该皮肤自己的页面底色上显示。页面代码只引用令牌名，不写颜色值。

旧变量 → 新令牌

原有皮肤用的是两套变量名（页面层 --canvas / --paper … 与基础层 --color-bg-canvas …）。迁移时按这张表做全局替换，左边是旧值，右边是新值。

沿用色值不变，只改名 调整色值有改动，原因见第 5 节 按新值旧变量存在但各皮肤取值不统一，直接用新值 新增旧皮肤里没有对应变量

对比度校验

文字要求 ≥ 4.5:1；状态文字在自己的浅色填充上也要 ≥ 4.5:1（徽标就是这样画的）。品牌色只用于开关、勾选框等非文字图形，按 3:1 要求；如果之后要做“品牌色底 + 白字”的按钮，deepseek 风需要另配更深的按钮色。

各皮肤迁移说明

只列与旧皮肤不同的地方。没提到的令牌都是按原色沿用。

开发接入步骤

01先接结构，再接皮肤

页面全部按 deepseek 风设计稿实现，只引用 ds.css 里的令牌。skins.css 放在 ds.css 之后加载，<html data-skin="…"> 决定当前皮肤，不设时就是 deepseek 风。

02旧变量一次换完

按第 3 节表格全局替换旧变量名。替换完搜索 #、rgb(、rgba(，页面和组件里不应再有写死的颜色（PPT 幻灯片内容本身除外）。

03用组件级令牌代替“白色/黑色”

主按钮文字用 --primary-ink，选中项文字用 --ink-strong，浮层底用 --float，遮罩用 --scrim，画布节点底用 --node-bg，连线用 --edge。这样浅色皮肤不会出现白底白字。

04角色色走 --role-1…6

画布与列表里的角色头像按顺序取 --role-n，每套皮肤已配好与底色对比足够的六色。

05状态色含义不变

执行中=run、停滞=stall、失败=warn、完成=done、待确认=wait、未开始=idle、结果未明=unknown（虚线描边）。四套皮肤只换色值，不换含义，也不换图标。

06验收

每个页面在四套皮肤下各截一张图，对照本页第 1 节检查：选中态可辨、徽标可读、浮层不透底、没有残留深色块。设计稿右下角“皮肤”下拉可以直接切换预览。
