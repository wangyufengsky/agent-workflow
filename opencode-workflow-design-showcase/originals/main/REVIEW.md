# opencode-workflow · deepseek 风 逐页审查与改造说明

> 交给 codex 的开发依据。原型在 `pages/*.html`，设计系统在 `assets/ds.css`，外壳与通用组件在 `assets/shell.js`。
> 原型是纯静态 HTML + 原生 JS，只用来表达结构、层级、交互和状态；生产实现继续用现有 Foundation + AntD，
> 不要把原型代码直接搬进生产。

## 0. 怎么用这份设计稿

1. **deepseek 是第 5 套皮肤，也是新的结构基准。** 先按本稿把页面结构、组件形态和交互做成 deepseek 皮肤；
   另外三套皮肤（warm / spdb / github-white；科技蓝已退役）**结构完全跟随**，只替换 `:root` 令牌。
2. **令牌映射**：`ds.css` 第 1 节的每个令牌都要在四套皮肤里各给一个值。不要在页面代码里写死颜色。
3. **业务规则不变**：冻结身份、UNKNOWN 只读回读、草稿与执行分离、抽屉宽度（400 / 480 / 520 / 600）、
   210 导航、56 页头、36 控件、40 表单，全部保留。本稿改的是信息层级、布局和交互路径。
4. **接口标注**：每页末尾的“接口”一节标注 `SOURCE_EXISTING`（已有接口，直接用）或 `PROPOSED`（本稿建议、需后端评审）。
   PROPOSED 项没评审通过前，前端用降级方案（见各页说明），不要伪造数据。

## 1. 全局设计系统（ds.css）

| 类别 | 规则 |
|---|---|
| 底色层级 | `--bg #0a0a0a` → `--surface` → `--panel` → `--raised` → `--overlay`；卡片用 `--fill-1`（2% 白）+ `--line`（7% 白）描边 |
| 文字 | `--ink` 主文、`--ink-2` 正文、`--sub` 次要、`--muted` 说明；都是实色，对比度 ≥ 4.5 |
| 标题 | 页面标题 Montserrat 500 / 26px / 字距 -0.5；区块标题 15px / 500；不用粗黑体 |
| 按钮 | 全部胶囊。主按钮白底黑字（每屏最多一个）；次按钮 6% 白底 + 12% 白描边；危险按钮红字红描边，不铺红底 |
| 控件 | 搜索框、筛选用 36px 胶囊；表单输入 40px / 圆角 10；聚焦为品牌蓝 3px 光圈 |
| 卡片 | 圆角 16；可点卡片整卡可点，悬停加亮；卡片内不再套灰底大框 |
| 状态 | 执行中绿、停滞红、失败琥珀、完成青、等待紫、待执行灰；**结果未明 = 琥珀色虚线框 + 问号图标**，全站统一 |
| 状态表达 | 必须“图标 + 文字 + 颜色”三者同时出现，不能只靠颜色 |
| 抽屉 | 右侧滑出，宽 400 / 480 / 520 / 600；头部标题 + 关闭，底部固定操作区；Esc 关闭并把焦点还给触发按钮 |
| 侧栏 | 玻璃渐变底；“开始任务”提升为侧栏顶部主按钮；待处理中心显示数量；底部常驻运行环境状态 |
| 页头 | 只放面包屑 / 页名 + 本页主操作。**设计审阅控件（状态、版本、皮肤切换）不进产品页头** |
| 动效 | 进入 0.45s 上浮淡入；抽屉 0.45s；状态色 0.65s 渐变；`prefers-reduced-motion` 下全部关闭 |

## 2. 外壳（shell.js）

- 15 个主导航保留，顺序：工作区（主页、项目、知识库、PPT）→ 规划与执行（流程、任务列表、待处理中心、质量与用量、模板任务）→ 系统（运行环境、工具与 Skill、数据库、角色管理、设置）。
- “开始任务”从导航列表移到侧栏顶部，做成主按钮（路由不变 `/requirements/new`）。
- 侧栏底部：运行环境状态芯片（绿点 = 已连接，琥珀 = 部分可用，红 = 断开），点击进入运行环境。
- 皮肤切换移到“设置 → 外观”；页头不再放皮肤下拉框。

## 3. 主页 `pages/home.html`

**定位**：展示页。介绍 opencode-workflow 是什么、怎么工作，并把人引到“开始任务”和“项目”。**不放可直接执行的输入框，不读取业务数据**（与原主页合同一致：零新增业务请求）。

**原设计的问题**
- 首屏只有标语和一张流程图，看完不知道 opencode-workflow 能做哪些事。
- 4 个入口卡和上面的演示没有关联，页面像拼起来的。

**改成了**
- **首屏**：小徽标“本地开发工作区” → 标语“Everything is a *Workflow.*”（Workflow. 保留 Georgia 斜体，颜色改为强调蓝）→ 两行说明 → 两个按钮：开始任务（主）、查看项目（次）。
- **产品窗口**：流程演示放进带窗口标题栏的深色面板，作为首屏主视觉。点阵网格底；节点为深色卡 + 状态描边光晕；每个阶段在画布底部配一句说明（例如“编写测试”停滞：缺少数据库读取权限，等待处理）。五阶段 × 2 秒、暂停 / 点阶段停留、页面隐藏时停表、减少动态效果时不自动播放，全部沿用已批准的节奏。
- **能力介绍**：标题“能力不断拓展，工作由你掌握”，四张能力卡（可复用的流程 / 看得见的执行 / 关键决定留给你 / 每个结论都有出处），每张卡下半部是一个小示意（步骤链、状态行、问题单选、带引用的句子），整卡可点到对应页面。下方一行四个小入口（项目、模板任务、PPT、质量与用量）。
- **收尾**：点阵渐隐背景上的“从一个目标开始” + 开始任务按钮。

**状态**：只有正常态；模块加载失败沿用原合同的页面级错误与重试。

**接口**：无。全部为静态展示内容 — DESIGN_ONLY。

## 4. 项目 `pages/projects.html`

**原设计的问题**
- 卡片里的项目目录是一块很大的灰底框，信息被稀释；工作模式、分支、技术栈、任务数权重一样，扫不出重点。
- 工作模式筛选藏在下拉框里，看不到每类有多少。
- “路径不可用”的项目只有一个小标签，不知道怎么办。
- 详情页左侧是 184px 配置索引，概览只是字段罗列，看不出哪些配置还缺。
- 登记是整页表单，名称要手填。

**改成了**
- **列表**：标题 + 一句说明；工具条 = 胶囊搜索 + 分段筛选（全部 / Git 分支 / 直接目录 / 不可用，带数量）+ 刷新图标。
- **卡片**：图标 + 名称（可换行）+ 路径一行（等宽、超长省略、悬停看全）→ 徽标行（工作模式、N 个运行中）→ 两行说明 → 三格事实条（当前分支 / 技术栈 / 任务数）→ 底部“开始任务”“模板任务”+“查看配置 ›”。整卡可点进详情；“⋯”菜单：查看配置 / 复制目录 / 取消管理。
- **路径不可用**：图标换警示，开始任务和模板任务禁用，卡片内直接说明“目录在本机找不到……请取消管理后按新路径重新登记”（没有改路径接口，所以不提供“修改路径”）。
- **详情**：页头 = 图标 + 名称 + 模式徽标 + 路径（可复制）+ 右侧“开始任务”（主）“模板任务”（次）“⋯”（取消管理）。下面四个页签：概览 / Git 与 GitLab / 文档路径 / 项目公约。项目公约未生成时页签带琥珀小圆点。
  - **概览**：左“项目信息 + 最近任务（3 条）”，右“配置状态”清单（Git 账号 / GitLab / 文档路径 / 项目公约，每项带状态徽标，点击跳到对应页签）。
  - **Git 账号**：账号来源改为两张单选卡（继承全局 / 此项目单独配置）；单独配置时显示认证方式分段 + 用户名 + 密钥（已保存时显示“留空则不修改”）。“验证连接”和“保存”分开，验证结果就地显示。
  - **GitLab 与证据**：仓库搜索 + 证据来源行（类型 / 规则 / 删除），计数 x / 16；切类型清空规则、JUnit 不读外部目录的说明写在下面；“检查绑定”在保存前禁用并说明原因。
  - **文档路径**：输入 + 实时显示“实际位置”。
  - **项目公约**：右侧三步时间线（生成草稿 → 审阅差异 → 写入项目）。未生成 → 空态 + “生成公约草稿”；生成中 → 转圈 + 已运行时长 + 停止（二次确认）+ 读取中的文件；草稿就绪 → 差异预览 + “确认写入”；状态未明 → 虚线琥珀提示 + 按原记录重新读取。
- **登记**：480 抽屉。先填目录（或“选择”），名称自动取目录名，可改；文档目录和说明收进“更多（可选）”。按钮下方实时说明还差什么。有未提交内容时关闭要确认。
- **取消管理**：对话框写明项目名、路径、“文件不会被删除或修改”。

**状态**：列表 / 加载 / 读取失败 / 无项目 / 无搜索结果 / 登记抽屉 / 登记结果未明 / 取消管理 / 详情各页签 / 公约四态。

**接口**：全部沿用 D11 合同（SOURCE_EXISTING）。卡片上的“N 个运行中”需要任务数按状态拆分 — **PROPOSED**；未评审前不显示该徽标。最近任务复用任务列表按项目过滤 — SOURCE_EXISTING。

## 5. 开始任务 `pages/start.html`

**原设计的问题**
- 两步向导，第一步只有“选项目 + 写目标”，却要先开 400 抽屉选项目（通常只有两三个项目）。
- 选流程时看不到流程包含哪些步骤。
- 没有地方总结“我将创建什么、之后会发生什么”。

**改成了**
- 一页三段，带编号，顺序为 **项目 → 目标 → 流程**，完成一段编号变成绿色勾：
  1. **项目**：最近 3 个项目直接平铺成单选卡 + “其他项目…”（打开 400 抽屉，可搜索，不可用项目置灰）。
  2. **目标**：选好项目之前，目标框半透明且只读，标题旁提示“先选择项目”；选中项目后标题旁显示“在 某项目 中”，目标框自动获得焦点。大输入框底部内嵌“任务名称”——默认从目标自动生成，改过就以用户为准；显示字数。
  3. **流程**：常用 3 个流程平铺，卡片里显示步骤链（需求讨论 → 规划 → 实施 → 验收）+ “全部流程…”（400 抽屉）。选中后读取当前版本，显示“版本 r12 已核对”；读取失败给出行内错误与重试，不能提交。
- 右侧固定总结卡：将要创建的任务名、项目、流程（含版本）；“接下来”三步（形成需求草稿 → 在需求画布确认计划 → 开始执行）；主按钮“形成需求草稿”，下方实时说明还差什么（先选择项目 / 写下目标 / 还需要选择流程）。
- **结果未明**：整页只读，顶部虚线琥珀提示，“用原请求重试”（同一 requestKey 与请求体）。
- **已形成**：回执卡（任务 / 项目 / 流程版本）+ “去确认计划”；交接失败时标题改为“草稿已形成，但没能自动打开”，按钮“打开原草稿”，不重新创建。
- 从项目卡片或项目详情的“开始任务”进入时，项目已选好，直接从目标开始。

**状态**：空白 / 已填写 / 核对流程版本中 / 流程版本读取失败 / 项目列表读取失败 / 提交中 / 结果未明 / 草稿已形成 / 已形成但打开失败。

**接口**：沿用 D04 合同（SOURCE_EXISTING）。路由参数 `project`（从项目页带入）是纯前端行为 — DESIGN_ONLY。

## 6. 流程目录 `pages/workflows.html`

**原设计的问题**
- 表格只有名称、来源、版本、时间，看不出一个流程包含哪些步骤，选流程靠猜。
- 来源筛选是下拉框，还要再点“搜索”按钮。
- 详情面板里“编辑 / 使用 / 复制 / 归档”四个按钮权重一样。

**改成了**
- 页头右侧“新建流程”（主）。工具条：胶囊搜索（输入即筛选）+ 分段筛选“全部 / 我的流程 / 程序内置”带数量。
- 列表行：图标 + 名称（内置流程带“内置”小标签）+ 一行说明 + 右侧“版本 N · 更新时间 ›”。选中行高亮。
- 右侧 400 详情卡：来源与版本徽标、名称、说明、**步骤链**（编号竖排；并行步骤并排展示，标“并行”）、更新时间与“已用于 N 个任务”。
  主操作“用这个流程开始任务”（带流程进入开始任务页并预选）；次操作“编辑流程”（内置为“查看步骤”）、“复制”；“⋯”里放“归档…”。
- 复制：对话框可改副本名称（120 字以内，空名称就地报错），并写明“将复制版本 N 的步骤定义”。
- 归档：对话框写明不再出现在目录和开始任务里，已有任务不受影响、历史保留。
- 结果未明：顶部虚线琥珀提示 + “用原请求重试”。

**状态**：目录 + 详情 / 未选中 / 内置详情 / 详情读取中 / 目录加载中 / 目录读取失败 / 加载更多失败 / 复制 / 归档 / 复制结果未明。

**接口**：列表、复制、归档沿用 D03 合同（SOURCE_EXISTING）。详情中的步骤链需要读取流程定义 `GET /api/workflows/templates/{id}`（流程画布合同中的 SOURCE_EXISTING 接口），在目录页选中时调用 — **跨页复用，需流程组确认**；读取中显示骨架，失败时只显示名称与说明并给重试。“已用于 N 个任务”没有现成字段 — **PROPOSED**，未评审前隐藏。

## 7. 流程画布 `pages/workflow-editor.html`

**原设计的问题**（用户反馈：画布操作反直觉）
- 打开后是“查看”，要先点“修改流程”进入编辑模式，再点“保存并退出 / 退出编辑”，模式切换让人困惑。
- 节点里职业形象占了大半，步骤名字很小。
- 添加、删除、连接都藏在节点详情的一排按钮里，不知道从哪下手。
- 画布四周是设计审阅条和说明文字，真正的画布只占一半。

**改成了**
- **没有编辑模式**。“我的流程”打开即可修改，所有修改是本地草稿，工具条显示“N 处未保存修改”，点“保存”才提交；内置流程只读，工具条主按钮为“复制后修改”。
- **工具条（替代页头）**：面包屑“流程 /” + 可直接改的流程名 + 来源与版本徽标 + 保存状态 + 撤销 / 重做（⌘Z / ⇧⌘Z）+ 添加步骤 + 检查（带问题数）+ 保存（主）。
- **画布**：铺满剩余空间，点阵底；首次打开自动适应画布（横向主链，图太宽时左对齐让“开始”可见）。左下角缩放条（− 百分比 + / 适应画布）；右上角“N 个步骤 · M 条连线”。
- **节点**：204×100 深色卡：步骤名（14px/500）→ 职业（首字头像 + 名称；未指定职业为琥珀虚线“?”）→ 产出说明。开始 / 交付为小胶囊系统节点，点击说明“可以移动，不能删除”。
- **直接操作**：悬停或选中步骤，右侧出现白色 “+”（添加下一步 / 添加并行步骤 / 从步骤模板选择）；悬停画布时连线中点出现 “+”，在两步之间插入。新步骤自动选中并聚焦名称。
- **首次提示**：左上角可关闭的小卡，四行说明怎么点、怎么加、怎么平移缩放。
- **步骤面板（右 480）**：顶部可改名称；“谁来做”大按钮（点开选职业）→“这一步做什么”→“产出与验收”→“之后”（列出后续步骤；两条以上时说明“普通连线表示并行”；添加下一步 / 添加并行步骤 / 连接到…）→“高级设置”默认收起（输入映射、单步预算、外部写入）。底部：删除这一步（二次确认，前后自动连起来）+ 完成。
- **检查**：右上浮层列出问题（例如“性能检查”未指定职业），每条可“定位”——画布平移到该步骤并选中，缩放不变。保存前自动检查，有问题时不提交。
- **空流程**：开始与交付之间显示“从第一步开始 / 添加第一步”。
- **步骤模板（左 400 抽屉）**：搜索 + 模板列表，点击添加到所选步骤之后。
- **结果未明**：画布只读 + 虚线琥珀提示“用原请求重试”；**版本冲突**：红色提示“已被更新为版本 5”，提供“查看版本 5 / 导出我的修改”，不在原键下改写。

**状态**：已保存 / 有未保存修改 / 有步骤未指定职业 / 新流程空 / 内置只读 / 保存结果未明 / 版本冲突。

**接口**：沿用 D07 合同（SOURCE_EXISTING：read / create / save / layout / validate / profession / instantiate）。布局（节点坐标）仍是 PROPOSED 本地扩展；本稿使用自动分层布局，不依赖坐标持久化。执行相关按钮（执行 / 暂停 / 推进）不出现在流程画布。

## 8. 需求画布 `pages/requirement.html`

**原设计的问题**
- 与流程画布几乎一模一样（同样的“修改计划”按钮），看不出这一页的任务是“确认这次任务的计划”。
- 澄清问题、候选计划、任务设置（模型 / 预算 / 资料）、校验、确认、开始执行分散在不同状态里，没有一条主线。
- “确认计划”和“开始执行”是两个独立动作，但界面没有说明先后关系。

**改成了**
- **工具条**：面包屑“任务列表 /” + 任务名 + 右侧四段进度胶囊：需求草稿 → 澄清与规划 → 确认计划 → 开始执行（当前段白底，完成段绿勾）+ “⋯”（保存为流程… / 查看澄清问答 / 取消这个需求…）。

  - 标题「发布修订 3」+ 绿色「已核对」+「只读」徽标；

**状态**

| id | 含义 |
|---|---|
| `pub-draft` | 草稿视图，顶部带「草稿 / 已发布版本」切换（入口） |
| `pub-view` | 已发布版本回执 |

| `pub-error` | 读取失败，可重试 |
| `pub-dep` | 依赖提示：选中从未发布的「需求分析师」 |

**保留的业务边界**
- 草稿、精确发布修订、实例绑定和运行状态相互独立。读取或核对不发布；保存不生成执行版本。

- 409 时保存禁用，提供「放弃本地修改，读取服务器草稿」。该操作在有本地修改时仍要先过放弃确认。
- 形象上下文只绑定已核对的发布修订，原型不改动形象页签。

**与 React 实现的对应**
- 标题「发布修订 N」对应 `published.revisionNumber`，职业名对应 `published.displayName`。
- 指令文档块对应 `published.baseInstructions`。
- 能力 chip 对应 `published.capabilities`，经 `professionCapabilities` 映射为标签，为空时 React 显示「无声明」。
- 内容摘要对应 `published.contentSha256`。
- 「核对当前发布引用」对应 `owner.head()`。React 中仅在 `s.base` 存在时显示，在 `locked || s.reading` 时禁用。
- 依赖提示对应 `s.publishedDependency`。原型文案是按场景示意的，实际字符串由控制器给出。
- 读取中对应 `s.reading`（「正在读取固定版本…」）。
- 冲突横幅对应 `s.failure.status === 409` 与 `currentVersion`。
- 「核对原操作」对应 CommandNotice 的 `owner.recover()`，按钮文案以语义注册表实际文案为准。
- 放弃确认对应 UiConfirmDialog「放弃未保存配置」（`ui.discardChanges`），按钮文案以语义注册表实际文案为准。

  - 「限制说明」为 info 列表；
  - 「有效工具上限 · N 项」为两列表：左列中文用途，右列等宽工具名；
  - 「诊断」为琥珀 warn 列表；没有诊断时显示一行绿色「没有诊断问题」。
- 无有效工具：空状态说明「空清单不表示不受限制」。
- 目录未登记的职责位置显示为「该发布版本的职责位置（目录未登记）」。

**状态**

| id | 含义 |
|---|---|
| `perm-pv-none` | 未核对发布版本，前置提示 +「查看已发布版本」 |
| `perm-pv-pick` | 待选择职责位置，读取按钮禁用 |
| `perm-pv-loading` | 读取中，下拉禁用，骨架屏 |
| `perm-pv-result` | 预估结果，有限制说明和 4 个工具，无诊断 |
| `perm-pv-notools` | 无有效工具 |
| `perm-pv-diag` | 有诊断：未登记位置、外部服务身份、实例文件/命令授权未计入 |
| `perm-pv-error` | 读取失败，可重试 |

**保留的业务边界**
- 预估不能替代实际会话授权、工具发现或工作区许可，这一点常驻显示。
- 选择页签、选择位置、读取预估都不写入。预估基于原冻结的精确发布修订，只列出该修订允许的职责位置。
- files/commands 无损编辑缺口属于 C 类，这里只在诊断中如实说明“没有计算、保留原样”，不提供编辑。
- 没有新增确认框。

**与 React 实现的对应**

| 原型 | React |
|---|---|
| 「预估职责位置」下拉 | `published.allowedSlots`，标签取 `s.slots[].label`，回退「该发布版本的职责位置」；修改调用 `owner.slot` |
| 「读取预估」 | `owner.preview()`，在 `locked \|\| s.reading \|\| !s.slot` 时禁用 |
| 限制说明 | `s.preview.limitations` |
| 有效工具上限 | `s.preview.preview.effectivePermissions.tools`：用途列为 `roleToolDescription(name)`，工具名列为 `name`；为空时 React 显示「没有有效工具声明。」 |
| 诊断 | `s.preview.preview.diagnostics.diagnostics[].message` |
| 前置提示 | `!published` 时的「请先核对精确发布修订，才能预估该版本的权限。」 |
| 读取中 | `s.reading` |

- 以上文本都经过 `safe()` 处理：非中文内容会被替换为「配置条件尚未满足，请核对原字段后重试。」
- 读取时间是原型示意。DTO 中如果没有时间字段，就只显示位置和修订。
- 卡内的读取失败条在 React 中由页级 `s.error` 或 `s.failure` 显示，建议实现时就近放在本卡内。

## B-05. 需求高级澄清与规划扩展 `pages/requirement.html?state=pl-rounds`

**入口与可见条件**
- 路由 `/requirements/:id`。在需求画布右侧打开 520 的「澄清与规划」面板，取代 360 的计划概览。面板打开时，进度条停在「澄清与规划」。
- 入口：
  - 原型中：页头「更多操作」菜单新增「澄清与规划…」（只在点开菜单时出现，已有状态的外观不变）。
  - React 中：计划概览「查看澄清问题与规划草案」，或工具条「更多操作 → 澄清与规划」。
- 写操作锁定期间面板不能关闭（React 中 `open = visible || owner.locked()`）。

**原实现的问题**
- 一条长纵列铺满所有内容：澄清答案、配置下拉、轮次、工作包、草案和映射，全部是同权重的 h3 + 灰色段落，找不到当前该做什么。
- 状态只有文字：「停止尚未核明」与普通状态看起来一样；工作包「尚未证明完成」只是一句灰字。
- 应用的两个前提（来源轮次已停止、计划版本一致）是两行零散的提示，按钮可用或不可用时没有原因。
- 映射核对把 `target ← source` 原样输出，结果只是一行文字。
- 冲突、接口缺失、读取失败都用同一种告警块，彼此之间以及与正文之间都缺少层级。

**改成了**
- **面板骨架**
  - 页头为「需求计划 · 修订 N」+「澄清与规划」，带刷新和关闭按钮。
  - 页头下方是分区导航「答案 · 配置 · 轮次 · 工作包 · 草案」，带数量；有待核对的轮次时显示琥珀点；滚动时自动高亮当前分区。
  - 面板级状态条固定在导航下方、不随内容滚动：停止未核明（虚线琥珀）、接口未提供、已应用。
  - 底部固定说明：保存答案、生成草案、应用草案、确认计划、开始执行是五个独立操作。
- **A 区保持紧凑**
  - 澄清答案压成一张卡：问题数和必答数、答案修订、问题来源修订，以及「查看与修改答案」（跳到原有的 questions 稿）。
  - 草案列表只保留一行一个草案。
- **(a) 规划配置**
  - 两行冻结卡：任务模板、职业，各带「发布 N」，并加「生成时冻结」徽标。
  - 「更换」展开两个下拉（只列出已发布版本），附「加载更多模板」，以及核对结果「已核对：模板发布 7，推荐职业发布 4」。
  - 未选配置时给出说明，并提供「选择规划配置」。
  - 「生成规划草案」放在配置下方，禁用时紧挨按钮说明原因：先选择规划配置 / 停止结果尚未核明 / 正在停止。
- **(b) 规划轮次**
  - 手风琴列表，每行「第 N 轮」+「基于计划修订 · 时间」+ 状态徽标。八种状态各有图标和颜色，STOP_UNKNOWN 用虚线琥珀，STOPPING 用转圈。
  - 展开后依次显示：
    - 本轮输入胶囊：答案修订、模板 · 发布、职业 · 发布；
    - 失败原因；
    - 本轮问答快照，未回答的显示「尚未回答」；
    - 操作「沿用本轮配置」，以及可停止状态下的「停止本轮规划」；STOP_UNKNOWN 时改为「核对原轮次」。
- **(c) 工作包**
  - 列表：标题、步骤数、目标，以及「已证明完成 / 未证明完成」徽标。说明：完成以服务端证明为准。
  - 点进详情（面板内下钻，可返回），内容依次为：
    - 目标；
    - 步骤：每步可在画布上定位，执行中会显示步骤状态；
    - 前置工作包胶囊；
    - 验收条件；
    - 完成证明：「N 份冻结产出合同 · N 份证明」。每份制品一行，含短 ID、来源计划修订、第几次尝试、「验收与停止引用齐全」。
  - 没有证明时，用琥珀提示直说「不能认定这个工作包已完成，即使其中的步骤显示执行中或已完成」。
  - 底部注明只读。
- **(d) 输入映射核对**（在草案详情里）
  - 每个步骤一张卡：结果徽标（未核对 / 核对中 / 一致 / 不一致 / 无法核对）+「核对」按钮。
  - 每行显示「目标输入 ← 来源步骤 · 产出项」。整对象映射显示为「整个输入」和「全部产出」。
  - 结果文案写在卡内。合同不完整时按钮禁用，并给出琥珀说明。
- **(e) 应用 / 退回**
  - 「应用前检查」清单有两项，「来源轮次已停止」和「草案基于当前计划修订 N」，各带说明。未通过的项给出修复入口，例如「去停止第 3 轮」。
  - 有映射不一致时，清单追加一条灰色建议项，注明不阻止应用。
  - 「应用规划草案」是面板底部唯一的主按钮，未通过时禁用并说明原因。
  - 退回收在折叠区「退回这份草案」：必填退回说明 + 危险按钮。
  - 三个确认框沿用原文意思：
    - 停止：已有问题、答案和草案保留，停止完成前继续等待。
    - 应用：会写入生效计划；之后需要重新确认计划，再明确开始执行。
    - 退回：当前计划不变，原草案和来源保留，并引用退回说明。
  - 应用后：面板顶部显示成功条「请重新确认计划，再开始执行」，底部主按钮变为「关闭并重新确认计划」，进度条前进到「确认计划」。
- **异常**
  - 接口未提供：琥珀条带「重新读取」；轮次、工作包、草案三个分区变灰并注明需要规划服务；生成按钮禁用。
  - 版本冲突：红色条「需求已在别处更新」，带「放弃本次请求并重新核对」；退回说明保留为只读，应用和退回都锁定。
  - 读取失败：只影响出错的分区（示例为规划轮次），其他分区照常显示。

**状态**（全部追加在已有状态之后，label 以「补充 · 」开头）
| id | 含义 |
|---|---|
| `pl-config` | 规划配置编辑：已发布模板 / 职业下拉，发布版本已核对 |
| `pl-rounds` | 规划轮次列表，第 3 轮（草案待审阅）展开：问答快照、沿用、停止 |
| `pl-stop-unknown` | 第 3 轮停止尚未核明：面板状态条 + 轮次内核对入口，生成被锁 |
| `pl-stopping` | 第 3 轮停止中，尚不能开始新一轮 |
| `pl-package` | 工作包详情（执行已开始）：有 1 份制品验收与停止证明 |
| `pl-package-noproof` | 工作包详情：步骤执行中，但没有证明，不能认定完成 |
| `pl-map-ok` | 草案映射核对 3/3 一致 |
| `pl-map-bad` | 映射核对：1 组不一致，1 组合同不完整无法核对 |
| `pl-precheck` | 应用前检查：来源轮次未停止，应用禁用，附「去停止第 3 轮」 |
| `pl-apply-confirm` | 应用确认框 |
| `pl-reject-confirm` | 退回说明已填，退回确认框 |

| `pl-unavailable` | 本地服务未提供澄清与规划接口 |
| `pl-conflict` | 退回时版本冲突，退回和应用锁定，可放弃并重新核对 |
| `pl-loading` | 各分区读取中（骨架 + 状态文字） |
| `pl-error` | 规划轮次读取失败，其余分区正常 |
| `pl-empty` | 尚无规划：未选配置、无轮次 / 工作包 / 草案 |

- 已有 9 个状态用逐像素比对：除 `planning` 的转圈动画外全部一致。
- 原型可交互：停止后进入停止中再变为已停止；核对原轮次；核对映射；生成新一轮（第 4 轮，已请求规划）；应用；退回；放弃冲突后重新核对。

**保留的业务边界**
- 显示答案修订和问题来源修订；模板和职业只取已发布版本，并在生成时冻结。
- STOP_UNKNOWN 和 STOPPING 时不能生成新一轮。
- 工作包只有服务端的制品验收与停止证明才算完成。
- 映射核对只读。
- 草案的版本校验：确认框打开后如果候选、版本或退回说明有变化，React 会阻止并提示重新核对。原型以冲突状态示意。
- 应用后仍需单独确认计划，再开始执行；面板内没有确认计划或开始执行的按钮。
- 没有新增后端能力。

## B-06. 历史模板与自动化档案 `pages/templates.html?state=arc-overview`

**入口与可见条件**
- 模板任务页头右侧新增两个入口：「历史任务」链接，以及次要按钮「历史模板与自动化记录」。按钮任何时候都可点，点开是 600 宽的只读抽屉。
- `/automations` 只做重定向，不单独画。

**原实现的问题**
- 抽屉里的记录卡片和页签都没有专属样式，所有内容是平铺的文字段落：规则卡把「触发 · 启用 · 审批」挤在一行，检测状态只是一行粗体字。
- 运行详情放在所有页签之下，切换页签后很难发现。核实关联任务只有一个孤立按钮，结果用 Alert 表示。
- 列表为空时没有任何文字，读取中只看到刷新按钮在转。

**改成了**
- **抽屉头部**：标题旁有「只读」徽标，副标题写服务器时间，右侧是图标式的「重新读取」。头部下面固定一条只读说明：「原写入接口已退役，这里不会启动、审批、导入或生成密钥」。
- **页签**：五个页签，手动激活。方向键和 Home / End 只移动焦点；点击、Enter、空格才切换，切换时才读取，原型里会短暂显示骨架。读取期间整排页签禁用。
- **归档概览**：三格计数（历史模板 / 旧规则 / 运行记录），下面是服务器时间和旧规则一览。
- **规则卡**：
  - 标题和「历史启用 / 历史禁用」徽标；
  - 副行写触发方式、自动开始或需要审批；
  - 元信息：项目、冻结模板及其版本、规则修订；
  - 检测块用徽标表示三种情况：检测正常、检测失败 · 连续 N 次（附错误原因）、未检查；块里还写最近检测和最近成功时间；
  - 触发配置默认折叠，展开为只读 JSON。
- **历史模板**：每个模板一张卡（已归档 / 历史有效、版本、更新时间），可以就地展开冻结版本：
  - 每个版本一行手风琴，带「不可变 / 原可变版本」和「原自动开始已批准 / 未批准」徽标；
  - 展开后显示短 SHA 和冻结时间，下面是冻结合同 JSON；
  - 底部提示框写明导出的是「最新原合同（版本 N），不是你正在查看的历史版本」，旁边是「导出最新原合同」。
- **旧规则与检测记录**：每张规则卡有「查看运行记录 · N」按钮，就地展开这条规则的运行列表。
- **运行记录**：每行显示运行编号、状态徽标、触发方式、时间和关联任务。状态与颜色对应：已完成、失败、已跳过、等待审批、已排队、运行中、已检测。
- **运行详情**：固定在页签下方，切换页签时仍保留，自带关闭按钮，内部可以滚动。
  - 显示规则、草稿、开始和结束时间，失败时附错误条，原始运行证据为只读 JSON。
  - 有关联任务时显示「核实关联任务」，核实中显示加载。
  - 成功后变为绿色提示条和「查看关联任务」。
  - 失败时为琥珀提示：「已不存在或你没有查看权限，运行记录本身仍保留」，并提供「重新核实」。
- **导出说明**：
  - 警示条「这不是完整备份」；
  - 两栏对照：会包含的（历史模板版本、部分规则配置）和不会包含的（运行记录、检测信息、Webhook 密钥）；
  - 一句「导出只是下载文件，不会导入、启动或修改」，主按钮「导出旧格式 v1」。
- **空状态文案**（原系统没有）：
  - 档案里没有记录；
  - 没有历史模板；
  - 没有旧规则；
  - 没有运行记录；
  - 这条规则没有运行记录；
  - 这次运行没有关联任务。

**状态**
- `arc-overview`：归档概览
- `arc-templates`：历史模板，展开「发布前回归测试」的三个冻结版本

## B-07. 快照评审的运行专用区域 `pages/task.html?state=snap-full`

**入口与可见条件**
- 任务详情 `/tasks/:id`，模板任务，且 `templateProgress.snapshot` 有值（快照代码评审）。
- 原型在任务画布的页头放了分段切换「执行进度 | 模板报告」，打开右侧 480 运行面板；面板内也有同名页签。
- 「阶段报告」只在 `snapshot.targetSha` 存在、且任务状态不是 COMPLETED 时出现，因此取消、失败后仍可读。

**原实现的问题**
- 快照信息塞在一行文字里，例如「日期增量审查 · 计划修订 3 · 补充批次 2」。版本号藏在「审查版本」折叠里，以完整 40 位显示，而且基线缺失时留一个空行。
- 指标三到四个大数字没有层级，「需处理」不醒目。阶段行是纯文本，看不出比例。
- 「进度不代表最终完成」是一行灰字，容易漏看。
- 功能批次只是一个展开 / 收起按钮，看不出数量。失败批次的错误与普通行混在一起。
- 阶段报告只有一句「已分析 N · 未完成 N · 排除 N」，没有比例。读取和下载按钮并列，下载在未读取时直接不出现，用户不知道还有下载。

**改成了**

执行进度：
- **指标**：四格，依次为「已验证审查批次 / 执行中 / 需处理 / 剩余批次」，需处理大于 0 时用琥珀色。批次总数未定时只显示三格，并提示「批次总数在审查计划确认后确定」。
- **阶段**：每行一条进度条加 `已完成 / 总数`，总数未定时显示「待定」。
- **固定提示**「进度不等于完成」：说明批次全部验证后还要汇总报告并通过校验，最终状态以执行服务为准。
- **审查范围**卡：
  - 审查方式徽标「全面审查 / 日期增量审查」，审查深度徽标「全量审查 / 轻量审查」；
  - 全量时显示「审查计划 修订 N」「补充批次 N 个」；轻量时说明“分析批次固定；只有发现候选问题的批次增加独立复核”；
  - 版本号以短格式显示，「基线 b71e04c → 目标 9f3c2a7」，各带复制按钮；
  - 全面审查不设基线，只显示目标；
  - 「完整版本号」折叠展开显示 40 位；
  - 注明版本在开始时固定。
- **功能批次**：可折叠，标题带数量。每行是批次名、用途、状态徽标（已验证 / 执行中 / 需处理 / 待执行），批次错误放在该行下方，带琥珀图标。底部有「已显示 6 / 24 · 加载更多」。
- **输出目录**：单行显示，可复制。

模板报告：
- 最终报告状态行，属于通用区域，仅作上下文。
- **阶段报告**：
  - 标「只读」，说明「已完成与未完成范围分别标注；取消后仍可读取；读取和下载都不会启动执行」；
  - 操作行放在内容上方：「读取阶段报告」（主）；「下载 Markdown」始终可见，未读取时禁用并注明「读取后才能下载」；读取后下载变为主按钮，读取降为「重新读取」；
  - 读取后显示：已分析、未完成、排除三段比例条加图例数字，按分析单元计并注明读取时间；下方是 Markdown 正文渲染（已分析范围、已确认问题、未完成范围、排除）。
- 已取消的任务：页头状态为「已取消」，状况条给出「阅读阶段报告」，报告页签顶部用信息提示说明仍可读取和下载。
- 面板底部固定说明「查看进度和报告不会启动、暂停或改变执行」。

**状态**（均追加在 task.html 状态列表末尾）
| id | 含义 |
|---|---|
| `snap-full` | 执行进度，日期增量审查 + 全量审查（修订 3 · 补充 2，基线 → 目标） |

  - 标题（过长时截断，悬停显示全文）；
  - 未筛选项目时，标题下方显示所属项目；
  - 状态徽标（图标 + 文字 + 颜色）；
  - 「修订 N」；
  - 更新时间。
- **分页**：底部「已显示 N 个 · 最近更新在前」+「加载更多」（游标式）。加载中按钮转圈，并在列表末尾追加骨架行；全部加载后显示「已全部显示」。
- **详情抽屉（400）**
  - 依次为：状态徽标 + 一句话解释这个状态下能做什么；计划修订；更新时间。
  - 信息条：「选中只是查看。确认计划、开始执行都在画布里单独操作，这里不会改变需求。」
  - 底部唯一的主按钮「打开画布」。
  - 再点一次已选中的行就关闭抽屉，按 Esc 或点遮罩关闭时同步取消选中。
- **空状态**
  - 全部为空：「从一个需求开始」+「新建需求」。
  - 某个项目没有需求：「这个项目还没有需求」+「新建需求」（带项目）+「查看全部项目」。
- **错误**
  - 需求读取失败：列表内红色条加「重试」，并说明「项目筛选已保留」。
  - 项目列表读取失败：工具条下方琥珀条「暂时不能按项目筛选，下面仍显示全部需求」加「重试」，筛选图标换成告警图标；列表不受影响。

**状态**
| id | 含义 |
|---|---|
| `list` | 全部项目，8 个需求，覆盖 8 种状态 |
| `selected` | 已选中「项目配置入口整合」，打开详情抽屉 |
| `filtered` | 按「OpenCode Loopper」筛选（截图时展开了筛选弹层） |
| `project-empty` | 按「支付网关」筛选，该项目没有需求 |
| `empty` | 全部为空 |
| `loading` | 读取中（骨架 + 刷新按钮转圈） |
| `error` | 需求读取失败 |
| `project-error` | 项目列表读取失败，需求列表照常 |
| `more` | 加载更多进行中 |

需求状态的显示：
| 状态值 | 显示 |
|---|---|
| PLANNING | 规划中 |
| PENDING_START | 已确认 · 待开始 |
| RUNNING | 执行中 |
| PAUSED | 已暂停 |
| STALLED | 停滞 |
| COMPLETED | 已完成 |
| FAILED | 失败 |
| CANCELLED | 已取消 |
| 其他值 | 状态待核对（虚线琥珀） |

**保留的业务边界**
- 项目筛选（含地址里的 `projectId`）、游标分页、读取中和读取失败的身份、需求状态、指向 `/requirements/:id` 的深链接，都保留。
- 新建始终进入 `/requirements/new`，并带上当前项目。
- 选中不会确认计划也不会执行；本页没有任何写操作。
- 没有新增后端能力。

**与 React 实现的对应**

页面与筛选：
| 原型 | React |
|---|---|
| 标题 | `semanticLabel('nav.requirements')`（按语义注册表实际文案） |
| 新建需求 | `workflow.newRequirement` → `navigation.go({path:'/requirements/new', query:{projectId}})` |
| 流程目录 | `PageLink /workflows`（`nav.workflows`） |
| 项目下拉 | `owner.projects(query)` 远程搜索；`setProject(project ?? null)`；当前项目不在本页结果时补进选项；`aria-label="工作项目"`；占位文字「全部项目」 |
| 加载更多项目 | `projectCursor` → `owner.projects(projectQuery, true)` |
| 刷新 | `ui.refresh` → `owner.load()` |
| 初始筛选 | `queryString(route, 'projectId')` |

列表、分页与状态：
| 原型 | React |
|---|---|
| 列表 | `UiSelectableList`，取 `row.title`、`workflowStateLabel(row.state)`、`formatDateTime(row.updatedAt)` |
| 列表上的「修订 N」 | 用的是 `headRevision`；原实现只在详情里显示，DTO 已有这个字段 |
| 所属项目副行 | 需要行数据里有项目字段；如果 DTO 没有，就去掉这一行 |
| 加载更多 | `cursor` → `owner.load(true)` |
| 读取中 / 失败 | 需求：`ReadNotice(error, busy)`，原文「正在读取需求…」；项目：`ReadNotice(projectError, projectBusy)` |
| 空状态 | 条件为 `!busy && !error && !projectError && !projectBusy && !rows.length`；标题沿用「这个项目还没有需求」和「从一个需求开始」，说明文字改写 |

详情抽屉：
| 原型 | React |
|---|---|
| 抽屉 | `UiContextPanel open={!!selected}`，标题为 `selected.title`（没有时显示「需求详情」） |
| 关闭 | `owner.select('')`，焦点回到列表行 |
| 内容 | 「计划修订」= `headRevision`；状态；`time` |
| 打开画布 | `PageLink /requirements/{encodeURIComponent(id)}`，`aria-label` 为「需求画布：{标题}」 |

**存疑点**
- 「打开画布」在 React 里一律进入 `/requirements/:id`；那个页面开始执行前是需求画布，执行后会显示执行状态。原型因此把规划中、待开始的需求链到 requirement.html，执行中及之后的链到 task.html（设计稿里的执行画布）。如果要统一只链 requirement.html，改 `canvasHref` 即可。
- 状态中文以 `workflowStateLabel` 的实际映射为准。
- 「一句话状态说明」是展示层补充。
