任务隔离与交付 · 设计原型

每个新任务先在独立工作区里执行（Git：独立任务分支 + worktree；非 Git：基线快照 + 独立副本），节点验收后进入待交付；用户查看本任务变更，选择交付目标，每个有副作用的步骤分别确认，所选动作全部可信成功后任务才算完成。本页列出原型的全部状态，点任一状态直接打开对应画面。

需求→计划确认→隔离执行→原节点验收→查看任务变更→选择交付→逐步确认→所选动作全部成功→任务完成

蓝色是用户明确操作；执行结束、模型回复、进程退出或「已提交请求」都不等于交付完成。

设计完成本原型可评审的部分

  • TD01–TD07 全部状态可点击：确认、提交 / 推送 / MR、检查、应用、清理都用定时器切换模拟状态。
  • 沿用原稿容器：开始任务、任务大画布与右侧面板、Git 工作台外壳；唯一新增交互视图是 TD05 非 Git 三方冲突应用。
  • 四主题（deepseek / claude / SPDB / GitHub 白）同一状态集；1440×900 主展示，另查 1280×800、1024×768。
  • 失败与未知分开：UNKNOWN 只给「核对原操作」，读失败可「重新读取」，不出现重发副作用的按钮。

业务未实现需要后续同版 API 与代码

  • 普通新任务统一隔离、同任务并行写子隔离与汇合：未实现，现有只有 AI 修复专属 worktree。
  • 任务完成门槛：deriveExecutionStatus 现在节点全成功即 succeeded，不等所选交付；需执行 / 状态 owner 改。
  • 非 Git 三方检查与逐项应用后端是新需求；推送 / MR 依赖 PR16 候选，生产安装与真实 GitLab 未验收。
  • 待冻结：两步「准备 → 开始」或「准备并开始」、无变更结算、未完成时改变目标、子集交付对必需产物的影响。所有接口名均为候选。
