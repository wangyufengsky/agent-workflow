## 1. Q10 · PE37 大需求分组逐步细化（正式路径）

**入口**：任务列表 / 需求目录“会员积分体系重构”（T-2060）；待处理“选择范围继续规划”。都进同一张需求画布。

**流程**（每一步都是独立操作，都不会自动触发下一步）：

1. **总览（第 1 轮，已应用 → 计划修订 2）**：6 个分组，3 个已细化（积分账户与流水 4 步、获取规则 3 步、验收 1 步），3 个未细化（消耗与抵扣、过期与清零、数据迁移），未细化组画成虚线占位，写“未细化，不能执行”。“确认计划”禁用：“还有 N 个组未细化，不能确认执行”。
2. **继续规划选区** → 预览确认框：写“第 N 轮”、细化范围只限该组、其他分组与当前草稿不变、跨组依赖按总览连线保留、本轮最多 2 次派发（初稿 1 + 修订 1）。确认后才调用模型。
3. **分组规划中（LG-PLANNING）**：状态条显示第 N 轮与段内阶段（读取范围 → 生成候选 → 检查）；可离开页面；“停止规划”只停这一轮，停稳结账后回到总览，该组仍未细化。
4. **组候选审阅（LG-CAND）**：画布上该组的新增步骤标“新增”、替换占位；组外步骤不变。右侧列新增步骤、跨组依赖、检查、修订 0 / 1、用量、应用后节点数。可“应用到草稿”（计划修订 +1，不执行）或“不采用”（该组仍未细化，候选留在历史）。
5. 回到总览，已细化组写“第 N 轮”；顺序任意。
6. **全部细化后**：计划修订 5、18 步，“确认计划”可用 → 确认框写步骤数、轮次（总览 1 + 分组 3）、需求覆盖 11 条、上限 18 / 20 → 同一画布“工作区”（复用 v4 准备区）→ 开始执行 → 统一任务画布（T-2060，18 步，与需求画布确认视图同一编号 n1–n18）。

**不变的边界**：分组只是展示与范围索引，不是执行节点、不是调度屏障；本期上限（节点 ≤ 20、分组 ≤ 8、深度 ≤ 2）超出时要求用户明确分期，不自动丢弃剩余需求；跨范围替换（PE38）仍不开放。

## 2. Q9 · 目录里的“规划职责”（只读）

- **角色管理**：列表新增“需求分析师（规划职责）· 已发布修订 1 · 只读”。详情写明：只用于 AI 规划，不出现在流程步骤“谁来做”里，不执行业务步骤。内容：
  - 绑定的流程方法与规划策略（PlanningPolicyBinding）：需求开发 r12 → 规划策略 v1（可细化：实现、测试）；缺陷修复 r4 → 规划策略 v1；文档整理 r2 → 未配置；
  - 精确版本：职业 / 任务类型 / 模板 / 提示词的引用与修订、内容摘要；“任务冻结的就是这些，目录发布新修订不改变已开始的规划轮次”；
  - 能力上限：只读项目资料、不写文件、不运行命令、不调用外部服务；每轮派发 ≤ 2、节点 ≤ 20、分组 ≤ 8；
  - 最近使用的任务（点开回到对应需求画布）。
  - 原有“需求分析师（未发布草稿 v1）”是另一个执行职业，保持原样。
- **流程目录**：补上与“开始任务”一致的“需求开发 r12”“缺陷修复 r4”（内置，带“AI 规划”标记）。详情新增“AI 规划 · 只读”：规划策略引用与摘要、规划职责（可点进角色管理）、可细化 / 不可改、本期上限、最近使用。
- **互链**：需求画布“需求与输入”的“AI 规划”行、步骤“版本与依据”、PE37“本期能力上限”里的“规划依据”都可点进；目录页显示“返回需求画布”（带 `back`，回到原状态）。
- 本期在目录里只读；“修改方式另行决定”。
