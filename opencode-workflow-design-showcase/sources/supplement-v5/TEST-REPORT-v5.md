## 2. v5 新增路径（32 步）

### H 大需求分组逐步细化（PE37）（22 步）

1. 任务列表“会员积分体系重构”→ 需求画布 PE37 总览（T-2060）
2. 未细化时“确认计划”禁用并写原因（还有 3 个组未细化）
3. 不再标“设计候选 · 后续分期”
4. 继续规划选区 → 预览：第 2 轮、只细化该组、可以确认开始
5. 预览“返回”取消：仍在总览，3 组未细化
6. 确认开始 → 分组规划中（新一轮，其他分组不变）
7. 服务事件按样例时间线到达 → 组候选待审阅
8. 候选：4 个新增步骤；本轮修订 0 / 1；当前草稿未改变
9. 应用确认框：应用后还有 2 个组未细化，已细化的组不会先执行
10. 应用 → 总览：“消耗与抵扣”已细化（计划修订 3），确认仍禁用（还有 2 个）
11. 停止本轮：回到总览，“数据迁移”仍未细化，已细化的组保留
12. 不采用：该组仍未细化，候选保留在历史
13. 最后一组：应用确认框写“应用后可以确认整份计划”
14. 全部细化：计划修订 5（18 步）· “确认计划”可用
15. 全部细化后确认按钮可用、画布无“未细化”占位
16. 分组命令都用 replaceState：浏览器历史没有增加
17. 确认框：18 步 · 总览 1 轮 + 分组细化 3 轮
18. 确认 → 同一需求画布“工作区”（T-2060，计划修订 5）
19. 准备独立工作区 → 已就绪
20. 开始执行 → 统一任务画布（T-2060，18 步，规划来源）
21. 节点详情往返：同任务 T-2060、恢复选中步骤
22. “在需求画布查看”→ B08（计划修订 5，总览 + 3 轮分组细化）

### I 目录里的规划职责（只读）（8 步）

1. 需求画布“需求与输入”→ 需求分析师（规划职责）→ 角色管理只读详情
2. 规划职责：绑定的流程方法与规划策略、能力上限、最近使用的任务
3. 规划职责不出现在执行步骤“谁来做”、目录里不能编辑
4. → 流程目录“需求开发 r12”详情的“AI 规划 · 只读”
5. 流程目录：支持 AI 规划的流程带标记
6. “返回需求画布”回到同一任务草稿
7. 左侧“角色管理”→ 点“需求分析师（规划职责）”进入同一只读详情
8. 切回其他职业：原有角色页不受影响

### J 完成提醒维持现状（计数口径）（2 步）

1. 待处理“规划事项”与任务列表“需要处理”的规划侧数量一致（13 = 13）
2. 标明同一口径，不弹窗、不另发通知

## 3. 覆盖的正常 / 失败 / 取消 / 返回 / 恢复（v5 部分）

| 类型 | 覆盖点 |
|---|---|
| 正常 | 总览 → 选组 → 新一轮 → 候选 → 应用 × 3 → 确认 → 准备 → 开始 → 统一任务画布（18 步）；需求画布 → 角色管理 / 流程目录只读详情 |
| 取消 | 预览框“返回”；不采用组候选（该组仍未细化） |
| 停止 | 分组规划中“停止规划”→ 停稳结账后回到总览，已细化组保留 |
| 返回 | 目录“返回需求画布”回到原任务、原状态；节点详情往返恢复选中；任务画布“在需求画布查看”→ B08 |
| 恢复 / 历史 | 分组命令用 replaceState：一整轮细化浏览器历史不增加，后退不重放命令 |
