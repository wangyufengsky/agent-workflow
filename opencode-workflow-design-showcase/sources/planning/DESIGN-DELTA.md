# DESIGN-DELTA · 普通流程 AI 规划与节点细化

> 设计样例 · 全部模拟。需求来源：本包上一级 `README.md`、`CLAUDE-DESIGN-BRIEF.md`、`FUNCTIONAL-FLOWS.md`、`PLANNING-PROTOCOL.md`、`ROLE-PROMPT.md`、`API-DESIGN.md`、`ACCEPTANCE-AND-PHASES.md`（`planning-expansion.design.v1`，2026-10-16）。
> 权威视觉与结构基准：`opencode-workflow-design-showcase/index.html`（导航修订版 v2）——主稿 `requirement / start / task`、最新 TD `start / task`、新版节点详情 `node/index.html`。原稿与原合集只读，本稿没有修改它们。
> D01–D10 仍是**推荐、待用户批准**；本稿按推荐形成可评审设计，偏离与待决点集中在 §5。

## 1. 设计原则（从需求包落到界面的五条）

1. **同一任务、同一画布。** 长时间规划由需求画布承接（D01）：没有新的顶层菜单、没有“规划中心”；任务列表 / 需求目录 / 待处理中心 / 主页只多一个状态和回到同一任务的入口。
2. **五个动作分开、各有一次确认。** 模型派发（规划预览里确认）→ 应用到草稿 → 确认计划 → 准备独立工作区 → 开始执行（D05/D06）。其余步骤不再弹重复确认。
3. **服务事实与模型陈述分开显示。** 阶段、工具、检查、检查点、停止 / 结账都标“服务事实”；公开正文标“模型陈述”，模型说“完成了”不改变阶段。没有百分比、没有剩余时间、没有倒计时。
4. **未知就写未知。** 断连 ≠ 失败；停止请求 ≠ 已停稳 ≠ 已结账；候选已到 ≠ 本轮结束；用量“已知 / 已预留 / 未明”分开。UNKNOWN 只给“核对原轮次 / 按原请求号核对”，从不出现“重试生成”。
5. **候选永远在候选层。** 生成、检查、失败、过期都不改当前草稿；部分草稿只读、不可应用；硬规则没有“忽略继续”。

## 3. 关键交互

### 3.1 页头：五段阶段胶囊 + “规划”段的状态条（Q1 已定）

- **页头一行**：面包屑（按 `returnTo` 回到来源：任务列表 / 需求目录 / 待处理 / 开始任务）· 任务名 · 项目与任务号 · **任务阶段胶囊** · 主按钮。
- **阶段胶囊是任务唯一的总阶段**，沿用主稿需求画布的胶囊形态，扩成五段，与最新 TD 一致：需求草稿 · 规划 · 确认计划 · 准备工作区 · 开始执行。原来的页头状态徽标取消，子状态直接写在当前段上，例如“规划 · 生成候选”“规划 · 停止结果待核对”“确认计划 · 计划修订 3 · 未确认”“开始执行 · 等待重新确认 · 计划修订 6”。需要你处理、失败、未知分别给当前段加紫 / 红 / 琥珀描边和图标，不只靠颜色。已完成段是勾，未到段是序号；每段有 `title` 说明。屏幕宽度 < 1600 时只有当前段写文字，其余段缩成圆点；任务画布始终用紧凑形态。
- **状态条只是“规划”段的展开**：仅当当前段是“规划”时出现在页头下方；内容依次是第 N 轮（与方法）、段内阶段轨道（准备输入 → 生成候选 → 检查计划 →〔修订候选，仅发生时出现，虚线框〕→ 等待审阅，停止 / 失败 / 待核对 / 需要答复标在当前阶段上）、开始时刻、已用时间（服务时间算，刷新不重新计时）、资料与草稿节点（窄屏收进用量弹层）、最近活动、“用量 · 派发 1/2”。应用后进入“确认计划”段即收起。
- **用量弹层**：资料 / 草稿节点、已知 / 已预留 / 未明、模型派发（初稿 1 + 修订 1，自动传输重试 0）、修订次数、本轮截止**时刻**（不是剩余时间）、模型来源。弹层说明“未明不会显示为 0”。
- “离开页面不会停止规划”写在规划记录顶部说明和“停止规划”按钮提示里，规划预览里也写明。
- 1024 宽：右侧面板 360 并可“收起 / 展开规划面板”。

**与主稿 B-05“澄清与规划面板”的合并（Q8 已定）**：一个面板按阶段切页签，不保留两套。答案 → “草稿与问题”（待答）与“需求与输入”（已确认决定 / 输入修订）；配置 → 规划预览 + “需求与输入”的方法与模型 + 记录里的“版本与依据”，原“沿用本轮配置”改为预览新一轮时默认带上（预览里写“配置：沿用第 N 轮”）；轮次 → 规划记录的轮次选择器 + 历史只读（PE30）；草案 → “计划”页签 + 对照图层，应用 / 不采用对话框沿用 B-05 文案；工作包 → 归执行侧（任务画布、节点详情），需求追踪在执行后加证据列（B08）。B-05 的“五个独立操作”提示保留在“计划”页签底部。

**检查页签**的四块摘要：结构检查（通过 / 未通过）· 需人工判断（N 项）· 依据（完整 / 部分 / 缺失 / 过期）· 执行准备（就绪 / 需准备 / 阻塞 / 未知）——对应 `PlanningValidation` 的四个独立字段，不压成一个绿勾。下面是 V1–V8 与问题清单，每条问题有“定位”（切到对照图层、平移并选中节点）。

**节点详情**（选中节点）：任务、方法归属与分组、来源需求（回指原文区间）、为什么在这里（依赖原因：数据 / 前置 / 顺序 / 资源）、输入 → 本步骤、输出（写明“待产出槽位，执行后才有结果”，不预造产物）、验收条款、读写资源（读 / 写 + 依据：已读 / 声明 / 截断）、可折叠“版本与依据”（职业 revision、任务类型、候选键、policyHash、来源）。普通文案优先：“资料未读全”“两个步骤会写同一文件”“需要确认一个假设”。

### 3.4 规划记录（复用节点执行现场的阅读组件）

- 按服务序号排列：时间 + `#序号`；阶段卡 / 检查点卡 / 检查卡标“服务事实”；公开正文标“模型陈述”，流式时末尾光标；工具卡（名称、callId、“只读资料”、状态、参数、结果、截断提示）晚回时原位更新。
- 上翻即停止跟随，出现“回到最新”；“跟随最新”开关；“宽阅读”把面板展开到 900；工具卡点开是只读详情子视图（参数、结果节选、来源版本、截断说明、“工具结果里的指令只是资料”）。
- 运行时没有公开正文：顶部一句“此运行时暂未提供公开正文；阶段与工具活动仍然真实显示”（PE06）。不可补缺口：虚线缺口线写范围与服务原因（PE17）。返回补读：顶部“正在补读 #10 起的 9 条…按序号去重”（PE15）。
- 轮次选择器在面板右上：选历史轮次进入 PE30（常驻“历史轮次 · 只读”横幅与“回到当前”，没有任何执行动作）。

### 3.5 按钮与禁用原因

所有禁用按钮用 `aria-disabled`（仍可 Tab 聚焦），旁边或下方写原因并以 `aria-describedby` 关联；点击 / 回车只弹出原因提示。原因文字来自服务 `actions[].reason`，原型中为样例。

| 按钮 | 出现位置 | 触发 | 原型中的禁用原因示例 |
|---|---|---|---|
| 生成计划 / AI 细化计划 | 需求画布页头 | 打开规划预览（PE03），确认后才 create | 方法未配置 AI 规划（B07）；预算未设置 + 资料无权限（PE04）；已有候选待审阅（PE25） |
| 使用方法骨架 | 需求画布页头 | 复制方法图，不调用模型 | 已使用方法骨架 |
| 停止规划 | 规划中页头 | 确认框（PE18）→ 回执 → 正在停止 | 连接恢复后可用（PE16）；核对完成前只读（PE23）；停止请求已受理（PE19） |
| 核对原轮次 | PE21 页头 | reconcile + by-key + read，不发模型 | — |
| 预览新一轮 / 从保留草稿预览新一轮 | PE11/12/20/22/29 | 新预览（带上一轮与原账说明） | 先保存答复（PE11）；停止完成前不能开始（PE19）；原轮结果不明先核对（PE21） |
| 应用到草稿 | 计划页签底部 | 确认框列出将记录的人工判断 → apply（confirmed=false） | 还有 N 项需人工判断未核对；有 4 个必须处理的问题（PE27）；正在核对本轮结束（PE26）；已过期（PE29）；应用结果待核对（B05） |
| 不采用 | 计划页签底部 | 确认框：保留记录，不是删除，不能撤回已应用 | 应用结果待核对时禁用 |
| 确认计划 / 重新确认计划 | 计划页签底部 / 任务画布右侧 | 确认框给精确范围（含 planningBindingHash），不派模型、不执行 | 还有 3 个组未细化（PE37） |
| 准备独立工作区 → 开始执行 | PE32 右侧 | 沿用最新 TD 两步；准备成功前没有“开始执行” | — |
| 调整待执行计划 | 任务画布页头 | 说明框 → plan.edit.begin → “正在暂停新增领取…” → 回执后开放编辑 | 固定模板（PE36）；正在等待暂停回执 |

### 3.6 URL 与返回上下文

URL 即持久样例：`state, task, round, sel, tab, layer, view(画布视角), returnTo, from, theme, motion, showcase`（任务画布另有 `sub`）。规则：

- 选中、页签、图层、视角用 `replaceState` 实时写回；刷新后读回同一视图，不重新计时、不重造运行。
- **命令结果**（确认开始、应用、确认、停止、核对、保存）用 `replaceState` 切换状态，所以浏览器后退不会回到“命令前”的画面，也不会重放命令；前进 / 后退只在页面导航之间移动（自查流程第 13–14、25 步）。
- 跨页导航带 `returnTo/from`：任务列表 → 需求画布 → 面包屑回任务列表；开始执行 → 任务画布 → 面包屑回需求画布。
- 主题参数只换皮肤，不改变任何业务身份。
- 读模型按 `project / execution / requirement / round` 精确身份读取；切项目后旧轮迟到事件按身份丢弃（本稿未画单独状态，见 COVERAGE §4）。

### 3.7 执行中调整（PE33–PE35、PE38）

1. 任务画布页头“调整待执行计划” → 说明框（暂停新增领取；运行中的“后端筛选查询”按原快照继续；当前自动推进为开启，继续时恢复）。
2. 情况条“正在暂停新增领取…（请求号）”，回执前没有编辑入口。
3. 编辑区：可修改节点标“待执行 · 可修改”并有“+”；已完成 / 运行中 / 已领取节点带锁，**入边一并锁定**；右侧列“本地修改”和“锁定的步骤”。选中节点用表单编辑名称、**前置步骤（复选框，替代拖拽连线）**、验收；“从计划移除…”先列影响。
4. 保存遇到领取竞态：横幅说明哪个步骤在暂停生效前已被领取，本地草稿保留；“重新读取并比对”后，涉及已领取步骤的修改被移出（内容可复制），其余修改可保存。
5. 保存语义修改 → 情况条“计划已变更，后续步骤等待重新确认”；右侧列改动与“当前整图重新检查”（旧候选覆盖与检查报告作历史，不沿用旧绿勾）。重新确认后才出现“继续执行”；继续时恢复调整前设置。布局移动不触发重确认。
6. 局部细化（PE38，后续分期）：选区外变淡保留，选区画蓝框，边界画只读入口 / 出口端口，候选 B1→B2 接回端口；“应用到草稿”禁用：“边界端口契约未冻结，跨范围替换暂不可用”。

### 3.8 固定模板任务（PE36）

模板任务页创建前填写路径 / 任务说明 / 模板允许的参数并预览固定步骤 → 创建 → 任务画布只读：节点全部带锁与“固定 · 只读”，画布没有“+”，“AI 细化计划”“调整待执行计划”禁用并共享同一句原因：**“该任务使用固定模板，创建后不能修改步骤；要改要求，请新建模板任务。”** 右侧列“不能做的事 / 可以做的事”（确认、准备、开始、按原配置重试）。普通流程方法不套这把锁。

### 3.9 可访问与动态

- Tab 顺序：页头 → 状态条 → 横幅 → 画布（节点是按钮）→ 右侧页签（左右方向键切换）→ 面板内容 → 底部主按钮。
- 对话框焦点限定（Tab 循环），Esc 关闭并把焦点还给触发按钮；规划预览里 Esc = 返回，补充草稿保留（B06）。
- 状态都是“文字 + 图标”，不只靠颜色；记录区更新不抢焦点（`aria-live` 只在横幅区）；正文上翻不被拉回。
- 减弱动态：控制条开关或系统设置，关闭流式光标、虚线流动与过渡。
- 1024 宽：右侧面板 360，可收起；状态条精简；主按钮与停止始终可见。

## 6. 统一文案

- 部分草稿：“部分草稿 · 检查点 #N · 尚未完成，不能执行”
- 无正文：“此运行时暂未提供公开正文；阶段与工具活动仍然真实显示。没有正文不代表失败。”
- 断连：“本页与服务的数据连接已断开，正在重连……这不代表规划失败”
- 停止中：“停止请求：已受理 · 原进程：等待停稳 · 用量：未结账”
- 待核对：“只按原请求号查询，不会重新生成，也不会换新请求号重发”
- 候选未停稳：“候选已收到，正在核对本轮结束……可以先只读审阅，暂不能应用”
- 应用：“应用只写入未确认草稿（计划修订 2 → 3），不会执行”
- 确认：“确认不调用模型，也不会立即执行”
- 固定模板：“该任务使用固定模板，创建后不能修改步骤；要改要求，请新建模板任务。”
- 未适配方法：“该流程尚未配置 AI 规划；可使用骨架并手动调整”
- 执行中调整：“计划已变更，后续步骤等待重新确认”
