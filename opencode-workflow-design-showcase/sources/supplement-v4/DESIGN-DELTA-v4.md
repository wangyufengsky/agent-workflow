## 4. C04 保留自动推进设置（AD05）

- “调整待执行计划”确认框先写**调整前的设置**（服务记录的原模式）：自动节点推进开启 / 关闭（手动推进）/ 任务已暂停。确认后服务记录原模式并暂停新增领取（回执前不开放编辑），运行中的步骤按原快照继续。
- 调整面板、重新确认框、“继续时”说明、继续后的横幅都读同一个原模式（URL 中的 `prior` 只是原型对服务 guard 记录的模拟），回调不写死“开启”：

| 原模式 | 继续按钮 | 继续后 |
|---|---|---|
| 自动开启 | 继续执行 | 回到调整前状态，自动推进开启 |
| 自动关闭（含先手动关掉再调整） | 继续执行 | 自动推进仍关闭；“整体推进”与“推进直接后继”可用（无可推进步骤时禁用并写原因） |
| 任务已暂停 | **结束调整（任务保持暂停）** | 仍暂停；只有“恢复任务”（单独动作）才继续，恢复后自动推进按原设置 |

- 未保存放弃：“放弃调整”确认框写恢复到的原模式；放弃后计划修订不变、草稿丢弃。
- 保存冲突（领取竞态）：本地草稿保留，“重新读取并比对”后只保留仍可保存的修改。

## 5. C05 业务问题与风险核对分开（AD06）

- **业务问题组件**（PE11 与第 1 轮候选审阅同一组件、同一措辞）：问题、对步骤 / 输入输出 / 验收的影响、来源（模型假设 / 模型提议 · 记录号）、选项及各自影响。**没有预选**；模型建议只作“建议 · 模型提议，未作答”标签。
- 未全部回答：“保存答复”禁用；“应用到草稿”/“预览新一轮”禁用并写“还有 N 个业务问题未回答（必须明确回答，不能用勾选代替）”。
- 保存答复 → **需求输入修订 2**（记录回答人、时间、答案；旧轮输入保留）→ 服务按修订 2 **重新校验候选**（不调用模型）：答案与候选假设一致 → 可应用（QA02）；不一致 → 候选过期，需按修订 2 预览新一轮（QA03）。
- 第 2 轮显示“已确认的业务决定（需求输入修订 2）”；“修改答复…”形成修订 3，当前候选过期（PE29 `chg=1`），不回写旧轮。
- 风险核对（勾选）只剩不改变业务范围的 2 项（依据截断、需求覆盖语义）；日期字段与导出上限从勾选区移除，任何地方都不再写“非关键路径”。应用与确认框分开列“业务决定”和“风险核对”。
- 没有引入自动“关键性打分”。
