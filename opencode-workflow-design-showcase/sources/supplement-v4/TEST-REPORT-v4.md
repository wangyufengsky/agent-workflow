## 2. 交互路径与步骤（85 步，8 个主题 × 宽度组合逐步一致；另 deepseek 1440 一次）

### A 主线（Git 成功）（20 步）

1. 冷启动 index → 主页，正式菜单完整
2. 左侧“开始任务”→ 新开始页 PE01（AD01 保留）
3. 形成需求草稿 → 同任务需求画布 PE02（未调用模型）
4. 确认开始规划 → 服务事件按样例时间线自动到达 → 候选审阅（不靠底部模拟按钮）
5. 业务问题未回答：“应用到草稿”禁用，原因写“业务问题未回答”
6. 业务问题没有预选答案（建议只作标记）
7. 同一问题不再标“非关键”
8. 保存答复 → 需求输入修订 2 → 服务按修订 2 重新校验候选（一致）
9. 风险核对只剩 2 项（不改变业务范围）
10. 确认计划 → 同一需求画布“工作区”页签（AD02）
11. 准备前“开始执行”禁用并写原因
12. 准备对话框“再看看”取消：仍未准备
13. 准备中：阶段名，无百分比
14. 准备成功 → 已就绪，“开始执行”可用
15. 准备命令用 replaceState，不增加历史（后退不重放）
16. 开始执行 → 统一任务画布（同一任务 T-2051，规划来源）
17. 执行中步骤 → 最新节点详情（返回任务画布按钮）
18. 返回恢复：同任务、选中步骤、右侧面板与页签
19. “在需求画布查看”→ 同任务 B08（执行刚开始，无预造证据）
20. 需求画布 → 打开任务画布（回到同任务）

### B 准备工作区异常（需求画布内）（17 步）

1. 任务列表 → 对账单（非 Git）→ 同任务需求画布工作区页签
2. 非 Git：列出未复制资源，不说整个项目已隔离
3. 非 Git 准备 → 已就绪（独立副本）
4. 非 Git 开始 → 统一任务画布显示“独立副本”
5. 工单：准备回执未知 → 只给“核对原创建”
6. 核对原创建 → 已就绪（不重投新请求）
7. 发票：部分创建（分支已建、目录未建）→ 开始执行禁用
8. 补建工作目录（沿用原准备记录）→ 已就绪
9. 积分单：同名冲突 → 准备按钮禁用、列出同名对象
10. 使用新名称重新预览 → 按新名称准备 → 已就绪
11. 支付单：无法读取项目 → 准备禁用
12. 授权后重新读取 → 可以准备
13. 通知单：空仓库 → 重新读取仍为空，准备保持禁用
14. 需求目录旧需求（已确认 · 待开始）→ 同身份需求画布工作区（T-2027）
15. 基线前移 → 停止准备，按钮禁用
16. 重新读取基线 → “按新基线准备独立工作区”（重新确认）
17. 旧需求开始执行 → 统一任务画布（迁入 · 身份 T-2027）

### C 调整与原自动推进（21 步）

1. 任务列表 → 规划任务执行中（统一任务画布）
2. 调整确认框写出原设置（开启）
3. 取消调整：仍执行中
4. 暂停新增领取（回执前不开放编辑）
5. 回执 → 编辑待执行区（锁 / 可修改）
6. 重新确认后“继续执行”出现，写明恢复为开启
7. 继续执行：自动推进恢复为开启，新步骤在计划里
8. 手动关闭自动推进 → 出现“整体推进”（此刻无可推进，禁用写原因）
9. 调整确认框写出原设置（关闭）
10. 放弃未保存调整 → 恢复调整前：自动推进仍关闭、手动推进入口在
11. 保存冲突（领取竞态）：本地草稿保留
12. 原关闭：确认后说明“继续后自动推进仍关闭”
13. 继续执行：自动推进仍关闭（不写死开启），手动推进可用
14. 需求目录旧任务（执行中）→ 统一任务画布（迁入，自动推进关闭）
15. 旧任务原关闭 → 继续后仍关闭
16. 任务列表旧任务（已暂停）→ 统一任务画布
17. 调整确认框写“已暂停 · 调整结束后仍暂停”
18. 原暂停：按钮是“结束调整（任务保持暂停）”
19. 结束调整后任务仍暂停（“继续”不被误解为开启）
20. 恢复任务（单独动作）→ 执行中，自动推进按原设置
21. 自动关闭的旧任务：执行中，整体推进禁用并写原因

### D 固定模板完整路径（6 步）

1. 单元测试开发：创建 → 需求画布确认计划（全部步骤带锁，AI 细化 / 修改禁用）
2. 单元测试开发：确认后切到工作区页签（不是提示框）
3. 单元测试开发：开始执行 → 统一任务画布，固定锁仍在（调整禁用）
4. 详细设计编写：创建 → 需求画布确认计划（全部步骤带锁，AI 细化 / 修改禁用）
5. 详细设计编写：确认后切到工作区页签（不是提示框）
6. 详细设计编写：开始执行 → 统一任务画布，固定锁仍在（调整禁用）

### E 旧任务与旧需求迁入（10 步）

1. 旧任务“停滞”→ 统一画布，停滞原因与授权在步骤面板
2. 允许本次读取 → 执行中（同任务）
3. 旧任务“失败”→ 统一画布失败原因
4. 恢复：选方式 → 准备 → 开始（原失败记录保留）
5. 旧需求“规划中”→ 新需求画布计划草稿（旧版流程，身份 T-2046）
6. 旧需求确认 → 准备 → 开始 → 统一任务画布（T-2046）
7. 旧版已完成任务 → 明确“旧版记录”，不伪装已交付
8. 旧模板任务 → 统一画布快照评审面板
9. 待处理中心事项 → 同任务统一画布并选中步骤
10. 旧恢复页“返回原任务”→ 统一画布（原稿样例身份 T-2044）

### F 工作包与节点返回（5 步）

1. 任务画布 → 在需求画布查看 → B08（执行侧事实一致）
2. 查看工作包 → 节点详情（返回需求画布）
3. 返回需求画布保留定位（同任务、B08、选中步骤）
4. 回到任务画布（同任务）
5. 浏览器后退回到需求画布（不串任务）

### G 业务问题（不一致 / 修改答复）（5 步）

1. PE11 需要回答：与候选审阅同一组件与措辞（业务问题）
2. 未回答不能预览新一轮
3. 回答后保存 → 需求输入修订 2 → 可预览新一轮
4. 第 2 轮候选：已确认的业务决定（来源输入修订 2）
5. 修改答复 → 修订 3，当前候选过期、不能应用（不回写旧轮）

## 3. 覆盖的正常 / 失败 / 取消 / 返回 / 恢复

| 类型 | 覆盖点 |
|---|---|
| 正常 | 开始任务 → 草稿 → 规划 → 回答业务问题 → 应用 → 确认 → 准备（Git / 非 Git）→ 开始 → 统一任务画布；固定模板创建 → 确认 → 准备 → 开始 |
| 失败 | 准备回执未知、部分创建、同名冲突、基线前移、无读取权限、空仓库；执行失败 → 恢复面板 → 独立恢复页；调整保存冲突 |
| 取消 | 准备确认框取消、开始执行确认框取消、调整确认框取消、放弃调整（恢复原模式） |
| 返回 | 面包屑按 returnTo 回任务列表 / 需求目录 / 模板任务；节点详情“返回任务画布 / 需求画布”；恢复页“返回原任务”；浏览器后退 / 前进不重放命令、不串任务 |
| 恢复 | 节点往返恢复选中步骤、右侧面板与页签、画布视角；原自动开启 / 关闭 / 暂停在继续 / 放弃后按原模式恢复；暂停任务“恢复任务”单独动作 |
